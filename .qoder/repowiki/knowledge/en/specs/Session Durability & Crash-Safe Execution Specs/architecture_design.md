Three independent spec artifacts share a common lifecycle (plan.md / spec.md / tasks.md) but cover two related durability concerns:
- SPEC-006 introduces a `SessionStore` protocol with an `InMemorySessionStore` and a `RedisSessionStore`, selected via `SESSION_STORE_BACKEND`, with graceful fallback to memory when Redis is unreachable.
- SPEC-016 adds a third backend, `PostgresSessionStore`, decoupling platform sessions from the AgentScope kernel's Redis instance; it keeps the same protocol and factory pattern while introducing a `sessions` table and `SESSION_DB_URL` configuration.
- SPEC-063 defines a durable, single-use dispatch claim stored in Postgres for the approved-mutation path, establishing burn-on-claim semantics (`dispatch_claimed` → `outcome_unknown` → `result_recorded`), bounded validity (900s first-dispatch window, 30-day retention), read-only recovery, and a coordinated mutation-disabled cutover — explicitly not exactly-once target effects.
Dependency direction is one-way: later specs extend the existing `SessionStore` protocol and Postgres infrastructure introduced by earlier ones; none introduce runtime code here — they are requirements/acceptance-criteria documents backed by companion plan, task, and failure-test matrix files.

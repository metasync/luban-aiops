Three sibling spec directories under `docs/specs/`, each following the same tri-file layout (`spec.md` + `plan.md` + `tasks.md`) that drives implementation across multiple products. SPEC-001 defines six requirements (R-1..R-6) tightening gateway authentication (`GATEWAY_REQUIRE_AUTH`), role propagation, session isolation in the transitional runtime, contract enforcement via pydantic models against shared schemas, backend resolution caching/timeouts, and a CI baseline — touching `products/tool-gateway`, `products/agent-platform`, `products/identity-broker`, and `shared/platform-ops/gitops`. SPEC-009 adds deterministic output redaction at the tool invocation choke point with Prometheus metrics and a fail-closed `REDACTION_OVERFLOW` policy, plus replacing the static client secret with Kubernetes projected service-account tokens validated by the identity broker's JWKS path per ADR-0004. SPEC-010 performs a structural split: moves portal-facing routes, token verification, policy enforcement, chat/session proxying, and delegation client out of `products/tool-gateway` into a new `products/platform-gateway`, keeping `tool-gateway` as the internal tool/connector home while preserving HTTP contracts, deny-by-default policy, and audit fields; it also renames env vars (`GATEWAY_*` → `PLATFORM_GATEWAY_*`), updates the broker registry, and adjusts the dev-k8s overlay to deploy both services behind the portal nginx proxy. Each spec tracks lifecycle status (`draft` → `approved` → `in-progress` → `delivered`) and records open questions and changelog entries as evidence of delivery.

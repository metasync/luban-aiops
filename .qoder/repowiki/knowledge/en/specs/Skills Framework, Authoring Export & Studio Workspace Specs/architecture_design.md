Three independent spec documents, each in its own `docs/specs/SPEC-NNN-*` directory with the standard `plan.md` / `spec.md` / `tasks.md` triad. They form a chronological delivery chain rather than sub-packages:

- SPEC-014 defines the foundational contract: Markdown skills with YAML frontmatter governed by `shared/shared-contracts/schemas/skill.schema.json`, ingested via a new `products/skills-hub` FastAPI service over federated Git/local sources, exposed through a read-only `skills.search` tool registered in tool-gateway, and cited by agent-platform's system prompt.
- SPEC-044 extends that foundation with an authoring loop: agent-platform generates a fenced `skill-frontmatter` + Markdown draft from a deterministic session digest, validates it against skills-hub's existing ingestion path via a new `POST /api/v1/skills/validate` route, then returns it to the operator as a client-side `.md` download — nothing is persisted on the platform.
- SPEC-056 reorganizes the portal surface: an additive immutable `session_type` discriminator (`operation` | `development`) on the session record splits one Chat entry into two entries sharing one `ChatView` parameterized by `mode`, moving declare-target/graduate controls into Studio while keeping Draft-as-skill in Chat.

Dependency direction is strictly forward: SPEC-044 depends on SPEC-014's skill schema and skills-hub; SPEC-056 depends on SPEC-044/045's authoring controls but does not change their trust model. Each spec declares its product boundaries (`products/skills-hub`, `products/tool-gateway`, `products/agent-platform`, `products/platform-gateway`, `products/operator-portal`) and shared contracts (`shared/shared-contracts/schemas`, `policy-default.yaml`, audit-event enum) it touches.

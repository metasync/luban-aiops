Three independent spec documents under `docs/specs/`, each a self-contained deliverable with `plan.md` / `spec.md` / `tasks.md` and an appended Changelog tracking draft → approved → delivered transitions.

- SPEC-005 establishes a dual-surface observability contract: always-on Prometheus `/metrics` (RED + security-arc domain counters) plus opt-in OpenTelemetry OTLP push to Elastic APM, gated by `OTEL_ENABLED`; request correlation bridges `x-request-id` to W3C `trace_id`. Conventions are published in `shared/shared-contracts/observability-conventions.md` as the single reference for all three services (`tool-gateway`, `identity-broker`, `agent-platform`).
- SPEC-013 builds on that surface to replace ephemeral pod-log auditing with a new `products/audit-service` FastAPI product. It defines a canonical event envelope schema (`shared/shared-contracts/schemas/audit-event.schema.json`) consumed by emitters and stored via an `AuditStore` protocol backed by either in-memory or PostgreSQL (WAL-durable, PVC-backed). Emission is fire-and-forget over HTTP authenticated via the existing broker-mediated service-identity mechanisms; querying is gated by a new `audit:read` policy action granted to `auditor`/`platform-admin` only, proxied through `platform-gateway` under `/api/v1/audit/*`.
- SPEC-046 extends SPEC-013 without changing the event vocabulary or adding policy actions: it adds `GET /api/v1/audit/summary` (envelope-column aggregates including a decision-chain projection) and `GET /api/v1/audit/export` (bounded RFC-4180 CSV streaming capped at `AUDIT_EXPORT_MAX_ROWS`), both proxied by platform-gateway under the existing `audit:read` gate and surfaced in the operator portal as two tabs (Events + Summary) with a shared filter toolbar.

Dependency direction inside this scope is strictly chronological: SPEC-046 references SPEC-013 as its foundation and deliberately does not touch `audit-event.schema.json`; SPEC-005's conventions are referenced by both later specs. Each spec declares its own Impact section enumerating touched products, contracts, and living-state docs rather than sharing a cross-spec manifest.

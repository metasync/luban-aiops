Five sibling spec directories each define one vertical slice of the agent execution runtime, all anchored to ADR-0002/0003 (AgentScope kernel and platform-owned contract). SPEC-007 introduces the tool-gateway layer with shared `tool-invocation`/`tool-result` schemas, a `BaseTool`/`ToolRegistry` abstraction, and Kubernetes read-only connectors gated by policy (`tools:invoke`). SPEC-017 extends the AgentScope kernel via `RuntimeSettings` knobs (ReAct budget, context compression, model retries, timezone injection) and adds Postgres-backed `AgentState` persistence through an `AgentStateStore` protocol (memory/postgres backends) so conversations survive restarts. SPEC-018 replaces hand-rolled kernel interception with AgentScope's `MiddlewareBase` hooks (`on_check_permission`, `on_acting`) and adopts out-of-box middlewares (`TracingMiddleware`, `ReplyBudgetControlMiddleware`) plus opt-in built-in task tools, guarded by a four-point adoption gate that preserves deny-by-default policy, delegated-token identity, read-only posture, and v2 contract boundaries. SPEC-037 and SPEC-038 form a two-phase R4 closing slice: Phase 1 signs execution requests/receipts with HMAC-SHA256 over canonical JSON envelopes and verifies argument digests at the gateway boundary; Phase 2 extracts mutating executions into a separate `execution-runtime` worker product that authenticates via a static handoff token, re-verifies the envelope, executes against the tool-gateway under the confirmer's delegated token, enforces single-flight idempotency by `execution_id`, and persists receipts — keeping isolation enforced at the infrastructure layer (ClusterIP-only, no portal exposure).

Pure documentation scope — three independent SPEC directories under `docs/specs/`, each following the same tri-file scaffold (`spec.md` + `plan.md` + `tasks.md`) and lifecycle headers (`status`, `owner`, `created`, `approved`, `delivered`, `release slice`, `related ADRs`, `lineage`).

- SPEC-064 evaluates two agentscope 2.0.8 surfaces against the SPEC-018 four-point adoption gate; `CompressContext` is adopted behind an opt-in env knob (`AGENTSCOPE_COMPRESS_CONTEXT_ENABLED`) while `GoalPipeline` is kept out due to overlap with SPEC-057's governed execution path.
- SPEC-072 adds an explicit `auto` sentinel for per-turn model routing (SPEC-071) surfaced in the portal's model selector plus a new authenticated `GET /api/v1/runtime/flags` endpoint backed by a new `runtime:flags` policy action, exposing a curated nine-flag allowlist derived from `RuntimeSettings`.
- SPEC-066 ships four measured lexical fixes (index `skill_id`, corpus-derived IDF weighting, sublinear body-length normalization, query-side CamelCase splitting) as one package with cross-backend parity enforced by a harness over both in-memory and Postgres stores, plus a content de-duplication guardrail in `rank()`.

Dependency direction is outward only: these specs reference existing contracts (`schemas/v2.py`, `agent-chat-request.schema.json`, `model-catalog.schema.json`, `feature-flags.schema.json`), policy bundles (`policy-default.yaml` mirrors), and product code (`products/agent-platform`, `products/platform-gateway`, `products/operator-portal`, `products/skills-hub`) but contain no source code themselves. Each spec closes its own release train (v0.44.0, v0.53.0, v0.46.0) with lockstep VERSION bumps and CHANGELOG entries.

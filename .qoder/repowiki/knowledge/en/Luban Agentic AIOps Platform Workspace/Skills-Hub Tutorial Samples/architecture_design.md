Samples are organised as independent tutorial units under `samples/<category>/<name>/`, each following the fixed layout of `README.md`, optional `WALKTHROUGH.md`, `skill/` (Markdown skill documents with YAML frontmatter), `demo/` scripts, and optional `target/` infrastructure. The `acme-admin/` category ships a runnable FastAPI console (`app/`) alongside progressive skills (health-check, user-status, lock-unlock-user, password-reset) that demonstrate read-only, browser-driven, and mutating flows; the retired `web-checks/` category previously held static-mock tutorials now rebased onto acme-admin. All samples are decoupled from each other and depend only on the platform's skills-hub deployment and shared target infrastructure hosted elsewhere. The sole coupling point is `deploy-samples.sh`, which discovers sample roots by finding directories named `skill`, packs every `skill/*.md` into a single `skills-samples` Kubernetes ConfigMap via `kubectl create configmap --from-file`, applies it idempotently, and restarts the `skills-hub` deployment so the generic `samples` source re-ingests them. Skill IDs become `samples/<slug>` derived from lowercased filenames with non-alphanumerics collapsed to `-`. Because samples ship out-of-band from platform base overlays, adding or removing tutorials never touches GitOps manifests.

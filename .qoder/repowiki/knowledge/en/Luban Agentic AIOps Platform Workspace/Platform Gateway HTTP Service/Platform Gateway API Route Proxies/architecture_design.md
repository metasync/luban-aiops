Each file under `routes/` defines a FastAPI `APIRouter` with one or more endpoints mounted at `/api/v1/*` (or `/health/*`) and is aggregated by `router.py`, which creates a root `APIRouter` and calls `include_router` for every feature module. Routes are thin proxies: they extract an `x_request_id` header via `resolve_request_id`, resolve caller identity through `gateway_service.resolve_request_identity`, enforce access via `gateway_service.enforce_policy` using action constants from `policy_engine`, optionally obtain a broker-mediated delegated token via `delegation_client.obtain_delegated_token`, then call a downstream client (`incident_client`, `skills_hub_client`, `tool_gateway_client`, or `gateway_service` chat/stream helpers). Streaming endpoints return `StreamingResponse` (chat SSE), while read-only routes return plain dicts/lists. The health module provides liveness/readiness probes without identity or policy checks. Dependency direction is strictly inward toward `platform_gateway.core.*` (config, observability, request context) and `platform_gateway.services.*` (clients, policy engine, delegation); routes contain no business logic beyond request shaping and audit logging.

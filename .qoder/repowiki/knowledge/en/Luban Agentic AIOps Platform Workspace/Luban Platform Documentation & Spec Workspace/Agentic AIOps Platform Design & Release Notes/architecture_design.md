Two-part structure: (1) top-level design documents (`part-1-decision-matrix.md`, `part-2-reference-architecture.md`, `identity-and-authorization-design.md`, `authorization-matrix.md`, `policy-specification.md`, `agent-platform-runtime-options.md`, `delivery-roadmap.md`) form a linear reading order that progresses from framework selection through target architecture, identity/authorization model, enforceable policy rules, runtime options, and staged delivery; (2) `release-notes/` holds one Markdown file per implementation wave, each tied to a SPEC number and a versioned release (v0.7.0 → v0.46.0), with `release-notes/README.md` serving as the authoritative index that cross-links notes back to the design docs and the workspace model. The module is pure documentation — no code — and its internal dependency direction flows from the design documents (authoritative contracts) into the release notes (implementation evidence).

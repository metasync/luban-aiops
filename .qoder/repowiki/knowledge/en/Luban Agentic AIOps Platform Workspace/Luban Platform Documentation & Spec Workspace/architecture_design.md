The `docs/` directory is the single source of truth for non-code artifacts across the platform, split by concern into five sibling trees that reference each other rather than code:
- `adr/` holds immutable, sequentially-numbered architectural decision records (0001–0017) that justify cross-cutting runtime, identity, orchestration, and delivery choices.
- `specs/` implements the spec-driven development workflow: each `SPEC-NNN-<slug>/` folder pairs `spec.md`, `plan.md`, and `tasks.md` (with optional acceptance matrices like `failure-test-matrix.md`) to drive feature work from proposal through implementation.
- `agentic-aiops-platform/` contains higher-level design documents (reference architecture, identity/authorization design, policy specification, runtime options, delivery roadmap) plus the chronological release notes in `release-notes/` that tie shipped waves back to SPECs.
- `guides/` provides operational runbooks (getting started, portal/studio usage, configuration, integrations, troubleshooting) consumed by operators and end users.
- `workspace/` captures exploratory spikes, product boundary definitions, repository governance, and future-state model sketches that have not yet graduated into a formal SPEC.
Cross-child linkage is semantic: release notes cite SPEC numbers, ADRs reference earlier ADRs, and spike assessments in `workspace/` feed into new entries under `specs/`. There is no build or orchestrator — navigation is via per-directory READMEs and the top-level index files (`adr/README.md`, `specs/README.md`, `agentic-aiops-platform/README.md`, `guides/README.md`).

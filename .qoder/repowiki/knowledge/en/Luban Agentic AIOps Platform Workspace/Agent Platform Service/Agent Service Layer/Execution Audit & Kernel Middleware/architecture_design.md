Three cooperating concerns under `agent_service/services`:
- `execution_worker_client.py` exposes an async `handoff()` that POSTs a signed SPEC-037 envelope plus parked arguments and delegated token to the execution-runtime worker at `/api/v1/executions/handoff`, using `httpx.AsyncClient` with a bounded timeout from `RuntimeSettings.execution_worker_timeout_seconds`. Failures are normalized into two typed exceptions — `WorkerHandoffError` (with a `reason` attribute, defaulting to `worker_unavailable`) for transport/config errors and 4xx rejections, and `WorkerHandoffTimeout` for timeouts — so callers can distinguish a still-running call from a hard failure.
- `execution_records.py` defines an `ExecutionRecordStore` Protocol and two implementations (`InMemoryExecutionRecordStore`, `PostgresExecutionRecordStore`) that persist one row per approved mutating tool call across the lifecycle `requested → succeeded/failed/timeout/rejected`. The Postgres backend uses raw SQL DDL/queries against a shared `sessions` database, enforces first-write-wins semantics via `ON CONFLICT DO NOTHING` and `WHERE status = 'requested'` updates, and sweeps rows older than `RETENTION_WINDOW_DAYS=30` on startup and writes. A module-level singleton `EXECUTION_RECORD_STORE` is built by `build_execution_record_store()`, which reads `AGENT_STATE_STORE_BACKEND` / `AGENT_STATE_DB_URL` and falls back to in-memory when Postgres is unavailable.
- `kernel_middleware.py` implements two `MiddlewareBase` subclasses: `GatewayPermissionMiddleware` enforces a deny-by-default allow-list of vetted read-only gateway tools plus kernel-local task tools, returning explicit `ASK` decisions that park batches on `RequireUserConfirmEvent` for the SPEC-020 confirmation bridge; it also supports optional flow-scoped auto-signing of browser writes via a `flow_signer` callback (SPEC-051 R-1). `ToolEvidenceMiddleware` emits `tool_call` / `tool_result` frames into a request-scoped `ContextVar` sink set around each streamed turn, redacting secrets via `secret_params.redact_evidence_parameters` and bounding payload sizes.
Dependency direction is one-way: middleware and record store do not import each other; the worker client is invoked by higher-level resume paths and never imported by middleware or records.

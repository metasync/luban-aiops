- Each platform service is modeled as a Kustomize subdirectory under `gitops/dev-k8s/base/<service>/` containing a `<service>-deployment.yaml`, `<service>-service.yaml`, and per-env `runtime-config.env` plus optional `runtime-secrets.env` / `runtime-secrets.example.env` pairs.
- Runtime configuration is centralized by aggregating every service's `runtime-config.env` into a single `platform-runtime-config` ConfigMap via `configMapGenerator` envs, so services consume settings through `envFrom` rather than inline env vars.
- Secrets follow a `<service>/runtime-secrets.env` (gitignored local copy) plus `<service>/runtime-secrets.example.env` (committed template) pair pattern, kept separate from non-secret `runtime-config.env`.
- Switchable behavior is expressed as Kustomize overlays under `gitops/runtime-profiles/` and activated by regenerating `dev-k8s/kustomization.yaml` via `select-runtime-profile.sh`, keeping the active profile reviewable as a git diff.
- Dev-only capabilities (mutating tools, browser web checks) are modeled as committed 'posture' overlays (`mutating-dev`, `browser-dev`) that are always included alongside the selected LLM profile, never selectable alone.
- Operational scripts use `set -eu`, derive their script directory via `SCRIPT_DIR=$(CDPATH= cd -- "$(dirname -- "$0")" && pwd)`, and accept parameters via positional args or environment variables with defaults.

The module is organized as a thin FastAPI routing layer that delegates all business logic to `tool_gateway.services.gateway_service` and `tool_gateway.core` dependencies. `api/router.py` creates a root `APIRouter` and mounts sub-routers from `api/routes/health.py` (liveness/readiness probes) and `api/routes/tools.py` (`/api/v2/tools` prefix). Each route handler extracts an identity via `resolve_request_identity`, enforces access policy through `enforce_policy`, and forwards tool invocations to the service layer; handlers never implement protocol logic themselves. Request correlation IDs are propagated via the `x-request-id` header using `resolve_request_id`. Shared request/response contracts live in `schemas/api.py`, where `IdentityContext` mirrors the external shared-contracts schema using Pydantic v2 with `extra='forbid'` to reject unknown fields. Dependency injection is used throughout for `GatewaySettings` and `ToolRegistry`.

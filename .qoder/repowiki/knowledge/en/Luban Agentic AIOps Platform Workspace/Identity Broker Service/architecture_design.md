The service is a FastAPI application (`src/identity_service/app.py`) bootstrapped by `main.py` via a uvicorn entry point registered as the `identity-service` console script. The app wires a request-logging middleware, Prometheus metrics setup, and OpenTelemetry telemetry before mounting a single `router` that aggregates three route modules: `health`, `auth`, and `identity`. Business logic is split into services under `services/`: `identity_service` handles Keycloak OIDC flows (login start/callback/logout/refresh), `exchange_service` implements broker-mediated token delegation (verifying subject tokens against the broker's RSA key and minting audience-bound delegated tokens with optional RFC 8693 `act` claims), and `token_service` owns the RSA key lifecycle (load/generate/persist) plus JWKS issuance. Configuration is centralized in `core/config.py` as frozen dataclasses parsed from environment variables, exposed through an `lru_cache`d `get_settings()` dependency injected into routes. Cross-cutting concerns live in `core/` (`config`, `metrics`, `observability`, `telemetry`, `runtime`). Schemas in `schemas/` define Pydantic models for all request/response payloads. Audit events are emitted asynchronously via `audit_emitter` to a configurable audit service. Workload identity support discovers the cluster OIDC issuer's JWKS via OpenID discovery and caches per-issuer clients at module scope.

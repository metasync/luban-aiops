The module is organized around three layers. `main.py` is the entry point that loads `GatewayRunSettings` (host/port from env) and starts uvicorn with the app. `app.py` defines `create_app()`, which configures logging via `core.observability`, builds a `ToolRegistry` gated by `mutating_tools_enabled`, lazily imports and registers optional connectors (k8s, elastic, skills, incidents, browser) based on `GatewaySettings` flags, attaches the registry to `app.state`, installs an HTTP middleware that resolves a correlation `x-request-id` and emits structured log events, includes the API router, and enables metrics/telemetry. `metadata.py` centralizes service identity constants (`SERVICE_NAME`, `SERVICE_TITLE`, `SERVICE_VERSION`, defaults). The `core/` subpackage provides reusable infrastructure: `config.py` exposes a cached `get_settings()` singleton of frozen `GatewaySettings` dataclasses parsed from `GATEWAY_*` / `IDENTITY_*` env vars; `runtime.py` provides `GatewayRunSettings` for the uvicorn host/port; `dependencies.py` offers a FastAPI dependency `get_tool_registry` that reads the registry from `request.app.state`; `request_context.py` implements request/user-id resolution per SPEC-005; `metrics.py`, `telemetry.py`, and `observability.py` wire Prometheus metrics, OpenTelemetry tracing, and structured logging. Dependency direction is one-way: `app.py` depends on `core/*` and `tools.registry`, while `core/*` only depend on stdlib, FastAPI, and `metadata` — no reverse imports from tools back into core.

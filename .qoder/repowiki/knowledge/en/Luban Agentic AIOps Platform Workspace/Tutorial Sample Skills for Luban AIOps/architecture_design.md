Each sample under `samples/<category>/<name>/` is an independent tutorial unit with the same layout: `README.md` (tutorial), optional `WALKTHROUGH.md` (live run), `skill/` (one or more skill documents consumed by skills-hub), optional `demo/` scripts, and optional `target/` infrastructure. Samples have no code dependencies on each other; they depend only on the platform's skills-hub deployment and shared target infrastructure (e.g. `browser-check-target`) hosted elsewhere in the repo. The sole coupling to a running cluster is `deploy-samples.sh`, which discovers sample roots by `find -type d -name skill`, packs every `skill/*.md` into a single `skills-samples` ConfigMap using `kubectl create configmap --from-file`, applies it idempotently, then restarts the `skills-hub` deployment so the generic `samples` source re-ingests. Skill IDs become `samples/<slug>` derived from lowercased filenames with non-alphanumerics collapsed to `-`. Samples ship out-of-band from platform base overlays, so adding/removing tutorials never touches GitOps manifests.

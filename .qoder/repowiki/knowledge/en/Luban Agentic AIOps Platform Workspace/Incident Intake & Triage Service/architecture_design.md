Layered FastAPI application with a clear separation of concerns:
- Entry point: `main.py` boots uvicorn using `IncidentRunSettings.from_env()`; `app.py` creates the FastAPI app, registers a request-id middleware, includes the central router, and wires metrics/telemetry.
- API layer (`api/routes/`) exposes health, incident CRUD, and webhook endpoints via a single `APIRouter` composed in `router.py`.
- Domain schemas live in `schemas/incident.py` as Pydantic v2 models (`Incident`, `TriageReport`, `ConnectorDispatch`) that mirror the shared contract JSON schemas (SPEC-015 R-1).
- Services layer implements business logic: `incident_store.py` defines an `IncidentStore` Protocol with two backends — `InMemoryIncidentStore` (dev/test) and `PostgresIncidentStore` (production, psycopg3 async) — selected by `build_incident_store` based on `INCIDENT_STORE_BACKEND`; `connectors.py` defines a `Connector` Protocol and registry for pluggable collaboration sinks (currently only `audit`); `triage.py` and `normalization.py` orchestrate agent calls and alert normalization; `query_auth.py` validates query/workload tokens.
- Core cross-cutting concerns in `core/`: frozen `IncidentSettings` dataclass loaded from `INCIDENT_*` env vars with `@lru_cache`, Prometheus metrics setup, OpenTelemetry + logging configuration, request-context request-id propagation, and runtime settings.
- Dependency direction is strictly inward: routes → services → core; stores and connectors are injected via Protocols so tests can swap implementations. The app lifespan initializes the store and connectors at startup, failing fast on unknown connector names (SPEC-015 R-5).

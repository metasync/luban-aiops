The repository is a product-oriented monorepo: each capability lives in `products/<name>/` as an independent Python FastAPI service (agent-platform, identity-broker, platform-gateway, tool-gateway, audit-service, execution-runtime, incident-service, skills-hub) plus the `operator-portal` web UI. Every product follows the same internal layout — `src/<pkg>/api/`, `core/`, `services/`, `schemas/`, `policies/`, `tools/`, with `app.py` + `main.py` entry points that wire logging, metrics, telemetry, request-id middleware, and router inclusion via a `create_app()` factory. Cross-cutting contracts are centralized under `shared/shared-contracts/schemas/*.schema.json` (JSON Schema draft 2020-12) and `policies/policy-default.yaml`, which are copied into consumers by `make sync-policy`. The root `Makefile` orchestrates cross-product concerns: it declares `PYTHON_PRODUCTS` / `IMAGE_PRODUCTS`, builds coordinated container images tagged from `VERSION`, renders Kustomize overlays under `shared/platform-ops/gitops/`, runs per-product tests, validates policies against schemas, and drives e2e demos under `shared/platform-ops/e2e/`. Deployment uses GitOps overlays (`dev-k8s`, `runtime-profiles/*`) and scripts such as `sync-*-secret.sh` to provision secrets; samples live separately under `samples/` and are installed out-of-band so base overlays never depend on them. Architecture Decision Records in `docs/adr/` and spec-driven development artifacts in `docs/specs/SPEC-NNN/` (plan/spec/tasks) document boundary decisions like gateway extraction (ADR-0005), broker-mediated delegation (ADR-0004), and HITL gating.

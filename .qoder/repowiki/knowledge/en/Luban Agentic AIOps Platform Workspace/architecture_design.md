The repository is an orchestrator rather than a runtime: the root `Makefile` declares the product surface (`PYTHON_PRODUCTS`, `IMAGE_PRODUCTS`) and delegates per-product work to each `products/<name>/Makefile`, while `mk/` supplies shared fragments for Python packaging and Docker image construction. Cross-cutting concerns are centralized at the root:
- `shared/shared-contracts/` holds the canonical API/event/policy/schema definitions consumed by multiple products (e.g. policy bundles synced via `make sync-policy`, secret vocabulary validated via `validate-secret-vocabulary`).
- `shared/platform-ops/gitops/` contains Kustomize overlays rendered by `make overlays`; `shared/platform-ops/dashboards/` is validated offline by `make validate-dashboards`.
- `shared/base-images/base-uv/` provides the common non-root Amazon Linux + uv base image referenced by every product `Dockerfile`.
- `samples/acme-admin/` is a separately deployed sample application exercising the platform end-to-end.
The verification gate `make verify` composes all of these into a single pre-commit/pre-push check, and `make build` produces coordinated images tagged from the single `VERSION` file, writing `.images.env` so the GitOps overlay references one consistent set of tags. Product boundaries are enforced by keeping inter-service communication through the contracts in `shared/shared-contracts/` rather than direct imports.

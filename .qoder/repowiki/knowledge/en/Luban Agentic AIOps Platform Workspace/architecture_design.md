The repository is a product-oriented monorepo. `products/` holds independently built, containerized services (agent-platform, audit-service, execution-runtime, identity-broker, incident-service, operator-portal, platform-gateway, skills-hub, tool-gateway; policy-center is design-stage). Each product ships its own `pyproject.toml`, `.python-version`, `Dockerfile`, `Makefile`, `src/<package>/`, and `tests/`. Cross-cutting concerns live in `shared/`: `shared-contracts` (API/event/policy schemas, SQL migrations, validation scripts), `platform-ops` (Kubernetes/kustomize overlays under `gitops/dev-k8s`, dashboards, e2e scripts), and `shared-sdk`. The root `Makefile` is the single orchestration entry point: it delegates per-product `sync/test/lint/build/push` via `make -C products/$p`, computes a coordinated `IMAGE_TAG` from `VERSION`, writes `.images.env`, and aggregates verification targets (`overlays`, `validate-dashboards`, `validate-policy`, `validate-version`, `validate-secret-vocabulary`, `validate-password-policy`, `portal-test`, contract tests, delegated-custody/runtime/multiproc/edge tests, execution-failure test) into `make verify`. Build fragments are factored into `mk/{defaults,image,python}.mk`; base images are built from `shared/base-images/base-uv`. Samples (`samples/acme-admin`) are deployed out-of-band so they never enter the base overlay. Docs follow spec-driven development: `docs/specs/SPEC-NNN-*` (plan/spec/tasks), `docs/adr/`, `docs/agentic-aiops-platform/release-notes/`, and `docs/workspace/` spikes.

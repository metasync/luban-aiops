The repository is a product-oriented monorepo. Each capability lives under `products/<name>/` as an independent Python service (agent-platform, platform-gateway, tool-gateway, identity-broker, audit-service, execution-runtime, incident-service, skills-hub) plus the `operator-portal` web UI; each product ships its own `src/<package>/`, `tests/`, `Dockerfile`, `Makefile`, `pyproject.toml`, and `uv.lock`. Cross-cutting assets live in `shared/`: `shared/shared-contracts` defines JSON schemas, policy bundles, and validation scripts that all products consume; `shared/platform-ops/gitops` holds Kustomize overlays (`dev-k8s`, `runtime-profiles/*`) used by `make deploy`; `shared/platform-ops/e2e` contains integration demo scripts; `shared/base-images/base-uv` provides the common uv-based container base. The root `Makefile` is the single entry point: it iterates over `PYTHON_PRODUCTS` and `IMAGE_PRODUCTS` to run per-product `sync`, `test`, `lint`, `build`, `push`, and coordinates overlay rendering, policy sync/validation, version lockstep checks, and deployment via `shared/platform-ops/gitops/dev-k8s/deploy.sh`. Product boundaries are enforced through HTTP APIs defined in `shared/shared-contracts/schemas` rather than direct imports between services, keeping identity, policy, and execution concerns separated.

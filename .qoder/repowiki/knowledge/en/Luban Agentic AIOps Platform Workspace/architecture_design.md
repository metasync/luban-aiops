The repository is organized as product-oriented services under `products/` plus shared assets under `shared/`. Each Python service follows the same internal layout (`src/<service>/api`, `core`, `schemas`, `services`, `tools`) so they can be built, tested, and containerized uniformly. Cross-service communication is enforced by JSON schemas in `shared/shared-contracts/schemas/` (chat, session, identity, policy, tool-invocation events) rather than direct imports; the platform-gateway verifies tokens via identity-broker and proxies chat/session calls to agent-platform while delegating tool execution to tool-gateway, with policy decisions applied at both gateways using the canonical `policy-default.yaml` kept in sync from `shared/shared-contracts/policies/`. Deployment is driven by Kustomize overlays in `shared/platform-ops/gitops/dev-k8s/`, which reference images produced by the root `make build` target that tags every image with a single coordinated tag written to `.images.env`. The top-level `Makefile` aggregates per-product routines, runs all tests, validates overlays, and deploys the dev cluster — making `make verify` the pre-commit/pre-push gate across the whole platform.

The repository is a product-oriented monorepo: each capability lives under `products/<name>/` as an independently buildable, Dockerized Python service with its own `src/<pkg>/`, `tests/`, `pyproject.toml`, `uv.lock`, and `Dockerfile`. Cross-cutting orchestration happens at the root via `Makefile`, which enumerates `PYTHON_PRODUCTS` and `IMAGE_PRODUCTS`, delegates per-product `sync/test/lint/build/push`, renders Kustomize overlays from `shared/platform-ops/gitops/{dev-k8s,runtime-profiles/*}`, and enforces policy/version lockstep through `verify` (test + overlays + policy validation + scenario evaluation + version check). The `platform-gateway` is the portal-facing edge that verifies tokens, enforces policies, proxies chat/session traffic, and delegates tool calls to `tool-gateway`; `identity-broker` handles SSO/federation/group normalization; `audit-service` ingests durable events from gateway/tool/identity services; `skills-hub` indexes Markdown skills; `incident-service` normalizes alerts and runs triage; `execution-runtime` isolates bounded mutating actions; `operator-portal` serves the web UI. Shared surface area is isolated in `shared/shared-contracts` (JSON schemas, policy YAMLs, validation scripts), `shared/shared-sdk` (client libraries), and `shared/platform-ops` (GitOps, e2e demos, skill runbooks). Dependency direction is strictly outward from products to shared contracts and inward through the gateway; there is no direct cross-product import — inter-service communication goes over HTTP/gRPC using the JSON schemas.

The repository is a product-oriented monorepo under `products/`, where each directory is an independently buildable, containerized service with its own `pyproject.toml`, `Dockerfile`, `Makefile`, and `tests/`. Cross-cutting concerns live in `shared/`: JSON schemas and policy YAMLs in `shared/shared-contracts`, reusable SDKs in `shared/shared-sdk`, and Kubernetes GitOps overlays plus e2e scripts in `shared/platform-ops/gitops` and `shared/platform-ops/e2e`. The root `Makefile` is the single entry point that delegates to per-product Makefiles, coordinates building all images into a coordinated semver tag derived from the root `VERSION` file, validates the canonical policy bundle against the shared schema, renders Kustomize overlays, and runs the `verify` gate (test + overlays + policy + version lockstep). Services communicate over HTTP/gRPC boundaries defined by the shared JSON schemas — there is no shared library coupling between products; instead they depend on `shared/shared-contracts` for contract validation. Deployment targets are driven by Kustomize overlays under `shared/platform-ops/gitops/dev-k8s` (with runtime profiles), orchestrated via `make deploy` which invokes `deploy.sh` and can auto-load images into a kind cluster.

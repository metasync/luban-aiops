The repository is a product-oriented monorepo under `products/`, where each directory is an independently buildable, Dockerized Python (uv) service with its own `src/<package>/`, `tests/`, `pyproject.toml`, `Dockerfile`, and `Makefile`. Cross-cutting concerns live in `shared/`: `shared/shared-contracts` holds JSON schemas, policy YAMLs, and validation scripts that all products consume; `shared/platform-ops` contains Kustomize GitOps overlays (`dev-k8s`, `runtime-profiles`) and deployment/sync scripts; `shared/base-images` provides the base uv image. The root `Makefile` orchestrates coordinated builds, pushes, overlay rendering, policy sync, version lockstep validation, and e2e demos against a deployed cluster. Services communicate over well-defined HTTP APIs described by the shared schemas — the `platform-gateway` is the portal-facing edge performing token verification, policy enforcement, chat/session proxying, and token delegation to downstream services (`agent-platform`, `tool-gateway`, `identity-broker`, `incident-service`, `skills-hub`, `audit-service`). Each service follows a uniform internal layout: `api/routes` for FastAPI endpoints, `services/` for business logic, `schemas/` for request/response models, `core/` for config/telemetry/metrics/request-context, and a `main.py`/`app.py` entrypoint. Policy decisions are centralized via a canonical `policy-default.yaml` copied into each consumer's `policies/` directory through `make sync-policy`.

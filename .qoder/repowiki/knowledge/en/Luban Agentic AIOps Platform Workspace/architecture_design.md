The repository is a product-oriented monorepo. Each capability lives under `products/<name>/` as an independent FastAPI service (agent-platform, identity-broker, platform-gateway, tool-gateway, audit-service, incident-service, execution-runtime, skills-hub) plus the `operator-portal` web UI; every Python product ships its own `pyproject.toml`, `Dockerfile`, `Makefile`, and `tests/` directory and is built into a container image tagged with a coordinated semver derived from the root `VERSION` file. Cross-cutting concerns are centralized: `shared/shared-contracts` holds JSON Schema API/event models and the canonical policy bundle (`policies/policy-default.yaml`) that both gateways consume; `shared/platform-ops/gitops` contains Kustomize overlays (dev-k8s, runtime profiles) rendered by the root Makefile; `mk/` provides shared Make fragments for Docker builds and Python tooling. The root `Makefile` orchestrates cross-product workflows — `sync`, `test`, `build`, `push`, `overlays`, `verify` (which runs tests, kustomize renders, policy validation, scenario checks, version lockstep, and secret-vocabulary validation), and `deploy` against the dev cluster. Dependency direction is strictly outward: products depend on `shared/shared-contracts` schemas and policies but never on each other directly; inter-service communication happens over HTTP/gRPC boundaries defined by those contracts, with identity propagated via JWT tokens issued by `identity-broker` and verified by consumers via JWKS.

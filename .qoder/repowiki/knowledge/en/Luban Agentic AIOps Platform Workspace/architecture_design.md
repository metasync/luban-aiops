The workspace is organized as a product-oriented monorepo under `products/`, where each directory is an independently buildable, testable Python service (agent-platform, platform-gateway, tool-gateway, identity-broker, audit-service, execution-runtime, incident-service, skills-hub) plus the operator-portal web UI. All products share cross-cutting contracts in `shared/shared-contracts` (JSON schemas for chat/session/stream/audit/policy/tool-invocation events, default policy bundles, and validation scripts) so services communicate via explicit API/event contracts rather than internal imports. The root `Makefile` orchestrates cross-product routines: it enumerates `PYTHON_PRODUCTS` and `IMAGE_PRODUCTS`, runs per-product `make test`/`build`/`lint`, renders GitOps overlays under `shared/platform-ops/gitops` with `kustomize build`, synchronizes canonical policy bundles to consumers via `make sync-policy`, and enforces version lockstep through `validate-version`. Deployment targets Kubernetes via Kustomize overlays (`dev-k8s`, `runtime-profiles/default|mutating-dev|browser-dev`) driven by scripts in `shared/platform-ops/gitops`. Documentation follows a three-tier Spec-Driven Development model: Tier 1 architecture records (long-lived), Tier 2 feature specs under `docs/specs/SPEC-NNN-<slug>/` (spec.md + plan.md + tasks.md, frozen after delivery), and Tier 3 living state docs; ADRs in `docs/adr/` capture cross-product architectural decisions. The verification gate `make verify` combines unit tests, overlay rendering, policy scenario validation, version checks, and secret-vocabulary validation into a single pre-commit/pre-push CI-equivalent command.

The repository is organized as a product-oriented monorepo under `products/`, where each directory is an independently buildable, containerized service with its own `pyproject.toml`, `Dockerfile`, `Makefile`, and `tests/` suite: `agent-platform` (agent runtime, session handling, streaming), `platform-gateway` (portal-facing edge with token verification, policy enforcement, chat/session proxying, delegation), `tool-gateway` (normalized tool/connector access including MCP and external systems), `identity-broker` (SSO, identity federation, group normalization, propagation), `audit-service` (durable audit ingest, retention-bounded store, scoped query API), `incident-service` (Alertmanager webhook intake, canonical incident model, triage reports, connector dispatch), `skills-hub` (Git-based Markdown skill ingestion, validation, indexing, ranked search), and `operator-portal` (nginx + static web UI). Cross-cutting concerns live in `shared/`: `shared-contracts` defines JSON schemas and YAML policies consumed by all products; `shared-sdk` holds client/tracing helpers; `shared/platform-ops/gitops/dev-k8s` provides Kustomize overlays per environment plus runtime profiles (dashscope/deepseek/openai) and sync scripts for secrets. The root `Makefile` orchestrates cross-product routines (`sync`, `test`, `build`, `push`, `verify`, `deploy`) and enforces version lockstep against a single `VERSION` file, while `mk/` contains shared Make fragments (`defaults.mk`, `image.mk`, `python.mk`). Documentation follows spec-driven development via `docs/specs/SPEC-NNN-*` directories (plan/spec/tasks), ADRs under `docs/adr/`, and operator/user guides under `docs/guides/`. Dependency direction is strictly product-to-shared-contracts; products communicate over HTTP APIs defined by the shared schemas rather than direct code coupling.

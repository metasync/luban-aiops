The repository is organized as a product-oriented monorepo under `products/`, where each service (agent-platform, identity-broker, platform-gateway, tool-gateway, audit-service, skills-hub, operator-portal) ships its own Dockerfile, Makefile, `pyproject.toml` + `uv.lock`, source tree (`src/<pkg>/`), and `tests/`. Cross-cutting concerns live in `shared/`: JSON schemas and policy YAMLs in `shared/shared-contracts/`, Kubernetes/Kustomize overlays and deployment scripts in `shared/platform-ops/gitops/dev-k8s/`, and base container images in `shared/base-images/base-uv/`. The root `Makefile` delegates per-product routines via `make -C products/<name>` and owns coordinated image tagging (git SHA + optional profile), policy synchronization from `shared/shared-contracts/policies/policy-default.yaml` to consumers, Kustomize overlay rendering, and a single `deploy` target that invokes `shared/platform-ops/gitops/dev-k8s/deploy.sh`. Dependency direction is strictly outward: services depend on `shared/shared-contracts` schemas and policies but never on each other's source; inter-service communication happens over HTTP APIs defined by the shared JSON schemas. Runtime profiles (dashscope/deepseek/openai) are layered via Kustomize overlays under `shared/platform-ops/gitops/runtime-profiles/`.

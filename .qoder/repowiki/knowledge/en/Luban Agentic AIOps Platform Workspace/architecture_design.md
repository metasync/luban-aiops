The repository is organized as a product-oriented monorepo under `products/`, where each directory is a self-contained service with its own `src/<package>/`, `tests/`, `Dockerfile`, `Makefile`, `pyproject.toml`, and `uv.lock`. The root `Makefile` orchestrates cross-cutting concerns: it defines lists of `PYTHON_PRODUCTS` and `IMAGE_PRODUCTS`, delegates per-product `sync/test/lint/build/push` targets via `make -C products/<name>`, builds coordinated container images tagged from the single `VERSION` file into `.images.env`, renders Kustomize overlays in `shared/platform-ops/gitops`, validates policy bundles against JSON schemas, and runs e2e demo scripts. Services follow a consistent internal layout — `api/routes/*` for HTTP endpoints, `services/*` for business logic, `schemas/*` for request/response models, `core/*` for config/metrics/telemetry/request-context, and `main.py`/`app.py` entry points — enabling uniform testing and deployment. Cross-service boundaries are enforced through `shared/shared-contracts` (JSON schemas for agent chat, sessions, audit events, identity tokens, incidents, skills, policies) rather than direct imports; consumers depend on these schemas and on HTTP/gRPC contracts. Policy enforcement is centralized: a canonical `policy-default.yaml` in `shared/shared-contracts/policies` is copied into `platform-gateway` and `tool-gateway` via `make sync-policy`, and each gateway ships a `services/policy_engine.py` that evaluates decisions before proxying or tool invocation. Identity flows through `identity-broker` (SSO, token exchange, group normalization) and `platform-gateway` (token verification, action policy, delegation), while `audit-service` receives durable audit events from all other services. Deployment uses GitOps overlays under `shared/platform-ops/gitops/dev-k8s` and `runtime-profiles/*` (openai, dashscope, deepseek, mutating-dev) rendered by `kustomize build` during `make overlays` and deployed via `make deploy`.

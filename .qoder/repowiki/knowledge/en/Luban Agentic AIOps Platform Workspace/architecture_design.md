The repository is a product-oriented monorepo under `products/` where each capability ships as an independent Python service (agent-platform, identity-broker, platform-gateway, tool-gateway, audit-service, execution-runtime, incident-service, skills-hub) plus the `operator-portal` web UI. Every product follows the same internal layout — `src/<pkg>/api/routes`, `core/config+runtime+telemetry`, `schemas`, `services`, `tests`, `Dockerfile`, `pyproject.toml`, `.python-version`, and a per-product `Makefile` — so the root `Makefile` can orchestrate them uniformly via `sync`, `test`, `build`, `push`, and `deploy`. Cross-cutting concerns live in `shared/`: JSON Schema contracts (`shared/shared-contracts/schemas`) define inter-service payloads; policy bundles (`shared/shared-contracts/policies`) are copied into both gateway products and the dev overlay; scripts validate versions, policies, and scenarios. Deployment is GitOps-driven: `shared/platform-ops/gitops/dev-k8s` holds Kustomize overlays rendered by `make overlays`, with secrets synced by helper scripts (e.g. `sync-audit-secrets.sh`, `sync-execution-signing-secret.sh`). End-to-end demos run against a deployed cluster via `shared/platform-ops/e2e/*.sh`. Spec-driven development is enforced through `docs/specs/SPEC-NNN-*` triads (plan/spec/tasks), `docs/adr/` decisions, and delivery-roadmap/release-note artifacts that gate releases. The root `Makefile` is the single entry point: `make verify` runs every product test suite, renders overlays, validates policy bundles and scenarios, and checks version lockstep between `VERSION`, product manifests, and the portal.

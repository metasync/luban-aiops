Layered FastAPI application under `src/skills_hub/`:
- Entry point: `main.py` exposes the `skills-hub` CLI script; `app.create_app()` wires lifespan (store init, sync manager start), HTTP middleware (request-id + log_event), metrics, and OpenTelemetry.
- API layer (`api/routes/{health,skills,status}.py`) mounted through `api/router.py`, which deliberately registers `/status` and `/search` before the `{skill_id:path}` catch-all so FastAPI's declaration-order matching is correct.
- Services layer: `ingestion.py` parses Markdown frontmatter against the shared skill contract (knowledge / executable_flow / composition classes); `scoring.py` provides a pure, deterministic scorer (title/tag/id/body weights, IDF via `CorpusStats`, CamelCase-aware query tokenization) shared by both backends; `skill_store.py` defines the `SkillStore` Protocol and two implementations — `InMemorySkillStore` for dev/test and `PostgresSkillStore` with raw psycopg DDL, GIN tsvector indexes, and per-source atomic replace; `sync.py` drives periodic git clone + ingestion; `query_auth.py` validates workload JWTs against a projected-token registry; `audit_emitter.py` emits audit events to the audit service.
- Core layer: `config.py` parses all `SKILLS_*` env vars into frozen dataclasses (`SourceSpec`, `QueryClient`, `WorkloadClient`, `SkillsSettings`); `observability.py`, `metrics.py`, `telemetry.py`, `request_context.py`, `runtime.py` provide cross-cutting concerns.
- Schemas: `schemas/skill.py` holds the Pydantic `Skill` model mirrored by the ingestion validator and DB row mapper.
- Dependency direction is strictly inward: routes → services → schemas/core; no cross-imports between sibling services except via the `SkillStore` protocol and `Skill` schema. The store factory `build_skill_store(settings)` selects backend at runtime based on `SKILLS_STORE_BACKEND`.

- External tool exposure is config-driven: each provider declares a tuple of gateway-owned spec objects (`AdmittedTool` / `ServiceNowReadTool`) carrying name, schema, tier, and target identifier — server metadata is never trusted for admission or risk level.
- Every outbound call returns structured `(data_or_none, error_tuple)` where errors are `(code, message, status)` triples with stable codes (`MCP_SDK_UNAVAILABLE`, `SERVICENOW_TIMEOUT`, etc.) so callers can distinguish policy denial from target-unavailable failures.
- Authentication is delegated to `resolve_outbound_auth` plus a shared `CredentialSetStore`/`OAuth2TokenClient`; credential set names may surface in messages but tokens never reach logs, results, or evidence.
- The target identity mode is explicitly `acting_service` in both connectors — the gateway calls the remote with its own credential, not the requester's delegated identity — and records this in `audit_attribution` so audit records do not imply target-side per-user RBAC.
- Fail-closed posture: transport timeouts, connection failures, non-2xx responses, unparseable bodies, and missing SDKs all become structured error outcomes rather than empty successes or silent retries.
- Optional heavy dependencies (`mcp` SDK, `httpx2`) are imported inside the code paths that need them so a deployment without the optional transport still imports cleanly and fails with a documented error code.

Two parallel sub-packages under `tool_gateway/`:

- `api/routes/` — per-feature FastAPI `APIRouter` modules (`health.py`, `tools.py`, `secrets.py`, `authorizations.py`) each exposing a module-level `router`. `api/router.py` is the single composition point that mounts them under the app root via `include_router`, keeping route registration centralized.
- `schemas/` — pure Pydantic models mirroring shared-contracts (`api.IdentityContext`) and defining SPEC-070 authorization wire shapes (`authorization.py`). They contain no route logic; routes import them only for request/response validation.

Dependency direction is strictly inward: routes depend on `core.config`, `core.dependencies`, `core.request_context`, `services.*`, and `schemas.*`; they never call each other. Cross-cutting concerns (settings injection via `Depends(get_settings)`, request-id resolution from `request.state` or `X-Request-Id`, identity resolution via `resolve_request_identity`, policy enforcement via `enforce_policy`) are factored into services so routes stay thin handlers. Feature flags gate optional surfaces: delegated tool invocation uses `GATEWAY_DELEGATED_INVOKE_ENABLED` and the authorization runtime uses `GATEWAY_DELEGATED_AUTHORIZATION_ENABLED`, both failing closed when absent. The authorization routes additionally require an `AuthorizationService` published on `request.app.state` by `create_app`, checked through `_require_service` before any handler runs.

- Fail-closed refusal types (`DelegatedInvokeError`, `AuthorizationError`, `CliError`, `CustodyError`) carry a fixed HTTP status code plus a non-sensitive detail string and never wrap raw library/provider messages.
- Bearer tokens are extracted via a local `_bearer(request)` helper that partitions on ` `, strips whitespace, rejects empty tokens, and enforces a `MAX_TOKEN_BYTES` size limit before any cryptographic operation.
- JWT verification always pins algorithm `RS256`, required claims (`exp`, `iss`, `sub`, `aud` plus `act`, `authentication_source` for human tokens), issuer, audience, and an exact subject allowlist from `GatewaySettings`, with all exceptions collapsed to a generic error message.
- Module-level caches of `jwt.PyJWKClient` keyed by JWKS URL are provided alongside a `reset_*_state()` function that clears them for tests, avoiding per-request JWKS fetches while remaining test-resettable.
- Sensitive values flow through `pydantic.SecretStr` and are never logged or echoed; when persistence is needed only a `capability_hash` (SHA-256 hex digest) is stored instead of the plaintext.
- All Postgres access goes through `PostgresCustodyStore.connection()` / `.guarded()` context managers that set `statement_timeout='5s'` and `lock_timeout='3s'`, and long-running operations serialize on `pg_advisory_xact_lock(hashtextextended(set_id,700016))` before touching bindings.

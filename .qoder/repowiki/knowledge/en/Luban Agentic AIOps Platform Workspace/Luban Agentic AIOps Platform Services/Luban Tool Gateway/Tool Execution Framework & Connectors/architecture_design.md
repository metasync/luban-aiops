Internal layering is a clear base → registry → connectors stack:
- `base.py` declares the abstract `BaseTool` contract (`definition`, async `execute(parameters, identity)`) plus the immutable `ToolDefinition` / `ToolResult` dataclasses and shared evidence/error helpers; risk tiers are restricted to the frozen `VALID_RISK_LEVELS = {read, write, admin}`.
- `registry.py` holds an in-process `ToolRegistry` keyed by name, validates risk levels at registration time, and enforces the mutating-tools gate (`allow_mutating` backed by `GATEWAY_MUTATING_TOOLS_ENABLED`); its `invoke` wraps every call in a structured error envelope so callers always receive a `tool-result` schema object.
- Each connector file (e.g. `http_connector.py`, `browser_connector.py`, `k8s_connector.py`, `elastic_connector.py`, `incidents_connector.py`, `secrets_connector.py`, `skills_connector.py`) registers one or more `BaseTool` subclasses via a `register_tools(registry)` method and owns its transport + policy surface.
- Shared cross-cutting concerns live in sibling modules consumed by connectors: `credential_sets.py` (file-backed, mtime-reloaded named credential store with scheme dispatch), `auth_resolution.py` (single `resolve_outbound_auth` dispatcher for basic/bearer/oauth2_client_credentials/oauth2_authorization_code schemes, setting per-task `DELEGATION_MODE` via `ContextVar`), `oauth_client.py` (process-local cached machine `client_credentials` token client), `user_delegated_client.py` (SPEC-070 provider-independent authorization-code acquisition with PKCE S256, custody-backed refresh, LRU access cache, and `DelegatedAcquisitionError` taxonomy), `delegated_configuration.py`, `browser_sessions.py`, `url_redaction.py`, `redaction.py`, `secret_delivery.py`, `password_policy.py`, and `auth_resolution.py`.
- Dependency direction is strictly inward: connectors depend on `base`/`registry`/`credential_sets`/`auth_resolution`; they do not import each other's tool classes. The HTTP connector additionally reuses `origin_of` from `browser_connector.py` as the canonical origin normalizer.
- Two OAuth paths coexist but never share code: `OAuth2TokenClient` handles machine-grant `client_credentials` tokens; `user_delegated_client.DelegatedAcquisitionClient` handles user-delegated `authorization_code` flows, with `auth_resolution.resolve_outbound_auth` dispatching between them based on the credential set's `scheme` field.

- Connectors implement `BaseTool` subclasses whose `definition` returns a `ToolDefinition` with a static `risk_level` of exactly `read`, `write`, or `admin`, and register themselves through a `register_tools(registry)` entry point rather than direct registry calls.
- All connector errors and denials return a `ToolResult` constructed via `make_error_result` / `make_denied_result` / `build_evidence`, never raise raw exceptions to callers — unknown tools and caught exceptions are normalized into structured `{code, message}` envelopes.
- Connector configuration is parameterized through constructor kwargs (e.g. `allow_origins`, `timeout_ms`, `max_response_bytes`, `transport`, `token_client`, `delegated_client`) so tests can inject `httpx.MockTransport` and mock clients without touching module globals.
- Outbound URLs are validated before any socket is opened via `_validate_destination` / `origin_of`: only `http`/`https` schemes, no userinfo, loopback/link-local/multicast hosts refused, and origins must match a deny-by-default allowlist; POST bodies are pre-bounded by depth/key/count/byte limits.
- Credential sets are resolved server-side by name from `CredentialSetStore`; literal secrets are never accepted as model parameters, and unknown schemes or missing required fields are ignored with a warning (fail-closed) rather than admitted half-formed.
- Sensitive values (tokens, secrets, query-string credentials) are never logged or serialized into results/evidence; only the failure class name and the credential-set **name** surface in logs, enforced via `SecretStr` and explicit redaction helpers like `redact_secret_query`.

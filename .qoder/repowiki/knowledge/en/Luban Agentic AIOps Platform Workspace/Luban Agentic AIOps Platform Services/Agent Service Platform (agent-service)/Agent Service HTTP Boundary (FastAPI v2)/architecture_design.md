Three cooperating sub-packages form a thin boundary around the kernel:
- `schemas/` declares the public Pydantic contracts (`api.py` for the transitional surface, `v2.py` for the current `/api/v2` contract) that both routes and clients share.
- `api/v2/routes.py` is the sole FastAPI entry point: it mounts an `APIRouter(prefix="/api/v2")`, parses headers (`X-User-ID`, `x-request-id`, `Authorization`) as identity carriers, validates bodies against `schemas.v2`, delegates business logic to `agent_service.services.*` (session store, confirmation registry, model catalog, evidence store, execution recovery, skill graduation), and forwards bearer tokens opaquely to the kernel via `get_runtime_kernel()`.
- `tools/gateway_tools.py` provides AgentScope `FunctionTool` implementations that call back into the gateway's `/api/v2/tools/{discover,invoke}` endpoints, carrying request-scoped context via `ContextVar`s (`DELEGATED_TOKEN`, `GENERATION_OWNER_TOKEN`, `CHAT_SESSION_ID`, `EXECUTION_REQUESTS`, etc.) set by the runtime kernel around each turn.

Cross-child wiring: routes import schema models from `schemas.v2`; tools are consumed by the kernel which in turn is invoked from routes. Identity never crosses the HTTP boundary in bodies — only via `X-User-ID` and the gateway-forwarded `Authorization: Bearer` header, which routes pass through without inspection (SPEC-008 R-5). The same bearer token is re-emitted by `gateway_tools` on tool discovery/invocation so downstream gateways see the original requester's credentials.

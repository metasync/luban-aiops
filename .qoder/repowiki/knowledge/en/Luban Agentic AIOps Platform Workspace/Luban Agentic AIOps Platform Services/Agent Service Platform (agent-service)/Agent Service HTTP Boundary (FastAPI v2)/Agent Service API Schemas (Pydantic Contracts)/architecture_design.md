Two parallel contract layers coexist under `schemas/`:
- `api.py` holds the legacy/transitional session/chat models (`SessionRecord`, `CreateSessionRequest`, `ChatRequest`, `ChatResponse`) used by the older `/api/` surface.
- `v2.py` is the single source of truth for the platform-owned `/api/v2/` surface; its module docstring states it is validated against JSON Schema files in `shared/shared-contracts/schemas/agent-*.schema.json`, making those external schemas the authoritative wire format and the Pydantic models the runtime validators.

Models are grouped by feature area with clear section comments: Chat (`AgentChatRequest`, `AgentChatConfirmRequest`, `AgentChatResponse`), Streaming (`AgentStreamEvent` with a long versioned history from v3→v13), Sessions (`AgentSession`, `AgentSessionSummary`, `AgentSessionList`, `AgentSessionCreateRequest`, `SkillTargetDeclareRequest`, `SkillGraduationResponse`), HITL & executions (`ConfirmationRecordModel`, `ExecutionRecordModel`, `ExecutionRecoveryModel`), Model discovery (`AgentModelInfo`, `AgentModelCatalog`), Runtime metadata (`AgentRuntimeMetadata`, `AgentHealth`), and Operations documents (`DocumentCreateRequest`, `SessionTitleUpdateRequest`).

Dependency direction is one-way: this package exposes pure Pydantic `BaseModel` types consumed by FastAPI route handlers elsewhere in `agent_service`; it imports no application logic. Cross-cutting concerns are expressed via Pydantic features — `model_validator(mode="after")` for cross-field constraints (requester pair parity, document-type field mixing), `model_serializer(mode="wrap")` to reproduce closed-schema byte fidelity (`ExecutionRecoveryModel._dump_closed`), and `ConfigDict(extra="forbid", frozen=True)` on opaque challenge envelopes.

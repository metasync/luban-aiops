- Authorization failures surface as HTTP 404 with detail "session not found" rather than 403, making foreign-session IDs indistinguishable from unknown ones (anti-enumeration posture).
- Bookkeeping writes (title minting, model pinning, touch) are wrapped in try/except that logs a warning and swallows the exception so store failures degrade gracefully without failing the caller's turn.
- Session identity fields (`requester_namespace`, `requester_sub`) are injected through `session_birth_fields(requester, user_id)` at create time and never mutated afterward, keeping requester binding immutable.
- Each backend implements the same `SessionStore` Protocol methods (`create_session`, `get_session`, `list_sessions_by_user`, `delete_session`, `touch_session`, `set_session_title`, `update_session_title`, `set_session_model`, `is_ready`, `server_version`, `__len__`) plus a `backend_name` class attribute.
- SQL queries are defined as module-level string constants prefixed with operation names (`_INSERT_SESSION`, `_GET_SESSION`, `_LIST_USER_SESSIONS`, `_TOUCH_SESSION`, `_SET_SESSION_TITLE`, `_UPDATE_SESSION_TITLE`, `_SET_SESSION_MODEL`, `_DELETE_SESSION`, `_COUNT_SESSIONS`, `_SWEEP_EXPIRED`) and parameterized via dict bindings.
- TTL filtering uses a shared `_NOT_EXPIRED` predicate (`last_accessed_at > now() - make_interval(secs => %(ttl_seconds)s)`) so every read/write path enforces idle expiration uniformly.

Three-layer split inside the module:
- `session_service.py` is the stateless service facade: it owns business rules (owner/requester authorization via `_assert_session_owner` / `_assert_requester`, title minting with redaction, model pinning, list capping) and coordinates cleanup of sibling stores (`AGENT_STATE_STORE`, `EVIDENCE_STORE`, `CONFIRMATION_RECORD_STORE`, `EXECUTION_RECORD_STORE`, `AUTHORING_TRACE_STORE`, `FLOW_CONTEXTS`, `FLOW_APPROVALS`) on session delete.
- `session_store.py` defines a `Protocol`-based `SessionStore` interface and ships three implementations — `InMemorySessionStore`, `RedisSessionStore`, `PostgresSessionStore` — selected at runtime by `build_session_store()` reading `SESSION_STORE_BACKEND` / `SESSION_TTL_SECONDS` / `SESSION_MAX_ENTRIES`. The Protocol deliberately exposes no setter for `session_type` so it remains a birth-only property (SPEC-056 R-1). The factory records metrics via `record_session_store_backend` / `record_session_store_error` / `record_session_store_fallback`.
- `session_transcript.py` is an independent best-effort reader that pulls `AgentState.context` from `AGENT_STATE_STORE`, filters to `user`/`assistant` roles, flattens block content, and applies `prose_redaction.redact_transcript` before returning `(transcript_available, turns)`.

Dependency direction is one-way: service → store protocol + transcript → `agent_state_store`; nothing in the store layer imports the service. Backends are isolated per class; only the factory knows about env vars and metrics.

Three cooperating sub-packages form a thin runtime layer around AgentScope:
- `core/` holds shared infrastructure: `config.py` caches a single `RuntimeSettings` instance via `lru_cache`, `env.py` provides typed env helpers, `observability.py` raises the root logger to INFO so structured audit events survive Uvicorn's default WARNING level, and `metrics.py` / `telemetry.py` / `request_context.py` expose cross-cutting hooks consumed by higher layers.
- `providers/` defines an abstract `AgentScopeProvider` in `base.py` with class-level metadata (`provider_name`, `default_model`, `model_series`, `discover_family_prefixes`, `discover_exclude_markers`) plus shared discovery filtering (SPEC-027 dated-snapshot and non-chat marker filters). Concrete adapters (`openai.py`, `dashscope.py`, `deepseek.py`, `luban.py`) subclass it and implement `build_model(settings)`; they are registered centrally in `registry.py`'s `_PROVIDERS` dict and exposed through `get_provider()` which raises `ProviderConfigurationError` for unknown names.
- `entrypoints/` exposes two independent runners: `native.py` builds an `agentscope.app.create_app` backed by Redis storage/message bus and a local workspace manager, served via uvicorn on configurable host/port; `runtime.py` builds an `AgentApp` with a `@agent_app.query(framework="agentscope")` handler that streams `TEXT_BLOCK_DELTA` / `THINKING_BLOCK_DELTA` / `REPLY_END` events from the kernel into AgentScope's `Msg` content blocks. Both entrypoints depend only on `core.config.get_settings` and `services.runtime_dependencies.get_runtime_kernel`, keeping provider selection out of the entrypoint code.
Dependency direction is one-way: entrypoints → core + services → providers; providers never import entrypoints or services.

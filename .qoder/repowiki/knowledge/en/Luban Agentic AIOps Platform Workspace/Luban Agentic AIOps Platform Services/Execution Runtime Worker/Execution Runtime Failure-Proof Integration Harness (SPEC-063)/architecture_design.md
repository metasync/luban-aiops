The module is a pytest-based failure-proof harness with two layers:

- Test layer (`test_*.py` files): one file per failure scenario family (admission, agent storage, crashes, cutover, minimization, observability, observations, persistence, retention, schema) plus `test_harness_contract.py`, which proves the measuring apparatus itself (barriers, commit proxies, clock reconciliation, negative controls).
- Support layer (`support/`): shared fixtures and infrastructure — `infrastructure.py` owns `DisposablePostgres` and prerequisite checks; `compose.yaml` provisions an owned Postgres container via Docker Compose with `io.luban.spec063.owner` labels for cleanup; `processes.py` + `http_services.py` spawn worker/gateway HTTP processes; `barriers.py` provides cross-process synchronization; `host_clock.py` reconciles host vs database time; `ledger.py` builds signed envelopes; `negative_controls.py` contains deliberately unsafe senders used to assert safety rejections; `scenarios.py` declares the canonical `CASES` matrix of F-xx rows × case variants.

Entry point `run.py` is the only way to invoke the harness; it enforces `--stage` (`campaign`, `harness`, `baseline-red`, `development`), sets `OTEL_*` exporters to `none`, creates a timestamped evidence directory under `.workspaces/spec063-evidence`, and delegates to `pytest.main`. `conftest.py` registers `--proof-stage` / `--proof-evidence` options, rejects direct `pytest` invocation, filters tests by stage and `@scenario(row, case)` markers, validates every selected case exists in `CASES`, and writes a JSON manifest at session end containing selected nodes, per-node results, and metadata. The `services` fixture constructs a token-scoped process tree (gateway → target, optional worker) using `ProcessService`; `evidence` is a bounded fact writer restricted to an allow-list of keys capped at 8 KiB so manifests stay auditable. Dependency direction is strictly inward: tests import from `support.*`; support never imports from tests.

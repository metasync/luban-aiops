Three cooperating services with a one-way dependency chain:

- `executor.py` is the outbound transport layer. `execute_tool` chooses between the public `/api/v2/tools/invoke` route (Bearer human token) and the private `/api/v2/tools/invoke-delegated` route (workload-projected JWT). `_post_invoke` wraps each call in an `httpx.AsyncClient` with `retries=0`, no redirects, and an outer `asyncio.timeout(min(gateway_timeout_seconds, 30))`; any transport error or malformed response is collapsed into `GatewayUncertain(ProtocolError)` so callers cannot distinguish network failure from a successful but inconsistent tool report.
- `single_flight.py` provides an in-process `SingleFlightRegistry` keyed on `execution_id`. It creates one `asyncio.Future` per key, lets concurrent duplicates await it, caches completed outcomes for up to `retention_seconds` / `MAX_COMPLETED_FLIGHTS=4096`, and returns `(outcome, owner)` so audit emission can be single-flighted alongside the call. The registry is process-local because the deployment pins `replicas: 1`; scaling requires a durable flight store first.
- `delegated_execution.py` owns verification of signed handoff envelopes and the runtime-bound `VerifiedDelegatedExecution` context. `verify_handoff` validates the envelope signature, both requester/decider human JWTs against the configured JWKS issuer/audience/actors, and the argument digest; it produces a frozen, process-local object whose `check_send` re-checks liveness and HMAC-equals the decider token plus projection fields before `executor._execute_delegated` forwards through the private route using a freshly read projected workload JWT from `settings.target_execution_token_path`.

Dependency direction: `executor` → `delegated_execution` (lazy import inside `_execute_delegated`), `delegated_execution` → `execution_protocol` + `execution_signing`; `single_flight` has no internal dependencies beyond stdlib. No live target is enabled — all external I/O paths raise explicit `ProtocolError` subclasses rather than leaking raw exceptions.

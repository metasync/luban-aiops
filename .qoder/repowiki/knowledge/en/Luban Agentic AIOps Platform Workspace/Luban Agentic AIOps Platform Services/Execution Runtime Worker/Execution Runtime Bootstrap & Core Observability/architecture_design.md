Two entry points compose the worker: `main.py` is the uvicorn CLI shim that loads `ExecutionRunSettings` (host/port from `EXECUTION_HOST`/`EXECUTION_PORT`, with Kubernetes `tcp://IP:PORT` port coercion) and starts the server with a bounded 35s graceful drain. `app.py` owns the `FastAPI` instance via `create_app()`: it installs a SIGTERM handler that flips `app.state.draining` before calling the previous handler, registers an HTTP middleware that attaches `x-request-id` to `request.state`, includes the API router, then calls `setup_metrics` and `setup_telemetry`. The `core/` package is a flat collection of cross-cutting concerns with no internal sub-packages:
- `config.py` — frozen `ExecutionSettings` dataclass loaded from `EXECUTION_*` env vars, validated in `__post_init__` (store backend enum, timeout range, retention), cached via `lru_cache(maxsize=1)`.
- `runtime.py` — minimal `ExecutionRunSettings` for the uvicorn bootstrap.
- `metrics.py` — module-level `prometheus_client` counters/histograms/gauges plus RED middleware and `/metrics`; gauges are refreshed at most every 5s against the ledger snapshot so scrapes never trigger execution work.
- `telemetry.py` — opt-in OTLP push pipeline gated by `OTEL_ENABLED`, installing FastAPI/HTTPX instrumentation and a log bridge; `MetricsMirror` lazily re-emits each prometheus family as OTel instruments with the same name + bounded labels.
- `observability.py` — root logger setup (`LOG_LEVEL`) and structured JSON `log_event` helper.
- `request_context.py` — correlation key resolver preferring inbound `x-request-id`, then active OTel trace id, then generated UUID.
Dependency direction is one-way: `app.py` depends on all `core/*` modules; `core/*` modules do not depend on app or service layers. The ledger is injected through `app.state.ledger` after lifespan initialization.

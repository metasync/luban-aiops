Layered FastAPI application under `src/incident_service/`:
- Entry point: `main.py` loads `IncidentRunSettings` and boots uvicorn; `app.py` creates the `FastAPI` instance with an async `lifespan` that builds connectors and the incident store, attaches middleware for request logging, and wires metrics/telemetry.
- API layer (`api/`) exposes routes via a single `router.py` aggregator including `health`, `incidents`, and `webhooks` sub-routers.
- Core cross-cutting concerns live in `core/`: frozen `IncidentSettings` dataclass loaded from `INCIDENT_*` env vars (`config.py`), Prometheus metrics (`metrics.py`), OpenTelemetry + OTLP exporter setup (`telemetry.py`), structured logging (`observability.py`), per-request ID propagation (`request_context.py`), and runtime settings (`runtime.py`).
- Domain schemas are Pydantic models in `schemas/incident.py`.
- Business services in `services/` implement the domain logic: `incident_store.py` defines the `IncidentStore` Protocol and two backends (`InMemoryIncidentStore` for dev/test, `PostgresIncidentStore` over psycopg3 with DDL auto-creation); `connectors.py` defines the `Connector` Protocol plus a registry-based factory (`CONNECTOR_REGISTRY`) with the built-in `audit` connector; `triage.py` drives agent calls; `normalization.py` normalizes incoming payloads; `query_auth.py` validates query/workload tokens; `audit_emitter.py` implements the audit connector.
- Dependency direction is strictly inward: routes → services → core/schemas; stores and connectors are selected at startup via factories keyed by settings, keeping the HTTP surface decoupled from persistence and collaboration backends.

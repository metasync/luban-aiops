Layered FastAPI application under `src/identity_service/`:
- Entry: `main.py` loads `IdentityRunSettings` from env and starts uvicorn; `app.py` builds the `FastAPI` instance with a request-id middleware, includes the router, and wires metrics/telemetry.
- API layer (`api/routes/{auth,health,identity}.py`) is mounted through `api/router.py`, which is the single include point for all HTTP endpoints.
- Business logic lives in `services/`: `identity_service.py` implements the Keycloak OIDC flow (PKCE login start, authorization-code exchange, refresh, logout) and normalizes claims into an internal `IdentityContext`; `exchange_service.py` implements SPEC-008 delegation — authenticating callers via static Basic credentials or Kubernetes projected workload tokens, verifying the presented subject token against the broker's own signing key, and minting a delegated token bound to the requested audience; `token_service.py` owns RSA key lifecycle (load/generate/persist at `jwt_private_key_path`, module-level singleton), signs RS256 JWTs with RFC 8693 `act` actor claims, and exposes JWKS; `audit_emitter.py` ships fire-and-forget audit events to a durable audit service on a daemon thread.
- Configuration is centralized in `core/config.py` as frozen dataclasses (`IdentitySettings`, `ServiceClient`, `WorkloadClient`) parsed from environment variables plus a cached `get_settings()` accessor; `core/runtime.py` provides process-level settings (`IDENTITY_SERVICE_HOST`/`PORT`).
- Schemas in `schemas/{auth,identity}.py` are Pydantic models shared between routes and services.
- Dependency direction is strictly API → services → core/config + schemas; services depend only on config and metadata, never on FastAPI. External dependencies are Keycloak OIDC endpoints and an optional audit-service HTTP endpoint.

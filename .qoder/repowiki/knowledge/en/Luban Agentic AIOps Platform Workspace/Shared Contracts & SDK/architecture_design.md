Two sibling sub-packages form a contract-first boundary between all `products/` modules:

- `shared/shared-contracts/` is the canonical source of truth. `schemas/*.schema.json` files declare every cross-service wire format (chat, agent v1/v2, session, stream events, identity token, audit, execution receipts, tools, skills, incidents, policies) using JSON Schema Draft 2020-12 with `$id` URIs. `policies/policy-default.yaml` is the single authoritative action-authorization bundle (v1, `action_authz` domain) defining role→action grants, deny-by-default semantics, and tiered approval outcomes; `policies/policy-scenarios.yaml` records expected outcomes per (role, action) pair. `scripts/` contains Python validators (`validate_policy.py`, `policy_diff.py`, `validate_policy_scenarios.py`, `validate_secret_vocabulary.py`, `validate_version.py`) that enforce schema conformance, version discipline, and scenario expectations — these are the only executable logic in this package.
- `shared/shared-sdk/` is currently a README-only placeholder reserving the namespace for future shared service clients, auth helpers, tracing utilities, and typed event producers/consumers built on top of the contracts above.

Dependency direction is strictly inward: product services depend on these schemas and bundles; nothing in `shared/` depends on any `products/` code. The module exposes no runtime library — consumers consume the JSON/YAML artifacts directly or via generated clients.

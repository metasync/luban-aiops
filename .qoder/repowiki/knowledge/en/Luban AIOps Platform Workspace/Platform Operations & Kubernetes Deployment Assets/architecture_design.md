The module is organized into three top-level areas under `shared/platform-ops/`:
- `gitops/dev-k8s/`: a Kustomize-based development overlay that deploys all platform services (agent-service, audit-service, execution-runtime, identity-service, incident-service, operator-portal/web-ui, platform-gateway, skills-hub, tool-gateway) plus shared infrastructure (PostgreSQL StatefulSet, Redis deployment) into the `dev-luban-aiops` namespace. Each service lives in its own subdirectory with paired `*-deployment.yaml` and `*-service.yaml` manifests plus per-service `runtime-config.env` and `runtime-secrets.env` files; a `base/kustomization.yaml` aggregates them.
- `gitops/runtime-profiles/`: pluggable Kustomize profile layers (e.g. `default`, `mutating-dev`) that patch base deployments via ConfigMaps and pod patches, keeping profile changes reviewable and Git-diffable separate from the base overlay.
- `gitops/*.sh`: shell helpers that orchestrate deployment (`deploy-overlay.sh`), image tag injection, secret synchronization across services (`sync-*-secrets.sh`), OIDC reconciliation, and runtime profile selection/verification.
- `skills/`: reusable skill content consumed by the platform at runtime — `platform-runbooks/guides/` for debugging Kubernetes issues and `sre-alerting/alerts/` defining alert documentation.
- `e2e/`: demo scripts exercising documents, incidents, mutating webhooks, and skills flows against a live cluster.

Dependency direction is one-way: deploy scripts and Kustomize overlays depend on built container images referenced via `IMAGE_TAG` and per-image env vars; they do not import application code. The `deploy-overlay.sh` entry point uses `kubectl kustomize --load-restrictor LoadRestrictionsNone` so the skills-hub can pull sample skill sources from outside the overlay root, then applies manifests and triggers rolling restarts of all deployments when ConfigMaps change.

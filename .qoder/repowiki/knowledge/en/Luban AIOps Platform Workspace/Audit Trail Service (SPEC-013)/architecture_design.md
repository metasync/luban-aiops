The service is a FastAPI application bootstrapped via `main.py` → `app.create_app()` which wires middleware, metrics, telemetry, and a lifespan that constructs the configured `AuditStore` (in-memory for dev/test, PostgreSQL for production) and starts a background `RetentionTask`. The API layer (`api/routes/`) exposes three routers — health, ingest (`POST /api/v1/audit/events`), and query — mounted through `api/router.py`. Ingest routes authenticate callers via `services/ingest_auth` using static client secrets or workload-projected tokens, validate payloads against Pydantic schemas in `schemas/audit.py`, then delegate persistence to the store. Storage uses a strategy pattern: an `AuditStore` Protocol defines `initialize/add/query/count/evict/ready/close`, implemented by `InMemoryAuditStore` and `PostgresAuditStore` selected by `build_audit_store` based on `AUDIT_STORE_BACKEND`. Query pagination uses a base64-encoded cursor of `(occurred_at, event_id)`. Configuration is centralized in `core/config.py` as frozen dataclasses loaded from environment variables with `@lru_cache` singleton access. Cross-cutting concerns (logging, Prometheus metrics, OpenTelemetry tracing, request-id propagation) live under `core/` and are attached at app creation time.

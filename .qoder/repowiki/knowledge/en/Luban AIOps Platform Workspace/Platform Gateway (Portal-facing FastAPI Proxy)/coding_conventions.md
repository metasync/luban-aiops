- Each feature endpoint follows a fixed pipeline: resolve `x-request-id`, call `resolve_request_identity`, invoke `enforce_policy(settings, identity, action, request_id)`, obtain a delegated token via `obtain_delegated_token`, then forward to the corresponding `agent_client` / upstream function.
- Upstream HTTP errors are normalized uniformly: `httpx.HTTPStatusError` with status 4xx is re-raised as a FastAPI `HTTPException` preserving the original code, while any other `httpx.HTTPError` or 5xx maps to 502 with a descriptive detail string.
- Configuration is centralized in the frozen `PlatformGatewaySettings` dataclass with `from_env()` reading all values from `PLATFORM_GATEWAY_*` / `IDENTITY_*` / `AGENT_*` env vars and exposed through an `@lru_cache(maxsize=1)` `get_settings()` dependency injected into routes.
- Every policy decision path emits both a Prometheus metric via `record_policy_decision` and a durable audit event via `emit_audit_event(build_audit_event(...))`, including blocked approval attempts.
- Streaming SSE endpoints (`chat_stream`, `chat_confirm`) parse incoming frames inline (`message_end`, `confirmation_result`, `message_delta`) to emit exactly one audit event per turn after the stream completes or a terminal frame is observed.
- Policy rules in `policies/policy-default.yaml` use a uniform schema with `domain: action_authz`, `roles_any`, `actions_any`, `priority`, `enabled`, and `decision.outcome` of `allow`, `deny`, or `require_approval` carrying an `approval.tier` and `decided_by_roles` block.

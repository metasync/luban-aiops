The repository is a product-oriented monorepo. Each capability lives under `products/<name>/` as an independent FastAPI/uv project with its own `src/<package>/`, `tests/`, `Dockerfile`, `pyproject.toml`, and `.python-version`. Cross-cutting concerns are centralized: `shared/shared-contracts/` holds JSON schemas, policy bundles, and validation scripts consumed by all products; `shared/platform-ops/gitops/` contains kustomize overlays (`dev-k8s`, `runtime-profiles/*`) rendered by the root Makefile; `mk/*.mk` provides shared build fragments for image and Python targets. The root `Makefile` orchestrates coordinated builds (`make build` tags every image with a single semver-derived tag written to `IMAGE_STATE`), verification gates (`make verify` runs per-product tests, kustomize overlay checks, policy scenario validation, version lockstep, and secret vocabulary checks), and deployment via `shared/platform-ops/gitops/dev-k8s/deploy.sh`. Products communicate over explicit wire contracts defined in `shared/shared-contracts/schemas/` (chat v1/v2, session, stream-event, tool-invocation/result, identity-token, policy-decision, etc.) rather than direct imports, keeping dependency direction strictly inward toward `shared/` and outward only through HTTP/gRPC boundaries. Policy enforcement is duplicated but contract-aligned across `platform-gateway` (portal edge) and `tool-gateway` (tool/connector edge), both evaluating the canonical `policy-default.yaml` from `shared/shared-contracts/policies/` which is synced via `make sync-policy`.

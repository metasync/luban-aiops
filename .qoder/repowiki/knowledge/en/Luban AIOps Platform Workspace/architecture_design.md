The root acts as a forge-agnostic orchestration layer that delegates per-product routines to `products/<name>/` while owning cross-cutting concerns: a single `IMAGE_TAG` computed from the root `VERSION` file is propagated to every Python product image so all services ship in lockstep; `mk/defaults.mk`, `mk/image.mk`, and `mk/python.mk` provide shared build fragments consumed by both root and product Makefiles. The root `Makefile` enumerates `PYTHON_PRODUCTS` and `IMAGE_PRODUCTS`, runs `sync/test/lint/build/push` across them, renders GitOps overlays via `kustomize build`, validates the canonical policy bundle (`shared/shared-contracts/policies/policy-default.yaml`) against its JSON schema, enforces version lockstep between VERSION, products, and the portal, and drives coordinated deploy/e2e flows through `shared/platform-ops/gitops/dev-k8s/deploy.sh`. Cross-service contracts live in `shared/shared-contracts_and_sdk/` (JSON Schema, action-authorization policy, SDK) and are referenced by multiple services, while `shared/platform_ops/` holds Kustomize overlays and runtime profiles consumed by the deploy target.

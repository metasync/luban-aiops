Two sibling sub-packages with distinct responsibilities:
- `tools/gateway_tools.py` builds AgentScope `FunctionTool` instances from gateway-discovered tool definitions. Each tool closure reads the per-turn delegated bearer token from the `DELEGATED_TOKEN` `ContextVar`, POSTs to `/api/v2/tools/invoke`, and returns an `agentscope.tool.ToolChunk` whose metadata carries the raw gateway result for evidence emission by `ToolEvidenceMiddleware`. Read-only tools call the gateway directly; mutating tools (`risk_level != 'read'`) first verify arguments against a signed execution envelope stored in `EXECUTION_REQUESTS`/`CURRENT_CALL_ID` contextvars, then hand off to the execution worker via `agent_service.services.execution_worker_client.handoff` instead of calling the gateway inline. Toolkit assembly is done through `build_gateway_toolkit` / `build_function_tools`, which normalize schemas and attach `gateway_tool_name` / `gateway_risk_level` attributes.
- `entrypoints/native.py` defines `NativeServiceSettings` (dataclass loaded from `AGENTSCOPE_*` env vars) and `build_native_service_app`, which wires `RedisStorage`, `RedisMessageBus`, and `LocalWorkspaceManager` into an `agentscope.app.create_app` and exposes a `run()` that starts it with uvicorn on configurable host/port.
- `entrypoints/runtime.py` builds an `AgentScope Runtime` `AgentApp` via `build_agent_app()`, registers a `@query(framework="agentscope")` handler that streams `TEXT_BLOCK_DELTA` / `THINKING_BLOCK_DELTA` events from the runtime kernel into `Msg` objects, handles unconfigured-agent and error paths, and persists session state around each query. A module-level `agent_app` instance is created at import time and exposed through `run()`.
Dependency direction is one-way: both entrypoints depend on `agent_service.core.*`, `agent_service.metadata`, and `agent_service.runtime_kernel`; tools additionally depend on `agent_service.services.execution_*` only when mutating, keeping read-only tool paths free of execution-worker coupling.

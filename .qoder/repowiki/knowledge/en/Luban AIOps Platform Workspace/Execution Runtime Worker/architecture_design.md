The service is a FastAPI application (`app.py`) launched via `main.run()` which boots Uvicorn with host/port from `ExecutionRunSettings`. The app lifecycle initializes two in-process services attached to `app.state`: an `ExecutionRecordStore` (memory or PostgreSQL backend) for signed receipt persistence and a `SingleFlightRegistry` keyed by `execution_id` to deduplicate concurrent handoffs. HTTP routes are split under `api/routes/` (`health`, `handoff`) and mounted through a central `router.py`. Business logic lives in `services/`: `executor.py` performs one-shot tool invocations against the tool-gateway via httpx, mapping transport/timeouts into structured error results; `single_flight.py` provides asyncio-future-based idempotency bounded by retention seconds and a hard cap of completed flights; `execution_signing.py` handles receipt signing; `audit_emitter.py` forwards audit events to an audit service. Configuration is centralized in `core/config.py` as frozen dataclasses loaded from `EXECUTION_*` environment variables with startup validation, while `core/runtime.py` holds process-level settings. Observability is wired via OpenTelemetry (OTLP exporter + FastAPI/httpx instrumentation), Prometheus metrics, and structured logging through `core/observability.py` and `core/request_context.py`.

Each subdirectory under `views/` is a self-contained feature view built as a React component tree using Ant Design primitives. Feature folders mirror domain areas: `control/` holds cross-cutting admin screens (Approvals, Permissions, Settings, Skills, Tools); `incidents/` provides incident triage with list/detail modes; `workspace/DocumentsView.tsx` renders operation documents inside the session workspace; `audit/AuditView.tsx` shows audit logs. Shared formatting helpers live in `format.ts` (e.g. `formatTimestamp`) and are imported across views. Data access is delegated to sibling modules (`../../api/*`, `../../auth/AuthContext`, `../../roles`, `../../stream/transport`, `../../sessions/useSessionWorkspace`), so this module owns only UI state, polling, and rendering — no direct HTTP calls. Complex features extract their data-fetching logic into custom hooks (e.g. `useApprovalsInbox` in `control/ApprovalsView.tsx`) that encapsulate polling, streaming confirmations via `openStream`/`consumeStream`, and optimistic local updates. The `SettingsView` uses an extensible pane registry (`SETTINGS_PANES`) pattern so new read-only panes can be added without modifying the container. Each view is accompanied by colocated `__tests__/` unit tests.

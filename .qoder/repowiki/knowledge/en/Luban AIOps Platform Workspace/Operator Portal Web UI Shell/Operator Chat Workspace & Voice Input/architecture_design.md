Two sibling feature folders compose a single operator workspace surface. `chat/` is centered on `ChatView.tsx`, which owns session lifecycle (via `../sessions/useSessionWorkspace`), model catalog selection (`../api/models`), and the live SSE stream (`../stream/useChatStream`). It composes smaller presentational components — `ComposerSelectionBar`, `ModelSelect`, plus inline `EvidencePanel`, `ConfirmationCardView`, `SessionPanel`, and `CopyIdButton` — and wires them to role-based permissions from `../roles`. Stateful side effects are extracted into hooks: `usePendingDecisionPoll.ts` polls `../api/sessions` on a bounded interval while a confirmation card is pending, using a fingerprint-based change gate and a settle window so it never races the live stream. Data-shape adapters live in pure modules: `transcript.ts` maps server `TranscriptTurn`/`EvidenceTurn`/`ConfirmationRecord` payloads into the in-memory `ChatTurn` model used by both live streaming and replayed history; `markdown.ts` provides a safe, escape-first regex renderer that only allows http(s) links. The `voice/` folder is a small, self-contained layer consumed by `ChatView`: `useSpeechRecognition.ts` wraps the Web Speech API (`window.SpeechRecognition` / `webkitSpeechRecognition`) behind a stable React hook returning `{supported, listening, error, start, stop}`, and `languages.ts` exposes a constant-driven list of supported locales with localStorage persistence and locale fallback resolution. Dependency direction is strictly inward: this module depends on `../api/*`, `../auth`, `../roles`, `../stream`, and `../sessions`, but nothing inside `voice/` depends on `chat/`.

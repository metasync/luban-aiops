Two independent sub-trees under `app/src`:
- `sessions/useSessionWorkspace.ts` exports a single React hook (`useSessionWorkspace`) that encapsulates all session state: a `SessionSummary[]` list refreshed via `listSessions`, a monotonic `refreshSeqRef` to avoid stale-setter races when a manual refresh interrupts the 30s interval poll, per-tab active session persistence in `sessionStorage` under `luban.portal.activeSessionId`, and local-only `pinned` entries created by `pinIncidentSession` for incident deep-links. It composes the `../api/sessions` client (`createSession`, `deleteSession`, `renameSession`, `listSessions`) and maps `ApiError` status codes (409, 404, 400) into typed `DeleteOutcome`/`RenameOutcome` results with anti-enumeration neutral messages.
- `theme/tokens.ts` defines a `palette` object and an Ant Design `ThemeConfig` (`portalTheme`) using `darkAlgorithm`; `theme/global.css` mirrors the same palette as CSS custom properties on `:root` so bespoke components consume one vocabulary while Ant Design consumes the JS theme config. The CSS also ships the app-shell layout classes (`.app-shell`, `.sidebar-*`, `.chat-view`, `.session-panel`, `.view-container`, `.md-content`, `.turn-request-banner`, `.confirm-card`, etc.) used across views.
Dependency direction is one-way: the hook depends on `../api/sessions`; the theme files have no runtime dependencies beyond antd and are consumed at the app root to inject styles and theming.

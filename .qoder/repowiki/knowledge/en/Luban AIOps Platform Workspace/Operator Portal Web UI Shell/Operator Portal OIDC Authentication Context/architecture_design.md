Three-file module split by concern: `AuthContext.tsx` exposes an `AuthProvider` React component and a `useAuth()` hook that owns UI state (`session`, `booting`, `authError`, `username`, `roles`) and orchestrates login/logout; `oidc.ts` implements the OIDC authorization-code-with-PKCE flow against the gateway's `/api/v1/auth/*` endpoints (login, callback, refresh, logout-url, me), including silent token refresh via a `setTimeout`-based timer scheduled from the access token's JWT `exp` claim; `storage.ts` persists `AuthSession` and pending PKCE request data in `window.sessionStorage` under stable keys, with a guarded JSON parser so corrupt storage degrades gracefully. Dependency direction is one-way: `AuthContext` → `oidc` → `storage`, while both depend on the shared `../api/client.requestJson` helper. The gateway owns all PKCE state and token exchange — this module only stores tokens and drives redirects.

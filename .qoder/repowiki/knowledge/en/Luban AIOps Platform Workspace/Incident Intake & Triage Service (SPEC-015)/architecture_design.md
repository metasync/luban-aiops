Layered FastAPI application with a clear separation between HTTP entry points, business services, and persistence. `main.py` boots uvicorn using `IncidentRunSettings.from_env()`, while `app.py` defines the FastAPI lifespan that builds the connector pipeline and incident store from settings and attaches them to `app.state`. The API layer (`api/routes/`) exposes health, webhook intake, and incident query endpoints via a single `router.py` aggregator. Business logic lives in `services/`: `connectors.py` defines a `Connector` Protocol and a registry-based factory (`CONNECTOR_REGISTRY`) so new collaboration sinks (audit, Slack, Jira) can be added without touching callers; `incident_store.py` implements an `IncidentStore` Protocol with two backends — `InMemoryIncidentStore` for dev/test and `PostgresIncidentStore` (psycopg3, per-operation connections, DDL auto-created on startup) selected by `INCIDENT_STORE_BACKEND`; `triage.py` and `normalization.py` handle agent calls and payload shaping; `query_auth.py` validates incoming requests against static or workload-projected tokens. Configuration is centralized in `core/config.py` as frozen dataclasses parsed from `INCIDENT_*` environment variables, with `get_settings()` cached via `lru_cache`. Cross-cutting concerns (logging, OpenTelemetry, Prometheus metrics, request-id propagation) are wired through `core/observability.py`, `telemetry.py`, `metrics.py`, and `request_context.py` as middleware and lifecycle hooks.

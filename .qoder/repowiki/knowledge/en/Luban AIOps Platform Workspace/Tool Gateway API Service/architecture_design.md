The service is a FastAPI application bootstrapped in `app.py:create_app`, which builds an in-process `ToolRegistry` at startup by conditionally importing and registering connector modules (Kubernetes, Elastic, Skills, Incidents) based on `GatewaySettings`. Requests flow through a single HTTP middleware that resolves a request ID and emits structured logs, then hit the central `/tools` route in `api/routes/tools.py`, which delegates to `services.gateway_service.invoke_tool`. That orchestrator performs three stages: identity resolution via local JWT verification (`services/token_verifier`), policy evaluation against a YAML bundle loaded from `policies/policy-default.yaml` via `services/policy_engine`, optional mutating-tool gating (`tools:mutate` action for non-read risk levels), registry dispatch, redaction of sensitive output (`tools/redaction`), audit emission (`services/audit_emitter`), and metrics/telemetry recording. Cross-cutting concerns live under `core/`: `config.py` provides a frozen dataclass settings object cached via `lru_cache`, `metrics.py` exposes Prometheus counters/gauges, `observability.py` wraps logging with correlation IDs, `telemetry.py` wires OpenTelemetry OTLP exporters, and `request_context.py` propagates `x-request-id`. Each connector in `tools/` implements `BaseTool` and registers itself with the registry, keeping the gateway decoupled from downstream systems. The entry point `main.py` runs uvicorn using `GatewayRunSettings.from_env()` for host/port.

The service is a FastAPI application (`src/identity_service/app.py`) bootstrapped by `main.py:run`, which loads runtime host/port via `IdentityRunSettings` from environment variables. The app registers an HTTP middleware that injects request IDs and emits structured log events, then mounts a single `APIRouter` that composes three route modules under `/api/v1/auth/*`, `/api/v1/identity/*`, and `/health`. Business logic is split into domain services in `services/`: `exchange_service` implements the token-delegation flow (SPEC-008/R-2,R-3) supporting both static HTTP Basic client credentials and projected Kubernetes workload tokens (SPEC-009/R-3), `token_service` owns RSA key lifecycle (load/generate/persist to disk or ephemeral in-memory) and signs RS256 JWTs with deterministic `kid`s, `identity_service` handles Keycloak OIDC authorization-code flows, and `audit_emitter` fires non-blocking audit events to a separate audit service over HTTP. Configuration is centralized in `core/config.py` as frozen dataclasses parsed from env vars (`IDENTITY_*`, `KEYCLOAK_*`, `OIDC_*`), exposed through an `lru_cache`d `get_settings()` accessor injected into routes via FastAPI `Depends`. Cross-cutting concerns live in `core/`: `metrics` (Prometheus counters), `telemetry` (OpenTelemetry OTLP exporter + FastAPI/httpx instrumentation), `observability` (structured logging), and `runtime` (host/port). Pydantic models in `schemas/` define all request/response contracts, and tests under `tests/` mirror the service layout.

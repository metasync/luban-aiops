## System Overview

The repository is a monorepo of nine Python microservices plus a React/TypeScript operator portal. Dependency management is **per-product** (no workspace-level `pyproject.toml` or shared lockfile). Each product under `products/<name>/` declares its own dependencies in a `pyproject.toml` using PEP 621, pinned via a per-product `uv.lock`, and the build/test toolchain is driven by `uv`.

## Key Files and Packages

- Per-product dependency manifests: `products/*/pyproject.toml` — each lists runtime `dependencies` and a `[dependency-groups].dev` group for test-only packages (`pytest`, `jsonschema`, `fakeredis`).
- Per-product lockfiles: `products/*/uv.lock` — generated by `uv`; consumed via `uv sync --frozen` to guarantee deterministic installs.
- Shared Makefile fragments:
  - `mk/python.mk` — defines `sync` (`uv sync --frozen`) and `test` targets used by every Python product.
  - `mk/image.mk` — builds container images; base image is `shared/base-images/base-uv/Dockerfile` which pins `UV_VERSION` and `PYTHON_VERSION` as build args.
  - Root `Makefile` — orchestrates `sync`, `test`, `build`, `push` across all products listed in `PYTHON_PRODUCTS` / `IMAGE_PRODUCTS`.
- Node.js frontend: `products/operator-portal/web-ui/app/package.json` + `package-lock.json` (npm) — no `pnpm`/`yarn` lockfile; uses npm defaults.
- Python version pinning: `.python-version` files per product (e.g. `3.12` in `agent-platform`) and `requires-python = ">=3.11"` in each `pyproject.toml`.
- Build backend: `uv_build>=0.8.14,<0.9.0` declared in each product's `[build-system]`.

## Architecture and Conventions

1. **Per-product isolation**: There is no cross-cutting `requirements.txt` or shared `pyproject`. Each service owns its dependency graph independently. This keeps agent-platform, platform-gateway, tool-gateway, etc. decoupled even though they share common libraries (FastAPI, Pydantic, OpenTelemetry, Prometheus).

2. **Deterministic installs via lockfiles**: The shared `mk/python.mk` target runs `uv sync --frozen`, which refuses to resolve against the network and instead uses the committed `uv.lock`. This enforces that CI and local environments install exactly the versions recorded in the lockfile.

3. **Shared base image for reproducible runtime**: All Python products are built from `shared/base-images/base-uv/Dockerfile`, which sets `BASE_UV_UV_VERSION` and `BASE_UV_PYTHON_VERSION` as Docker build args. The root `Makefile`'s `base-images` target builds this image once and passes it to per-product `docker build` calls, so every product image gets the same `uv` and Python interpreter.

4. **Coordinated versioning across services**: The root `VERSION` file is the single source of truth. The `make validate-version` target (via `shared/shared-contracts/scripts/validate_version.py`) checks that the `VERSION` value matches the versions declared in each product's `pyproject.toml` and the portal's code. This is enforced as part of the `verify` gate (`make verify` → `test overlays validate-policy validate-version`).

5. **Common dependency set**: Most Python services declare nearly identical runtime deps (FastAPI, Pydantic, OpenTelemetry exporters/instrumentations, Prometheus client, Uvicorn), with service-specific extras (e.g. `agentscope` only in agent-platform, `elasticsearch`/`kubernetes` only in tool-gateway, `PyJWT`/`cryptography` in gateway services). Dev dependencies are uniform (`pytest`, `jsonschema`, sometimes `fakeredis`).

6. **Node.js frontend**: The operator portal uses standard npm (`package.json` + `package-lock.json`) with `engines.node >= 22`. No custom registry or private package configuration was found in the repo.

## Conventions and Constraints

- **Python dependencies must be declared in `pyproject.toml`** under `[project.dependencies]` (PEP 621); no `requirements.txt` files exist.
- **Lockfiles are committed and immutable at install time**: `uv sync --frozen` is the only supported install path in `mk/python.mk`; any change to `uv.lock` requires an explicit `uv lock` update.
- **Python version is pinned per product** via `.python-version` and constrained via `requires-python = ">=3.11"` in each manifest.
- **Build system is locked**: `[build-system].requires` pins `uv_build` to a tight range (`>=0.8.14,<0.9.0`) across all products.
- **All Python products are built into images tagged with a coordinated semver+sha tag** produced by the root `Makefile`; image tags are written to `shared/platform-ops/gitops/dev-k8s/.images.env` and reused by GitOps overlays.
- **Policy YAML bundles are synchronized centrally**: `make sync-policy` copies `shared/shared-contracts/policies/policy-default.yaml` into `products/tool-gateway/src/tool_gateway/policies/`, `products/platform-gateway/src/platform_gateway/policies/`, and `shared/platform-ops/gitops/dev-k8s/base/shared/policy.yaml` — enforced by the `POLICY_TARGETS` list in the root Makefile.
- **No private Python registry or vendoring** was detected; dependencies resolve from PyPI (and the public `agentscope`/`agentscope-runtime` packages). Private registries would need to be configured outside this repo (e.g. via `uv` config or Docker registry mirrors).
- **Frontend dependencies use npm defaults** — no `.npmrc` or private registry configuration was found in the repository.

## Approach

Luban is a Python monorepo of nine product services plus one Node SPA. Dependency management is split by language:

- **Python** — `uv` (PEP 621 via `pyproject.toml`, lockfile `uv.lock`).
- **Node/TypeScript** — npm (`package.json` under `products/operator-portal/web-ui/app/package.json`; no lockfile committed).

There is no Go, Rust, or other ecosystem manifest in this repo.

## Key files

- `mk/python.mk` — shared `sync` / `test` targets that invoke `uv sync --frozen` and `uv run pytest`.
- `mk/defaults.mk` — pins `BASE_UV_UV_VERSION = 0.12.1` and `BASE_UV_PYTHON_VERSION = 3.12` used to build the shared base image.
- `shared/base-images/base-uv/Dockerfile` — consumes those defaults to bake a reproducible `luban-aiops/base-uv` image.
- `products/<product>/pyproject.toml` — per-product dependency declarations (PEP 621 `[project]` + `[dependency-groups.dev]`).
- `products/<product>/uv.lock` — per-product lockfile generated by `uv lock`.
- `products/<product>/.python-version` — pins `3.12` alongside each product.
- `products/operator-portal/web-ui/app/package.json` — Node dependencies for the operator portal SPA.
- `Makefile` — root orchestrator: `make sync` iterates `PYTHON_PRODUCTS` and delegates to each product's `make sync`.
- `docs/agentic-aiops-platform/release-notes/2026-08-28-dependency-hygiene.md` — documents the adopted refresh posture.

## Architecture and conventions

1. **One lockfile per product.** Each Python product ships its own `pyproject.toml` and `uv.lock`. There is no workspace-level `pyproject.toml` aggregating them; the root `Makefile` enumerates the eight Python products explicitly (`PYTHON_PRODUCTS := agent-platform audit-service execution-runtime identity-broker incident-service platform-gateway skills-hub tool-gateway`) and calls `make -C products/$p sync` for each.

2. **Frozen installs in CI and local dev.** `mk/python.mk` runs `uv sync --frozen`, which requires an exact match against `uv.lock` and refuses to resolve or write new entries. This makes the lockfile the single source of truth for installed versions.

3. **Reproducible base image.** The shared Docker image `shared/base-images/base-uv` is built from `mk/defaults.mk` with `BASE_UV_UV_VERSION=0.12.1` and `BASE_UV_PYTHON_VERSION=3.12`. The root `make base-images` target rebuilds it before `make build`, ensuring every product container layers on the same uv/Python runtime.

4. **Version ranges in `pyproject.toml`, exact pins in `uv.lock`.** Dependencies use bounded ranges (e.g. `fastapi>=0.115,<1.0`, `pydantic>=2.8,<3.0`, `agentscope>=2.0.4,<3.0`, `opentelemetry-sdk>=1.25,<2.0`). The release notes document that re-locking happens inside these ranges at "latest stable".

5. **Shared base packages across products.** All backend services pin the same FastAPI, Pydantic, OTel instrumentation, and Prometheus-client ranges, keeping transitive surfaces aligned.

6. **Node SPA uses npm without a committed lockfile.** `package.json` declares `engines.node >=22.22.2` and uses caret ranges (`^6.6.2` for antd, `^19.2.8` for react). The SPA is not part of the Python `PYTHON_PRODUCTS` list and is exercised separately through `make portal-test`.

7. **No vendoring.** No `vendor/` tree, no `requirements.txt`, no `go.mod`. Third-party code comes exclusively from PyPI/npm resolved against the lockfile.

8. **No private registry configured in manifests.** There is no `PYPI_MIRROR_URL`, `--index-url`, `PYPI_TOKEN`, or `uv.toml` in the repo. The `REGISTRY` variable in `mk/defaults.mk` only controls where *built images* are pushed, not where Python packages are fetched from.

## Conventions and constraints

- **Rule:** Python dependency resolution must be frozen. Enforced by `mk/python.mk` calling `uv sync --frozen`; any drift between `pyproject.toml` and `uv.lock` fails the build.
- **Rule:** The base uv/Python version is pinned centrally in `mk/defaults.mk` (`BASE_UV_UV_VERSION = 0.12.1`, `BASE_UV_PYTHON_VERSION = 3.12`) and consumed by `shared/base-images/base-uv/Dockerfile`; changing it requires rebuilding `base-images` first.
- **Rule:** Every Python product declares `requires-python = ">=3.11"` in its `pyproject.toml` and `.python-version = 3.12`, keeping the declared floor and the locked runtime in sync.
- **Convention:** Backend dependencies use bounded major-minor ranges (e.g. `<1.0`, `<2.0`, `<3.0`, `<4.0`, `<7.0`); the release notes explain that Redis and Elasticsearch caps stay parked because their deployed servers are 7.2 and there is no ES server in dev.
- **Convention:** OpenTelemetry instrumentation packages are kept at their locked SDK pairing on the permanent `0.xb` channel rather than chased as "latest stable" — documented as the sole recorded exception in `2026-08-28-dependency-hygiene.md`.
- **Convention:** Refreshes follow a "latest stable only" policy — no alpha/beta/RC/dev builds — applied through the recorded adopt set in the dependency hygiene release note.
- **Convention:** The operator portal SPA is treated as a separate concern: it has its own `package.json`, its own `vitest` suite, and is invoked via `make portal-test` rather than the Python `sync`/`test` loop.

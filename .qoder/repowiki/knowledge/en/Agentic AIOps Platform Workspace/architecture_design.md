The repository is organized as a product-oriented monorepo. `products/` contains independently deployable Python services (agent-platform, identity-broker, platform-gateway, tool-gateway, audit-service, incident-service, execution-runtime, skills-hub) plus the operator-portal web UI; each product ships its own `src/<package>/`, `tests/`, `Dockerfile`, `Makefile`, `pyproject.toml`, and `uv.lock`. `shared/` holds cross-cutting artifacts: `shared-contracts` (JSON schemas for agent chat, sessions, audit events, policies, skills, incidents), `shared-sdk` (client libraries), and `platform-ops` (Kubernetes overlays under `gitops/dev-k8s`, runtime profiles, and sync scripts). The root `Makefile` is the single entry point that delegates per-product routines via `make -C products/<name>`, aggregates tests/lint/build across all products, renders Kustomize overlays, validates policy and version lockstep, and drives coordinated image tagging and `kind` loading. Dependency direction is strictly outward from `products` into `shared/shared-contracts`; no product depends on another product's source code — inter-service communication goes through the HTTP APIs defined in those JSON schemas, with the platform-gateway acting as the portal-facing edge that verifies tokens, enforces policy, proxies chat/session requests, and delegates token issuance via identity-broker.

The repository is organized as a product-oriented monorepo under `products/`, where each directory is a self-contained service with its own `src/<package>/`, `tests/`, `Dockerfile`, `Makefile`, `pyproject.toml`, and `uv.lock`. Cross-cutting concerns live in `shared/`: `shared-contracts` defines JSON schemas and policy YAMLs consumed by every service; `platform-ops` holds Kustomize overlays (`dev-k8s`, runtime profiles) and sync scripts; `base-images/base-uv` provides the shared uv-based Python image. The root `Makefile` orchestrates cross-product workflows: it iterates over `PYTHON_PRODUCTS` and `IMAGE_PRODUCTS` lists to run tests, lint Dockerfiles, build images with a coordinated semver tag derived from the root `VERSION` file, render all Kustomize overlays, validate the canonical policy bundle against its schema, and enforce version lockstep across products. Services communicate via HTTP/gRPC boundaries defined in `shared/shared-contracts/schemas/*`; there is no shared Python package between products — coupling is intentionally API-level. The top-level entry points are the per-service `main.py`/`app.py` files that bootstrap FastAPI-like apps, while `mk/*.mk` supplies shared Make fragments for image building and Python tooling.

The repository is organized as a product-oriented monorepo under `products/`, where each directory is an independently buildable, containerized service with its own `src/<package>/`, `tests/`, `Dockerfile`, `Makefile`, and `pyproject.toml` managed via `uv`. Cross-cutting concerns live in `shared/`: `shared/shared-contracts` defines JSON schemas and policy YAMLs consumed by every service; `shared/platform-ops/gitops/dev-k8s` holds Kustomize overlays that assemble all services into a deployable cluster; `shared/base-images/base-uv` provides a common uv-based Python image. The root `Makefile` is the single entry point: it declares lists of `PYTHON_PRODUCTS` and `IMAGE_PRODUCTS`, delegates per-product `sync/test/lint/build/push` targets, renders all Kustomize overlays, synchronizes a canonical `policy-default.yaml` into each consumer, validates version lockstep against `VERSION`, and drives coordinated `build`/`deploy`/`e2e` flows. Services communicate over HTTP/gRPC using the shared JSON schemas in `shared/shared-contracts/schemas/`; the `platform-gateway` acts as the portal-facing edge that verifies tokens, enforces policies, proxies chat/session requests to `agent-platform`, and delegates tool calls to `tool-gateway`, while `identity-broker` issues federated tokens, `audit-service` persists events, `incident-service` ingests and triages incidents, and `skills-hub` serves ranked Markdown skill lookups. Documentation follows spec-driven development: `docs/specs/SPEC-NNN-*` define plan/spec/tasks per release slice, `docs/adr/` records architectural decisions, and `docs/agentic-aiops-platform/release-notes/` tracks delivered releases.

The repository is organized as a product-oriented monorepo under `products/`, where each directory is an independently buildable service with its own `pyproject.toml`, `Dockerfile`, `Makefile`, `src/<package>/`, and `tests/`. Cross-cutting concerns live in `shared/`: `shared/shared-contracts` holds JSON schemas and YAML policy definitions that all products consume; `shared/shared-sdk` provides client libraries; `shared/platform-ops` contains Kubernetes GitOps overlays (kustomize) and deployment scripts under `gitops/dev-k8s` and `runtime-profiles/`. The root `Makefile` orchestrates coordinated builds, pushes, and deployments by iterating over `PYTHON_PRODUCTS` and `IMAGE_PRODUCTS`, generating a single `IMAGE_TAG` from `VERSION`, writing `.images.env`, and rendering kustomize overlays. Services communicate via HTTP/gRPC boundaries defined by the shared JSON schemas — there is no shared Python package coupling between products. Two placeholder products (`policy-center`, `execution-runtime`) exist as README stubs awaiting implementation. Documentation follows spec-driven development: `docs/specs/SPEC-NNN-*` directories (plan/spec/tasks), `docs/adr/` for architectural decisions, and `docs/agentic-aiops-platform/release-notes/` tracking releases.

The repository is organized as a product-oriented monorepo under `products/`, where each directory is an independently buildable Python service (agent-platform, identity-broker, platform-gateway, tool-gateway, audit-service, incident-service, execution-runtime, skills-hub, operator-portal) plus a placeholder policy-center. Cross-cutting concerns live in `shared/`: `shared-contracts` defines JSON schemas and policy YAMLs that all products consume; `shared-sdk` holds client libraries; `shared/platform-ops` contains Kubernetes overlays (`gitops/dev-k8s`, `runtime-profiles/*`) and GitOps sync scripts. The root `Makefile` is the single entry point: it enumerates `PYTHON_PRODUCTS` and `IMAGE_PRODUCTS`, delegates per-product `sync/test/lint/build/push` via `make -C products/<name>`, renders Kustomize overlays, validates the canonical policy bundle against its schema, enforces version lockstep with `VERSION`, and drives coordinated `deploy` and `e2e` runs. Each product follows a consistent internal layout (`src/<pkg>/api`, `services`, `core`, `schemas`, plus `app.py`/`main.py`/`metadata.py`), enabling uniform CI and containerization. Dependency direction flows inward: operators and external clients hit `platform-gateway` → `tool-gateway`/`agent-platform`/`incident-service`/`skills-hub`, while `identity-broker` provides tokens and `audit-service` ingests events from all producers; nothing in `shared/` depends on any product.

The repository is a product-oriented monorepo: each capability lives in `products/<name>/` as an independently buildable Python service with its own `pyproject.toml`, `Dockerfile`, `Makefile`, `src/<pkg>/`, and `tests/`. The root `Makefile` aggregates per-product routines via `PYTHON_PRODUCTS` / `IMAGE_PRODUCTS` lists and drives coordinated builds that tag all images with a single `IMAGE_TAG` derived from `VERSION`, writing `.images.env` consumed by the GitOps deploy pipeline. Services follow a uniform internal layout (`api/routes`, `core/{config,metrics,observability,request_context,telemetry}`, `schemas`, `services`, `app.py` + `main.py` entrypoints), enabling cross-cutting concerns (auth, policy, audit emission, observability) to be wired consistently. Cross-service contracts are centralized in `shared/shared-contracts/schemas/*.schema.json` and `policies/policy-default.yaml`; the canonical policy bundle is copied into each consumer via `make sync-policy`. Deployment uses Kustomize overlays under `shared/platform-ops/gitops/` (dev-k8s base plus runtime profiles for dashscope/deepseek/openai/mutating-dev) orchestrated by `deploy.sh` and secret-sync scripts. Documentation is split into `docs/specs/SPEC-NNN-*` (plan/spec/tasks triplets driving release slices), `docs/adr/` (architecture decision records), `docs/guides/` (operator/user guides), and `docs/agentic-aiops-platform/release-notes/`. Two products (`execution-runtime`, `policy-center`) currently exist as README placeholders, indicating future expansion points.

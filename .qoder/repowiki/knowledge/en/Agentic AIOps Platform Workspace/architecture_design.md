The repository is a flat monorepo organized around product boundaries under `products/`, each product being an independently buildable, Dockerized service with its own `src/<package>/`, `tests/`, `Dockerfile`, `Makefile`, `pyproject.toml`, and `uv.lock`. The core products are: `agent-platform` (agent runtime, session store, model providers, streaming chat), `platform-gateway` (portal-facing edge enforcing token verification, policy decisions, chat/session proxying, and token delegation), `tool-gateway` (normalized tool/connector access with MCP and external system integration), `identity-broker` (SSO, identity federation, group normalization, broker-mediated token delegation), `audit-service` (durable audit event ingest, retention-bounded storage, permission-scoped query API), `incident-service` (Alertmanager webhook intake, canonical incident model, agent-driven triage, connector dispatch), `skills-hub` (Git-based Markdown skill ingestion, validation, indexing, ranked retrieval), and `operator-portal` (React/Vite web UI behind nginx). Cross-cutting concerns live in `shared/shared-contracts` (JSON schemas and policy YAML consumed by all services), `shared/shared-sdk`, and `shared/platform-ops/gitops` (Kustomize overlays per environment/runtime profile). The root `Makefile` aggregates per-product routines from `mk/defaults.mk`, `mk/image.mk`, `mk/python.mk`, coordinates a single coordinated image tag written to `.images.env`, enforces version lockstep against `VERSION`, validates the canonical policy bundle, renders Kustomize overlays, and drives `make verify` as the pre-commit/pre-push gate. Dependency direction is strictly product-to-shared-contracts; products do not import each other directly but communicate via HTTP APIs defined by the shared schemas.

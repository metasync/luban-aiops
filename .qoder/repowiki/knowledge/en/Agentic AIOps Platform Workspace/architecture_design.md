The repository is organized as a product-oriented monorepo under `products/`, where each directory is an independently buildable service or application (agent-platform, identity-broker, platform-gateway, tool-gateway, audit-service, execution-runtime, incident-service, skills-hub, operator-portal). Each product follows a uniform layout with `src/<package>/api`, `core`, `services`, `schemas` (and sometimes `tools`/`policies`), plus its own `Dockerfile`, `Makefile`, `pyproject.toml`, and `tests/`. Cross-cutting concerns live in `shared/`: `shared-contracts` defines JSON schemas and policy YAMLs that all products consume; `shared-sdk` holds client libraries; `platform-ops/gitops` contains Kustomize overlays and secret-sync scripts used by `make deploy`. The root `Makefile` is the single entry point that orchestrates per-product `sync`, `test`, `build`, `push`, overlay rendering via `kustomize`, policy validation against `shared/shared-contracts/policies/policy-default.yaml`, version lockstep checks against `VERSION`, and coordinated deployment to a dev cluster. Documentation is split into `adr/` (architecture decision records), `specs/` (spec-driven development artifacts with plan/spec/tasks triads), `agentic-aiops-platform/` (design docs and release notes), `guides/`, and `workspace/` (spikes and studies). Dependency direction is strictly product-to-shared: products depend on `shared/shared-contracts` schemas and policies but never on each other directly — inter-service communication goes through HTTP APIs defined by those shared contracts, with the platform-gateway acting as the portal-facing edge and the identity-broker mediating token delegation.

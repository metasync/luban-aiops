The repository is a product-oriented monorepo under `products/` where each service (agent-platform, identity-broker, platform-gateway, tool-gateway, audit-service, skills-hub, incident-service, operator-portal) is an independently buildable, containerized project with its own `pyproject.toml`, `Dockerfile`, `Makefile`, and `tests/`. Cross-cutting concerns live in `shared/`: `shared/shared-contracts` defines JSON schemas and YAML policy bundles that all services consume; `shared/platform-ops` holds Kustomize GitOps overlays (`dev-k8s`, `runtime-profiles/*`) and deployment scripts; `shared/base-images/base-uv` provides the shared uv-based Python base image. The root `Makefile` orchestrates coordinated builds, pushes, and deploys by iterating over `PYTHON_PRODUCTS` and `IMAGE_PRODUCTS`, writing a single `IMAGE_TAG` into `shared/platform-ops/gitops/dev-k8s/.images.env` consumed by the overlay. Policy files are synchronized from `shared/shared-contracts/policies/policy-default.yaml` to each consumer via `make sync-policy`. The `docs/specs/` directory drives spec-driven development with per-SPEC plan/spec/tasks triplets, and `docs/adr/` records architectural decisions. Dependency direction is outward-only: products depend on `shared/shared-contracts` for schema/policy contracts but never on each other directly — inter-service communication goes through HTTP APIs (e.g., platform-gateway proxies to agent-platform, tool-gateway, identity-broker, incident-service, skills-hub).

The repository is a product-oriented monorepo under `products/`, where each directory is an independently buildable Python service (FastAPI) plus its Dockerfile, tests, and `pyproject.toml` managed by `uv`. Cross-cutting concerns live in `shared/`: `shared/shared-contracts` defines JSON schemas for chat/session/stream, identity tokens, policy decisions, tool invocations, and audit events that all products consume; `shared/platform-ops` holds Kustomize GitOps overlays (`dev-k8s`, `runtime-profiles/*`) and deployment scripts; `shared/base-images` provides the `base-uv` image used by every product. The top-level `Makefile` orchestrates coordinated builds, pushes, and deployments across all products, computes a single `IMAGE_TAG` from `VERSION`, writes `.images.env`, and runs `kustomize build` checks on all overlays as part of `make verify`. Service boundaries are explicit: `platform-gateway` is the portal-facing edge handling token verification, action policy, and proxying to `agent-platform`; `tool-gateway` exposes normalized tools/connectors (Kubernetes, Elastic, Skills, Incidents) with a pluggable connector registry built at startup; `execution-runtime` runs isolated bounded actions; `audit-service` ingests and retains durable audit events; `incident-service` normalizes alerts and dispatches triage outcomes; `identity-broker` issues JWTs verified via JWKS; `skills-hub` indexes Markdown skill sources; `operator-portal` serves the web UI via nginx. Each service follows a uniform layout (`app.py` → `api/router.py` → `services/`, `core/config`, `core/metrics`, `core/telemetry`, `schemas/`, `metadata.py`) so they can be swapped or evolved without changing consumers.

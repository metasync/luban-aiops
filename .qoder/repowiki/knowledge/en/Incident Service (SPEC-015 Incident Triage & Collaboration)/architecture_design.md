The service is organized as a standard FastAPI product under `products/incident-service` mirroring the workspace's shared layout (`api/`, `core/`, `schemas/`, `services/`). `main.py` boots uvicorn via an `IncidentRunSettings.from_env()` entrypoint; `app.py` defines the lifespan that builds the configured `IncidentStore` (in-memory for dev/test, PostgreSQL for production) and connector pipeline from `INCIDENT_STORE_BACKEND` / `INCIDENT_CONNECTORS`. Routes are split by concern: `webhooks.py` exposes `/api/v1/webhooks/alertmanager` (Alertmanager intake with HMAC token auth, fingerprint-based dedupe, idempotent resolution), `incidents.py` exposes CRUD plus `/triage` (manual intake, query, and operator-triggered triage), and `health.py` provides readiness. The `services/` layer isolates domain logic: `normalization.py` maps Alertmanager payloads into a canonical `IncidentInput`; `triage.py` orchestrates a single agent turn on agent-platform `/api/v2/chat` using a dedicated `incident-<id>` session, prefers kernel-validated `structured_output` and falls back to parsing a fenced `` ```triage-report ``` `` block, then validates via Pydantic `TriageReport`; `connectors.py` defines a `Connector` Protocol and a registry (`CONNECTOR_REGISTRY`) so new collaboration sinks (Slack, Jira, …) plug in without changing triage flow — dispatch failures are caught per-connector and recorded rather than aborting triage; `incident_store.py` defines an `IncidentStore` Protocol implemented by `InMemoryIncidentStore` and `PostgresIncidentStore` (DDL self-upgrades tables on initialize); `query_auth.py` authenticates callers via static Basic credentials or projected Kubernetes workload tokens validated against the cluster OIDC issuer JWKS. Cross-cutting concerns live in `core/`: frozen `IncidentSettings` parsed from `INCIDENT_*` env vars, Prometheus metrics, OpenTelemetry telemetry, request-scoped logging context, and a shared `metadata.py` for service identity.

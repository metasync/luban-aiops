Routes are organized as a FastAPI `APIRouter` tree: `router.py` mounts sub-routers in declaration order (`health`, then `status`, then `skills`) because FastAPI matches routes top-to-bottom and `/api/v1/skills/{skill_id:path}` is a catch-all that must come after the more specific `/skills/search` path. Each route module defines its own `APIRouter` (with optional prefix like `/api/v1`) and exposes it for mounting. Cross-cutting dependencies — `SkillStore`, `SyncManager`, `SkillsSettings`, and auth via `authenticate_caller` — are injected through `Depends(get_settings)` and `request.app.state` accessors (`_store`, `_sync_manager`). Health/readiness endpoints are intentionally auth-exempt; all skill retrieval endpoints enforce query credential authentication before accessing the store. Error responses are normalized via a local `_error` helper returning structured JSON with `code`/`message` fields.

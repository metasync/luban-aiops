## System overview

The Luban AIOps platform manages Python dependencies through a **per-product `pyproject.toml` + `uv.lock`** model backed by [uv](https://github.com/astral-sh/uv) as the package manager and resolver. There is no monorepo-level `requirements.txt`, `Pipfile`, or shared `uv.lock`; each product under `products/<name>/` declares its own runtime and dev dependencies, and each ships a frozen lockfile that pins every transitive to exact versions (including hashes). The root Makefile orchestrates dependency refresh across all products via `make sync`, which iterates `PYTHON_PRODUCTS` and runs `make -C products/$p sync`.

## Key files and packages

- Per-product manifests: `products/*/pyproject.toml` — declare `[project]` dependencies with upper-version caps (e.g. `fastapi>=0.115,<1.0`, `pydantic>=2.8,<3.0`, `cryptography>=43.0,<51.0`) and `[dependency-groups].dev` for test-only deps (`pytest`, `jsonschema`, `fakeredis`).
- Per-product lockfiles: `products/*/uv.lock` — generated by uv; records exact resolved versions, sources (`registry = https://pypi.org/simple`), sdist/wheel URLs and sha256 hashes. All backends resolve from the public PyPI index; no private registry or `extra-index-url` is configured anywhere in the repo.
- Shared build fragments: `mk/python.mk` defines the canonical `sync` target (`uv sync --frozen`) and `test` target that re-syncs then runs pytest with OTel exporters disabled so tracing tests stay quiet but functional.
- Base image: `shared/base-images/base-uv/Dockerfile` installs a pinned `uv` (default `0.12.1` via ARG) into Amazon Linux 2023 minimal, sets `UV_PYTHON=3.12`, `UV_LINK_MODE=copy`, `UV_NO_SYNC=1`, and runs as non-root user `app`. Product Dockerfiles copy only `.python-version`, `pyproject.toml`, `uv.lock`, `README.md`, and `src/`, then run `uv sync --frozen --no-dev` at build time.
- Version lockstep enforcement: `shared/shared-contracts/scripts/validate_version.py` reads the root `VERSION` file and asserts it matches every `products/*/pyproject.toml` `[project].version`, every `products/*/src/*/metadata.py` `SERVICE_VERSION`, any `__version__` in package roots, and verifies the operator portal's Vite config still reads the root `VERSION` at build time. Invoked via `make validate-version`.
- Root orchestration: `Makefile` lists `PYTHON_PRODUCTS := agent-platform audit-service execution-runtime identity-broker incident-service platform-gateway skills-hub tool-gateway` and `IMAGE_PRODUCTS` (adds `operator-portal`); `make verify` chains `test overlays validate-policy validate-policy-scenarios validate-version`.

## Architecture and conventions

1. **Per-product isolation**: Each microservice owns its dependency graph independently. There are no cross-product Python package references; inter-service communication goes over HTTP/gRPC contracts defined in `shared/shared-contracts/schemas/`.
2. **Frozen resolution everywhere**: Both development (`uv sync --frozen`) and production builds (`uv sync --frozen --no-dev`) use the `--frozen` flag, meaning the lockfile is authoritative — no on-the-fly resolution against PyPI. This guarantees bit-for-bit reproducible images.
3. **Upper-version caps**: Runtime dependencies consistently cap major versions (e.g. `<1.0` for FastAPI, `<9.0` for Elasticsearch, `<7.0` for Redis, `<3.0` for PyJWT, `<51.0` for cryptography) while allowing minor/patch drift within the range. Dev dependencies follow the same pattern.
4. **Shared base image strategy**: All backend images derive from `luban-aiops/base-uv:al2023`, built once with a pinned uv and Python version. Product images do not install system Python; uv resolves interpreters from each product's `.python-version`.
5. **No vendoring**: Dependencies are fetched from PyPI at build time; there is no `vendor/` directory or local wheel cache committed to the repo.
6. **Single source of truth for platform version**: The root `VERSION` file drives coordinated releases; `make validate-version` enforces that every product's declared version stays in lockstep.

## Conventions and constraints

- **Dependency policy (descriptive)**: The release notes for SPEC-042 state an adoption posture of "latest stable only" — no alpha, beta, RC, or dev builds — with one recorded exception: OpenTelemetry instrumentation packages remain on their permanent `0.xb` channel paired with their SDK version. This is documented in `docs/agentic-aiops-platform/release-notes/2026-08-28-dependency-hygiene.md`.
- **Lockfile immutability in CI**: `uv sync --frozen` is used in both `mk/python.mk` and product Dockerfiles, enforcing that the committed `uv.lock` must be exactly what is installed.
- **Version lockstep rule**: `make validate-version` exits non-zero if any `products/*/pyproject.toml` version, `metadata.py` `SERVICE_VERSION`, or `__version__` diverges from the root `VERSION`. This is enforced by the script in `shared/shared-contracts/scripts/validate_version.py` and invoked from the root `verify` target.
- **Python version pinning**: Every product uses `.python-version` plus `requires-python = ">=3.11"` in `pyproject.toml`; the base image defaults to Python 3.12 via `UV_PYTHON=3.12`.
- **Build backend pinning**: All products declare `[build-system].requires = ["uv_build>=0.8.14,<0.9.0"]` with `build-backend = "uv_build"`, pinning the build toolchain itself.
- **No private registries**: No `uv.toml`, `PYPI_URL`, `UV_DEFAULT_INDEX`, `index-url`, or `extra-index-url` configuration was found; all packages resolve from `https://pypi.org/simple`.

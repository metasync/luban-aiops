The service is organized as a layered FastAPI application under `src/agent_service/`. The HTTP boundary (`api/v2/routes.py`) exposes `/api/v2/chat`, `/api/v2/chat/stream`, `/api/v2/sessions`, `/api/v2/runtime`, and `/api/v2/health`, normalizing headers (`X-User-ID`, `Authorization: Bearer` delegated token) into typed Pydantic schemas and delegating to services. `services/runtime_service.py` provides legacy v1-style helpers, while `services/session_service.py` + `session_store.py` manage Redis-backed sessions keyed by user. The core runtime lives in `runtime_kernel.py` as `AgentKernel`, which lazily builds an AgentScope `Agent` per session, caches it in an LRU `OrderedDict`, and owns two caches: a per-delegated-token `Toolkit` (so credentials never cross users) and a per-token tool-definition list reused for per-request toolkit rebuilds. Tool discovery and invocation are isolated in `tools/gateway_tools.py`, which calls the tool-gateway's `/api/v2/tools` and `/api/v2/tools/invoke` endpoints; each discovered tool becomes an async closure bound to the owning user's bearer token and posted to a per-request `asyncio.Queue` of `tool_call` / `tool_result` trace events consumed by `stream_events` to render the evidence panel. Provider backends (OpenAI, DashScope, DeepSeek) are pluggable via `providers/base.py` + `registry.py`, selected from `RuntimeSettings`. The app entrypoint `app.py` wires logging, metrics, telemetry, and the v2 router; `entrypoints/native.py` and `runtime.py` provide Docker/uvicorn startup. Dependency direction is strictly inward: routes → services → kernel → providers/tools; no framework types leak across boundaries.

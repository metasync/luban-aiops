The module is a documentation-only spec index organized as one directory per specification (`SPEC-NNN-<slug>/`) containing three standardized files: `spec.md` (requirements with acceptance criteria), `plan.md` (technical approach and sequencing), and `tasks.md` (execution checklist). A shared `templates/` directory provides starter content for new specs. The `README.md` defines the full lifecycle — draft → approved → in-progress → delivered → superseded — and enforces conventions such as sequential numbering, stable requirement IDs (`R-1`, `R-2`, …) referenced from tasks, and explicit status headers. Specs are cross-referenced to architecture records in `docs/adr/` and to living state docs under `products/` and `shared/shared-contracts`; delivery requires updating those living-state documents so code and specs stay synchronized. Enforcement is by review discipline plus the root `make verify` gate that runs tests and renders GitOps overlays.

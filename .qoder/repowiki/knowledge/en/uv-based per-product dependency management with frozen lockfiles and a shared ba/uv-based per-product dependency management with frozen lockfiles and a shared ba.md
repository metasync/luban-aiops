## Approach

Luban uses **uv** (Astral) as the sole Python package manager across all nine backend products. Each product is an independent PEP 621 project declared in `products/<name>/pyproject.toml`, with its own `uv.lock` lockfile. There are no monorepo-level dependency manifests, no `requirements.txt`, no Poetry, no Pipenv, and no vendored third-party source trees.

The root Makefile orchestrates cross-cutting operations (`make sync`, `make test`, `make build`) but delegates dependency resolution to each product's own `Makefile`, which includes the shared fragment `mk/python.mk`. The shared fragment defines:

```make
sync: ## Install/refresh this product's dependencies (frozen lock)
	uv sync --frozen
test:
	uv sync --frozen
	OTEL_TRACES_EXPORTER=none OTEL_METRICS_EXPORTER=none OTEL_LOGS_EXPORTER=none \
		uv run pytest
```

The `--frozen` flag is the key invariant: dependency resolution never reaches out to PyPI at build or test time — it must match the committed `uv.lock` exactly. This makes every product's dependency tree reproducible from source alone.

## Key files

- `mk/python.mk` — shared `sync` / `test` targets that enforce `uv sync --frozen` for every Python product.
- `mk/image.mk` — shared Docker build/push/lint targets used by every product.
- `mk/defaults.mk` — single source of truth for overridable defaults; pins `BASE_UV_UV_VERSION=0.12.1` and `BASE_UV_PYTHON_VERSION=3.12`.
- `shared/base-images/base-uv/Dockerfile` — builds the `luban-aiops/base-uv:al2023` image with a pinned uv binary installed into `/usr/local/bin`; no system Python is present.
- `products/*/Dockerfile` — each service copies `.python-version`, `pyproject.toml`, `uv.lock`, and `src/`, then runs `uv sync --frozen --no-dev`.
- `products/*/pyproject.toml` — declares runtime dependencies under `[project.dependencies]` and dev-only dependencies under `[dependency-groups].dev` (pytest, fakeredis, jsonschema).
- `products/*/uv.lock` — per-product lockfile generated by uv.
- Root `Makefile` — lists `PYTHON_PRODUCTS := agent-platform audit-service execution-runtime identity-broker incident-service platform-gateway skills-hub tool-gateway` and iterates them for `sync`, `test`, `lint`, `build`, `push`.

## Architecture and conventions

1. **Per-product isolation.** Each of the eight backend services plus the operator portal has its own `pyproject.toml` + `uv.lock`. Dependencies are not hoisted to a workspace root; there is no `pyproject.toml` at the repo root declaring dependencies.

2. **Version pinning style.** Runtime dependencies use broad upper bounds (e.g. `fastapi>=0.115,<1.0`, `pydantic>=2.8,<3.0`, `opentelemetry-sdk>=1.25,<2.0`) while the exact resolved versions live in `uv.lock`. Dev dependencies follow the same pattern (e.g. `pytest>=8.3,<9.0`).

3. **Build-system pinning.** Every product sets `[build-system] requires = ["uv_build>=0.8.14,<0.9.0"]` with `build-backend = "uv_build"`, so packaging also goes through uv.

4. **Container strategy.** All backend images derive from `FROM luban-aiops/base-uv:al2023`, which is built once via `make base-images` using the pinned `BASE_UV_UV_VERSION` and `BASE_UV_PYTHON_VERSION` from `mk/defaults.mk`. The base image installs uv into `/usr/local/bin`, creates a non-root `app` user (uid 1000), and sets `UV_LINK_MODE=copy`, `UV_NO_SYNC=1`, `UV_PYTHON=${PYTHON_VERSION}`, `UV_PYTHON_INSTALL_DIR=/app/.python`. Product images then run `uv sync --frozen --no-dev` to install only production dependencies.

5. **Python version pinning.** Each product carries a `.python-version` file (referenced by the Dockerfile COPY step); the base image resolves the interpreter via `UV_PYTHON` when none is found on PATH.

6. **No private registry configuration visible in-tree.** No `uv.toml`, `pyproject.toml` `[tool.uv.sources]`, `PIP_INDEX_URL`, `PYPI_MIRROR`, or `GOFLAGS -GOPRIVATE` appears in the repository. Dependency resolution relies on the default PyPI index (plus ECR for the base image `public.ecr.aws/amazonlinux/amazonlinux:2023-minimal`).

7. **Cross-cutting verification.** `make verify` chains product tests, GitOps overlay rendering, dashboard validation, policy validation, secret-vocabulary validation, password-policy validation, portal tests, and integration proofs. It does not include a `uv export` or `uv lock --check` step beyond the existing `--frozen` enforcement.

## Conventions and constraints

- **Observed convention:** All Python dependencies are declared exclusively in `pyproject.toml` under `[project.dependencies]` (runtime) and `[dependency-groups].dev` (test-only). No `requirements.txt` or `setup.py` exists anywhere in the codebase.
- **Enforced constraint:** `uv sync --frozen` is invoked by both the shared `sync` target and the Dockerfile `RUN` step; any drift between `pyproject.toml` and `uv.lock` fails the build and CI.
- **Enforced constraint:** Container images are built from `luban-aiops/base-uv:al2023` (built via `make base-images`), which pins uv to `BASE_UV_UV_VERSION=0.12.1` and Python to `BASE_UV_PYTHON_VERSION=3.12` — overrides require passing `--build-arg` explicitly.
- **Enforced constraint:** The root `Makefile` enumerates `PYTHON_PRODUCTS` and `IMAGE_PRODUCTS`; adding a new Python product requires registering it in both lists so `make sync`, `make test`, and `make build` cover it automatically.
- **Enforced constraint:** The root `VERSION` file is the single source of truth for the platform release version; `make validate-version` (via `shared/shared-contracts/scripts/validate_version.py`) enforces lockstep between `VERSION`, every product's `pyproject.toml` version, and portal metadata.
- **Observed convention:** Common observability and web-framework dependencies (`fastapi`, `uvicorn[standard]`, `pydantic`, `opentelemetry-*`, `prometheus-client`) appear across most products with identical version ranges, keeping the runtime surface aligned.
- **Observed convention:** Test-only packages (`pytest`, `fakeredis`, `jsonschema`) are placed under `[dependency-groups].dev` rather than `[project.dependencies]`, and Dockerfiles invoke `uv sync --frozen --no-dev` to exclude them from production images.

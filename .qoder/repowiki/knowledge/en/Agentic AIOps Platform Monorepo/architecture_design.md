The repository is organized as a product monorepo under `products/`, where each service (agent-platform, platform-gateway, execution-runtime, identity-broker, audit-service, incident-service, skills-hub, tool-gateway, operator-portal) ships its own FastAPI app, Dockerfile, Makefile, and tests. Cross-service boundaries are enforced by `shared/shared-contracts/schemas/*.schema.json` (JSON Schema files for chat, session, execution, identity, skill, incident, and policy payloads) plus `shared/platform-ops/gitops/` scripts that provision secrets per service. The `platform-gateway` acts as the single ingress that authenticates via `identity-broker`, enforces policies from `policy-center`, and proxies calls to agent-platform, execution-runtime, incident-service, skills-hub, and tool-gateway. Feature development follows spec-driven development: specs in `docs/specs/SPEC-NNN-*` define plan/spec/tasks triads that drive implementation across these products, with ADRs in `docs/adr/` recording architectural decisions. Build and image orchestration lives in `mk/` (defaults.mk, image.mk, python.mk) and the top-level `Makefile`, while `shared/base-images/base-uv/Dockerfile` provides the common Python container base used by every product.

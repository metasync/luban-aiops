The repository is organized as a product-per-service monorepo under `products/`, where each Python FastAPI service (agent-platform, platform-gateway, identity-broker, audit-service, incident-service, skills-hub, tool-gateway) follows an identical internal layout (`src/<service>/api`, `core`, `schemas`, `services`) so they can be built, containerized, and deployed uniformly via per-product Makefiles and Dockerfiles. Cross-service boundaries are enforced by JSON Schema files in `shared/shared-contracts/schemas/` plus policy definitions in `shared/shared-contracts/policies/`; the platform-gateway acts as the single ingress that authenticates callers against the identity-broker, enforces policies, and proxies requests to downstream services while propagating identity context and emitting audit events consumed by the audit-service. The operator-portal builds a React SPA that consumes these same APIs for human-in-the-loop confirmation flows. Kubernetes deployment is driven from `shared/platform-ops/gitops/dev-k8s` with Kustomize overlays and secret-sync scripts, and all cross-cutting concerns (observability, metrics, request context, telemetry) are implemented per-service but aligned to the conventions documented in `shared/shared-contracts/observability-conventions.md`. Feature development is governed by spec-driven artifacts under `docs/specs/SPEC-NNN-*` and ADRs under `docs/adr/`, which define the contracts that each product must implement.

- Specs follow a fixed template with Status, Summary, Motivation, numbered Requirements (R-N) each carrying testable acceptance criteria, Non-Goals, Impact, Open Questions, and a Changelog tracking draft → approved → delivered transitions.
- New capabilities are introduced via environment-backed settings on `RuntimeSettings` (e.g. `AGENTSCOPE_*`, `AGENT_STATE_STORE_BACKEND`, `AGENT_EXECUTION_*`) that default to existing behavior so unset deployments remain unchanged.
- Cross-service contracts are published as additive JSON Schema files under `shared/shared-contracts/schemas/` (tool-invocation, tool-result, execution-request, execution-receipt, audit-event) rather than inlined payloads.
- Failure modes degrade fail-closed or fail-open explicitly per requirement (missing signing key rejects execution, Postgres connection failure falls back to in-memory store, corrupt state rows are discarded with warnings) instead of raising unhandled exceptions.
- Adoption of upstream AgentScope features must pass a documented adoption gate preserving deny-by-default policy, delegated-token identity, read-only posture, and no leakage of kernel types across the platform-owned v2 contract boundary.

Four sequential, extending specs form a layered design for multi-provider LLM selection in the agent-platform: SPEC-024 introduces a credential-gated model catalog with a read-only `GET /api/v2/models` discovery endpoint, per-session pinned model affinity (request > pinned > default), and audit enrichment on `chat_started`/`chat_completed`; SPEC-026 extends it to expose each provider's full curated model series, shifts entry identity from provider name to model name, adds `<PROVIDER>_MODELS` override, and consolidates gitops runtime-profiles into a single generic profile; SPEC-027 adds live discovery by querying each configured provider's OpenAI-compatible `/models` endpoint with a fail-soft ladder (live → in-memory cache → Postgres-persisted last-good → curated series) driven by a FastAPI lifespan background task and atomic `MODEL_CATALOG` swap; SPEC-028 adds a fourth `luban` provider adapter using the same machinery with mandatory `LUBAN_BASE_URL`, small-model-safe defaults, and operator hosting guides. Each spec declares status, owner, release slice, related ADRs, requirements with acceptance criteria, non-goals, impact matrix, open questions, and changelog — forming a stable contract surface between agent-platform, platform-gateway, operator-portal, and shared contracts.

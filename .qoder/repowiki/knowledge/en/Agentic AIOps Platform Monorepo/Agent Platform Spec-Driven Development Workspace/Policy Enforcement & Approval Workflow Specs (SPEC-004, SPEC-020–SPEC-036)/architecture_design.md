Each subdirectory is a self-contained spec slice under `docs/specs/`, following a uniform three-file layout (`plan.md`, `spec.md`, `tasks.md`) that records status, owner, release slice, requirements with acceptance criteria, non-goals, impact, open questions, and a delivery changelog. The specs form a chronological dependency chain: SPEC-004 introduces the shared-contracts policy schema and gateway-side deny-by-default evaluation; SPEC-020 bridges kernel ASK parking to portal approve/deny via new SSE frames and a confirm endpoint; SPEC-030 adds the `require_approval` decision outcome with `tier_1` (self-approval) and `tier_2` (designated approver) enforcement on the same bridge; SPEC-031 persists confirmation lifecycles in Postgres and exposes an approvals inbox; SPEC-032 adds owner-side polling to reflect external decisions; SPEC-033 anchors cards to their parking turn ordinal; SPEC-034–SPEC-036 iteratively polish portal UX (arrival highlights, session-list refresh, banner layout, history pagination, seeded reveal). Cross-cutting boundaries are enforced through shared contracts in `shared/shared-contracts` (policy schemas, audit-event schema, agent-stream-event schema, default policy bundle), and each spec explicitly lists which products (`products/platform-gateway`, `products/agent-platform`, `products/operator-portal/web-ui`, `products/tool-gateway`) and contracts it touches, keeping dependency direction strictly from newer slices back to earlier ones.

Three independent release-spec documents (SPEC-014, SPEC-015, SPEC-039) each define a product slice with the same internal structure — plan.md, spec.md, tasks.md — describing a new service plus cross-cutting integrations. SPEC-014 (R2) introduces `products/skills-hub`, a FastAPI service that federates Git/local Markdown skill sources, validates them against `shared/shared-contracts/schemas/skill.schema.json`, indexes them behind a `SkillStore` protocol (InMemory/Postgres), and exposes search/list/get APIs consumed by a read-only `skills.search` tool registered in tool-gateway; agent-platform extends its system prompt to cite skills. SPEC-015 (R3) adds `products/incident-service`, which normalizes Alertmanager webhooks and manual reports into an `incident.schema.json` envelope, runs operator-initiated triage via agent-platform chat in dedicated sessions, captures a schema-validated `triage-report.schema.json`, and dispatches outcomes through a pluggable `Connector` protocol (built-in audit sink); platform-gateway proxies triage under new `incident:*` policy actions and tool-gateway registers `incidents.list`/`incidents.get`. SPEC-039 (R5 draft) augments `agent-platform` with a digest-first shift-summary artifact backed by a new Postgres store, gated by a `shifts:summarize` policy action, producing immutable snapshots from durable session/evidence/confirmation/execution records with optional LLM prose generated only from the digest. All three specs deliberately reuse existing guardrails (deny-by-default policy, read-only tool framework, broker-mediated delegation, evidence panels, audit trail) rather than opening new trust surfaces, and each follows the shared contract-test pattern binding Pydantic models to JSON schemas.

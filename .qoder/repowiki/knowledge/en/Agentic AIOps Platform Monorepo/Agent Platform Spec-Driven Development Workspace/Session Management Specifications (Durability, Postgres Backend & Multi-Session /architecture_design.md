Three independent spec directories under `docs/specs/`, each following a uniform plan/spec/tasks triad that drives implementation in `products/agent-platform` and `shared/platform-ops`. SPEC-006 introduces a strategy-pattern `SessionStore` protocol with pluggable `InMemorySessionStore` and `RedisSessionStore` selected via `SESSION_STORE_BACKEND`, including graceful fallback to memory when Redis is unreachable. SPEC-016 extends the same protocol with a `PostgresSessionStore` backed by a `sessions` table (`session_id`, `user_id`, `created_at`, `last_accessed_at`) using synchronous `psycopg[binary]`, moving sessions off AgentScope's kernel Redis to decouple platform state from the framework runtime. SPEC-022 builds on those durable stores to expose a v2 session lifecycle API (`GET /api/v2/sessions`, `GET /api/v2/sessions/{id}` with transcript, `DELETE /api/v2/sessions/{id}`) proxied through platform-gateway behind new `session:list` and `session:delete` policy actions, and adds a modality-aware chat request schema (`input_modality: text|voice`) with two enforced invariants. Each spec tracks status, acceptance criteria, risks, non-goals, and deployment impact (Kustomize overlays, runtime-config.env changes), forming a staged delivery path from durability → backend separation → operator workspace foundations.

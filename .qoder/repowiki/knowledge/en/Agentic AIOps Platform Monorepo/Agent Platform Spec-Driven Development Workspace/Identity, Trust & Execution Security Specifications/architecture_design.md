Three independent spec packages under `docs/specs/`, each a self-contained leaf with `spec.md` (requirements + acceptance criteria), `plan.md` (sequencing), and `tasks.md` (implementation checklist). SPEC-003 hardens the user identity boundary by replacing caller-asserted headers with RSA-signed JWTs issued by `identity-broker` and verified locally in `tool-gateway` via JWKS. SPEC-008 extends that trust to service-to-service calls by adding an audience-bound delegated-token exchange endpoint on `identity-broker`, a per-user cached delegated token in `tool-gateway`, and bearer relay from `agent-platform`. SPEC-037 adds HMAC-SHA256 signed execution envelopes around approved mutating tool calls, persisted as request/receipt records alongside confirmation records and surfaced as audit events. All three specs converge on shared contracts in `shared/shared-contracts` (JWT schema, audit-event schema) and are gated by CI via `make verify`; they form a layered trust progression: user identity → service delegation → execution integrity.

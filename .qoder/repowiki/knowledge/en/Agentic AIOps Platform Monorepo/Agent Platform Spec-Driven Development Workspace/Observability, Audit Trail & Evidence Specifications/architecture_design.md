Each spec follows a uniform three-file layout (plan.md, spec.md, tasks.md) and governs one cross-cutting capability that spans multiple products:
- SPEC-005 establishes the dual-surface observability contract: an always-on Prometheus `/metrics` endpoint plus an opt-in OpenTelemetry OTLP push pipeline gated by `OTEL_ENABLED`, with `x-request-id` bridged to W3C `trace_id` for correlation.
- SPEC-011 extends the agent-stream event schema with `tool_call`/`tool_result` frames, adds an Elastic read-only connector in tool-gateway, and renders a live evidence panel in the operator portal.
- SPEC-013 introduces a new `audit-service` product with a shared `audit-event.schema.json` contract, a strategy-pattern `AuditStore` (in-memory + PostgreSQL), authenticated fire-and-forget ingestion from all emitting services, and a policy-gated query API (`audit:read`) proxied through platform-gateway.
- SPEC-025 persists the `tool_call`/`tool_result` evidence frames alongside session transcripts so reopened sessions render the same evidence card as live streams, with bounded per-entry/per-session storage caps.
- SPEC-029 extends the audit vocabulary with `skill_searched`, `skill_retrieved`, `skills_synced` and wires skills-hub into the canonical emitter parity family, correlating via `x-request-id` forwarded from tool-gateway.
Dependency direction is strictly outward: specs reference shared contracts (`shared/shared-contracts/schemas/*`), existing service patterns (FastAPI, settings classes, structured logging), and dev-k8s overlays; they do not contain implementation code. Each spec records status, acceptance criteria, non-goals, impact, open questions, and a changelog documenting approved decisions and delivery deviations.

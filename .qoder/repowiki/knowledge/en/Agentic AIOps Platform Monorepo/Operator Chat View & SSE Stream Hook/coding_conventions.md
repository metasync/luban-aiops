- Streaming state is driven by refs (`turnsRef`, `sessionIdRef`, `controllerRef`, `streamingRef`) plus a minimal `useReducer` counter (`bump`) to force re-renders after event dispatch, keeping mutation synchronous during frame processing.
- SSE connections are wrapped in `AbortController`s stored in `controllerRef`; cleanup uses ownership checks (`controllerRef.current !== owner`) so a superseded stream's finally block does not cancel the replacement stream.
- Confirmation cards are anchored to their originating session via a `sessionId` field and transition through a fixed status set (`pending` → `approved` | `denied` | `expired` | `error`) using a shared `lockCard` helper that also sets a user-facing note.
- Error handling distinguishes `AbortError` (session switch), `StreamOpenError` with specific HTTP codes (401, 404, 409, 410), and generic errors, mapping each to a user-visible card or turn error rather than surfacing raw exceptions.
- Per-session transcript caching uses a `Map<string, ChatTurn[]>` keyed by session id, with `setSession` stashing the previous session's turns before restoring the target — history passed to `setSession` is shadowed when the session is already active, necessitating `reseedTurns` for authoritative updates.
- User-rendered content goes through a safe `renderMarkdown` function before being injected via `dangerouslySetInnerHTML`, ensuring only http(s) links are rendered and all other markup is escaped.

The module is organized as a four-tier documentation system that mirrors the platform's development lifecycle:
- `adr/` — Architecture Decision Records (numbered `NNNN-slug.md`, immutable once accepted, with a template and index) capturing cross-product decisions such as runtime kernel selection, trust model changes, and HITL gate policy.
- `specs/SPEC-NNN-<slug>/` — Feature specifications following a three-file structure (`spec.md` requirements, `plan.md` technical approach, `tasks.md` execution checklist) sourced from `specs/templates/`; each spec carries a lifecycle status (`draft` → `approved` → `in-progress` → `delivered` → `superseded`) and is linked to release slices in `agentic-aiops-platform/delivery-roadmap.md`. The index in `specs/README.md` enumerates all 59 specs and their delivery status.
- `agentic-aiops-platform/` — Long-lived Tier 1 architecture records (decision matrix, reference architecture, identity/auth design, authorization matrix, policy specification) plus a dated `release-notes/` directory tracking every release slice chronologically.
- `guides/` — Tier 3 living operator-facing guides (getting started, portal user guide, studio guide, configuration, troubleshooting, tool authoring, skills, incident triage).
- `workspace/` — Workspace-level governance documents defining product boundaries, backend layout conventions, Python container strategy, and repository organization.
Dependency direction flows outward: ADRs inform specs; specs drive implementation and feed into release notes; guides reference specs and architecture records but are not referenced by them. Verification is gated through `make verify`, which runs product tests and renders GitOps overlays, enforcing ADR-0008's requirement-to-test traceability.

- Each product follows a uniform package layout with `src/<product>/api`, `core`, `schemas`, `services`, and a parallel `tests/` directory mirroring module names, enabling consistent local testing and per-product Makefiles.
- Cross-product boundaries are expressed exclusively through JSON Schema files in `shared/shared-contracts/schemas/` (chat, session, stream, tool-invocation, audit, policy models) rather than shared Python packages, keeping consumers dependency-light.
- Policy changes are centralized: edits go only to `shared/shared-contracts/policies/policy-default.yaml`, then propagated via `make sync-policy` to both gateway packages and the dev-k8s overlay ConfigMap, with scenario expectations validated by `make validate-policy-scenarios`.
- Spec-driven development is enforced by requiring every cross-boundary or capability-changing change to be authored as a `docs/specs/SPEC-NNN-<slug>/` triad (spec.md, plan.md, tasks.md) with sequential numbering, requirement IDs (R-x), and acceptance criteria mapped to tests before advancing to `delivered`.
- Architecture decisions that constrain multiple products or alter trust/identity/deployment topology are captured as immutable numbered ADRs in `docs/adr/` using the provided template, with statuses of proposed/accepted/superseded rather than ad-hoc design notes.
- All Python services standardize on `uv` for environment and dependency management, pinning interpreter versions via `.python-version` at both workspace root and per-product directories so container builds honor the same target.

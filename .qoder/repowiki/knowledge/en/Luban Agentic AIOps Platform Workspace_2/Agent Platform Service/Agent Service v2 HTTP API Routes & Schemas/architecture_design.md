Two cooperating sub-packages form the HTTP boundary of the agent service. `api/v2/routes.py` defines a single FastAPI `APIRouter` with prefix `/api/v2` that mounts endpoints for chat (sync POST `/chat`, SSE stream GET `/chat/stream`, confirmation POST `/chat/confirm`, pending-confirmation GET), session CRUD (`/sessions`), skill-target declaration, skill graduation export, model discovery (`/models`), runtime metadata (`/runtime-metadata`), health (`/health`), and operations documents (`/documents`). Route handlers are thin adapters: they extract identity from headers (`X-User-ID`, `x-request-id`, forwarded `Authorization: Bearer` per SPEC-008 R-5), validate via shared helpers (`_user_id`, `_validated_skill_target`, `_resolve_model`, `_reject_if_parked`), then delegate to `agent_service.services.*` (session store, kernel, audit emitter, evidence store, confirmation registry, skills client, etc.). No AgentScope types leak into route signatures or response bodies — all serialization goes through the sibling `schemas/v2.py` Pydantic models, which are the single source of truth validated against JSON Schema files in `shared/shared-contracts/schemas/`. The older `schemas/api.py` holds legacy v1 models kept for backward compatibility. Dependency direction is strictly inward: routes → services → stores/kernel; schemas have no runtime imports beyond Pydantic.

The module defines a single abstract base `AgentScopeProvider` in `base.py` that enforces a uniform contract: each provider declares `provider_name`, `default_model`, optional `default_base_url`, a curated `model_series` (SPEC-026), and discovery filters (`discover_family_prefixes`, `discover_exclude_markers`) used by live model discovery (SPEC-027). Concrete providers (`openai.py`, `dashscope.py`, `deepseek.py`, `luban.py`) subclass this base and implement `build_model`, which lazily imports the corresponding `agentscope.credential`/`agentscope.model` classes and constructs the vendor-specific chat model with parameters pulled from `RuntimeSettings.provider_options`. A central `registry.py` holds an in-process `_PROVIDERS` dict keyed by string name and exposes `get_provider()` (raising `ProviderConfigurationError` for unknown names) plus `supported_provider_names()`. Dependency direction is one-way: providers depend on `base.py` and `agent_service.runtime_settings`; nothing in this package depends back on callers. The `luban` provider reuses the OpenAI client to target any OpenAI-compatible server (Ollama, vLLM, llama.cpp) and adds a stricter `validate` requiring `LUBAN_BASE_URL`.

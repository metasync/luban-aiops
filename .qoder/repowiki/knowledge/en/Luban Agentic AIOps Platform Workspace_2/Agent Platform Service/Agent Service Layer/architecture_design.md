Each concern is a single-file service module (session_state, execution_audit, skills_flow, runtime_model, document_evidence, security_prose) that composes against shared cross-cutting primitives: `runtime_dependencies.get_runtime_kernel()` provides a cached `AgentKernel` instance used by runtime, execution, and skills modules; `hitl_confirmations.CONFIRMATION_REGISTRY` is a process-wide parked-confirmation store consumed by both flow approvals and skill graduation; `incident_client` and `skills_client` are external HTTP clients reused across incident-report, shift-summary, and skill-draft flows. Pluggable backends (in-memory vs Redis/Postgres) are selected via `agent_service.core.config.get_settings()` so every persistence layer shares one configuration source. The package re-exports only `get_runtime_kernel`, keeping child modules as internal implementation details of the agent service boundary.

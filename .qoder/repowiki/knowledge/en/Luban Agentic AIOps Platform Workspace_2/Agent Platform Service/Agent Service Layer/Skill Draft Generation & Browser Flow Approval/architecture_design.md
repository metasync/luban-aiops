Three cooperating services under `agent_service/services`:
- `skills_client.py` is an outbound HTTP client to the skills-hub service (`POST /api/v1/skills/validate`) using Basic auth from `RuntimeSettings`. It raises a small typed exception hierarchy (`SkillsDependencyNotConfigured`, `SkillsServiceUnavailable`, `SkillsClientRejected`) so callers map failures to 503/502/4xx without leaking raw traces.
- `skill_draft.py` implements two generation anchors — session-scoped (`build_skill_draft_bundle`) and incident-scoped (`build_incident_skill_draft_bundle`) — both producing a digest-only JSON bundle (no raw transcripts/evidence) that feeds a fenced-contract prompt (`skill-frontmatter`). The model response is parsed by `parse_model_output`, post-processed through deterministic guardrails (`postprocess`: redaction via shared `REDACTION_VALUE_PATTERNS`, UTF-8 truncation to `MAX_BODY_BYTES`, Skill Format v1 caps), assembled into YAML frontmatter + Markdown with a provenance HTML comment, and finally validated against skills-hub. Any failure degrades to a facts-only skeleton (`build_skeleton` / `build_incident_skeleton`) that is always format-valid, so the path never returns 500.
- `flow_approvals.py` maintains two process-wide in-memory stores keyed by `session_id`: `FlowContextStore` (reflection of the gateway's flow binding from `web.navigate`) and `FlowApprovalStore` (TTL-bounded operator approval of the first parked write). A `FlowContext.identity()` tuple `(skill_id, origin)` scopes each approval; rebinds to a different flow invalidate authority, and gateway refusal codes in `FLOW_KILLING_ERROR_CODES` clear both stores to prevent stale auto-signing. Only tools in `BROWSER_WRITE_TOOLS` are gated.

Dependency direction: `skill_draft.py` depends on `incident_client`, `shift_summary`, and `skills_client`; `flow_approvals.py` is stateful runtime state consumed by the kernel/tool-gateway middleware and has no inward dependencies on the other two modules.

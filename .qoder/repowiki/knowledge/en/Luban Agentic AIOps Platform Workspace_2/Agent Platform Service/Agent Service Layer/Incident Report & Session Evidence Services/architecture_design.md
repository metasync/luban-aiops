Three cooperating service modules under `agent_service/services`:
- `incident_client.py` is a read-only HTTP client built on `httpx.AsyncClient` that calls `/api/v1/incidents/{incident_id}` using Basic auth sourced from `RuntimeSettings`. It raises a small structured exception hierarchy (`IncidentDependencyNotConfigured`, `IncidentServiceUnavailable`, `IncidentNotFound`, `IncidentClientRejected`) so callers can map failures to 503/502/404 without leaking raw traces.
- `incident_report.py` consumes the bundle returned by that client and builds an `incident_report` digest with four deterministic sections (`incident`, `triage`, `dispatches`, `session`). The `session` section implements SPEC-039 R-3 two-tier posture: owner sessions get full digests via `_digest_own_session`, foreign sessions are metadata-only when the requester has `approvals:list`, otherwise a `foreign_denied` marker; missing/unavailable sessions degrade gracefully. A separate `document_summary` produces counts-only strings for list surfaces.
- `evidence_store.py` provides per-session tool-evidence persistence (SPEC-025 R-1) behind an `EvidenceStore` Protocol with two concrete backends — `InMemoryEvidenceStore` and `PostgresEvidenceStore` — both subclassing `_BaseEvidenceStore` which centralizes size-cap enforcement, turn grouping, and budget eviction. The Postgres backend uses inline DDL and parameterized SQL statements, performs opportunistic TTL sweeps on write, and refreshes `updated_at` on reads to mirror the state-store pattern. A module-level `EVIDENCE_STORE` singleton is constructed by `build_evidence_store()`, which reads `AGENT_STATE_STORE_BACKEND` / `AGENT_STATE_DB_URL` / `AGENT_STATE_TTL_SECONDS` and falls back to memory if Postgres initialization fails.
Dependency direction is one-way: `incident_report` depends on `incident_client` and `session_store`; `evidence_store` depends only on core metrics and the shared agent-state env helpers; nothing in this scope imports the others except through well-defined interfaces.

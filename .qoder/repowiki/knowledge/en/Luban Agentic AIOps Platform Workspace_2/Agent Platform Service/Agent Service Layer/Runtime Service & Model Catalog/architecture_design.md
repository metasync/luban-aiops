Three cooperating files form the runtime facade of the agent service:
- `runtime_dependencies.py` is a thin dependency-injection layer that caches a single `AgentKernel` instance (via `functools.lru_cache`) and exposes the process-wide `CONFIRMATION_REGISTRY`, decoupling callers from kernel construction.
- `runtime_service.py` is the public API surface: health/status helpers (`live_status`, `ready_status`, `runtime_metadata`) delegate to the cached kernel, while `chat` and `stream_chat` resolve sessions via `ensure_session` and forward requests to the kernel's `reply_text` / `stream_events`, serializing SSE chunks as JSON.
- `model_catalog.py` implements a credential-gated, immutable-per-snapshot `ModelCatalog` singleton built from per-provider environment variables (`<PROVIDER>_API_KEY`, `_BASE_URL`, `_MODELS`, with fallback to `AGENTSCOPE_*` knobs for the active profile). It resolves provider credentials, builds entries from adapter-curated or overridden model series, deduplicates ids, and exposes legacy bare-provider-name aliases. A module-level `MODEL_CATALOG` object is swapped atomically under a `threading.Lock` by `refresh_catalog` (SPEC-027), so readers snapshot references without lock contention. Secrets are never exposed through `to_public_dict()`, which strips credentials/base URLs for discovery payloads.
Dependency direction is one-way: `runtime_service` → `runtime_dependencies` → `AgentKernel`; `model_catalog` depends only on `providers`, `runtime_settings`, and stdlib — it has no back-reference to the kernel.

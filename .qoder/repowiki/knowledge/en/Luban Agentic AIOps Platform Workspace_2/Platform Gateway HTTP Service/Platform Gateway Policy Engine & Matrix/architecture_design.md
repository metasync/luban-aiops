Two-layer design inside `platform_gateway.services` plus a data layer under `platform_gateway.policies`. `policy_engine.py` is the core: it defines frozen dataclasses (`PolicyRule`, `ApprovalSpec`, `PolicyDecision`) and a module-level singleton cache (`_bundle`, `_bundle_version`, `_bundle_hash`, `_configured_path`) keyed on the configured path. `load_bundle()` resolves the bundle from an external file (via `PLATFORM_GATEWAY_POLICY_PATH`) or falls back to the packaged `policy-default.yaml` bundled as a package resource; parsing validates schema, outcome, and approval constraints and raises `PolicyLoadError`. `evaluate()` implements SPEC-030 precedence `deny > require_approval > allow`, selecting the highest-priority rule within each outcome class and returning a `PolicyDecision` that may carry an `ApprovalSpec`. `policy_matrix.py` is a read-only transparency layer that reuses `evaluate()` to derive a role×action boolean matrix plus an additive `approval_requirements` structure (SPEC-030 R-5), filtering rows by identity scope (`platform-admin` sees all roles, others see only their own). The `policies/` package holds the default bundle (`policy-default.yaml`) — versioned, SHA-256 fingerprinted at load time (SPEC-048) — and is exposed via `importlib.resources` so it ships with the wheel. Dependency direction: `policy_matrix.py → policy_engine.py`; both depend only on `core.config.PlatformGatewaySettings` and `schemas.api.IdentityContext`, keeping the engine free of HTTP/framework coupling.

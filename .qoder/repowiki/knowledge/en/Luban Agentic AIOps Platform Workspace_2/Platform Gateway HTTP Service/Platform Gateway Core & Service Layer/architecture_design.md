The module is the runtime core of the platform-gateway service. `main.py` is the entry point that builds a `GatewayRunSettings` from env and starts uvicorn with the FastAPI app created in `app.py`. `app.py` wires logging, an HTTP middleware that records per-request latency via `core/observability`, includes the router, and mounts metrics/telemetry via `core/metrics` and `core/telemetry`. Configuration is centralized in `core/config.py` as a frozen `PlatformGatewaySettings` dataclass loaded from environment variables through `get_settings()` (LRU-cached), with defaults for agent-service, identity-service, audit, incident, tool-gateway, and skills-hub endpoints plus JWT/JWKS settings. `core/runtime.py` provides the separate `GatewayRunSettings` for host/port. The business layer lives in `services/gateway_service.py`, which implements request identity resolution (`resolve_request_identity` — local JWT verify or synthetic dev user), policy enforcement (`enforce_policy` calling `policy_engine.evaluate`), and every upstream proxy (sessions, documents, chat, skill drafts, approvals inbox, identity callbacks). Each proxy follows a uniform error posture: upstream 4xx pass through unchanged, transport failures and upstream 5xx map to 502, with structured detail extraction via `_upstream_detail`. Outbound HTTP calls are isolated in dedicated clients under `services/`: `agent_client.py` (the primary v2 agent-service client using httpx with SSE streaming for chat/confirm streams), `incident_client.py`, `skills_hub_client.py`, and `tool_gateway_client.py`. Request-scoped cross-cutting state (request id) flows through `core/request_context`. Shared Pydantic models mirroring shared-contracts schemas live in `schemas/api.py` (ChatRequest, SessionRecord, IdentityContext, etc.) and are consumed by both routes and services. `metadata.py` centralizes SERVICE_NAME/TITLE/VERSION used across health/readiness surfaces.

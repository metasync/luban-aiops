Three cooperating layers form the auth boundary of the gateway:
- `api/routes/auth.py` exposes FastAPI endpoints (`/api/v1/auth/{login,login-url,callback,me,logout-url,refresh}`) that orchestrate login flows via `gateway_service` and resolve identity by calling `verify_token` on bearer tokens.
- `services/token_verifier.py` performs local JWT verification against a cached `PyJWKClient` (module-level singleton keyed by `identity_jwks_url`) using RS256 with required claims `exp/iss/sub/aud`; it raises a domain `TokenVerificationError` rather than propagating `jwt` exceptions, and extracts an RFC 8693 `act` actor claim into an `IdentityContext`.
- `services/delegation_client.py` owns per-replica per-user in-memory cache (`_CacheEntry` with `expires_at`/`refresh_at` at 80% TTL) and exchanges verified subject tokens for audience-bound delegated tokens at `identity_service_url/api/v1/auth/exchange`. It prefers a projected workload token from a file (`workload_token_path`, re-read each exchange) and falls back to static client credentials with a one-time warning; a dev mode mints a locally signed RS256 subject token when no real user token is present. Exchange failures are non-fatal — `obtain_delegated_token` returns `None` so chat proceeds tool-less — and all outcomes are recorded via `core.metrics` delegation counters.
Dependency direction: routes → token_verifier + delegation_client; both services depend only on `PlatformGatewaySettings` and shared `schemas.api.IdentityContext`, keeping the auth boundary decoupled from upstream service implementations.

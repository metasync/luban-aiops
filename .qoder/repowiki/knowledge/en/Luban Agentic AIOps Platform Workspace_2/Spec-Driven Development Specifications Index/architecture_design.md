Flat directory layout under `docs/specs/` where every feature is a numbered folder `SPEC-NNN-<slug>/` containing three Markdown files: `spec.md` (requirements + acceptance criteria), `plan.md` (technical approach and sequencing), and `tasks.md` (execution checklist). A shared `templates/` directory holds the canonical skeleton for new specs. `README.md` defines the three-tier documentation model (Architecture Record / Feature Specs / Living State Docs), the spec lifecycle statuses (`draft`, `approved`, `in-progress`, `delivered`, `superseded`), numbering/naming rules, and the enforcement gate `make verify`. The index table in `README.md` is the single source of truth linking each spec ID to its title and status; later specs cross-reference earlier ones via an `extends SPEC-XXX` convention rather than importing content. Dependency direction is one-way: specs describe product code in `products/` and contracts in `shared/shared-contracts` but are not consumed by build tooling — they are review artifacts whose delivery is tracked by PR linkage and the frozen `delivered` state.

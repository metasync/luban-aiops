- Every tool subclass of `BaseTool` exposes its contract via a `definition` property returning a `ToolDefinition` with a `<domain>.<action>` name, a human-readable description, a `risk_level` from `{read, write, admin}`, a `category`, and a JSON-schema-like `parameters_schema`.
- Connector classes own client lifecycle behind a lazy `_ensure_client()` method that caches configuration status and returns `False` when the underlying SDK is missing or unreachable; tools call this first and return `make_error_result` with a connector-specific code (e.g. `ELASTIC_NOT_CONFIGURED`, `K8S_NOT_CONFIGURED`).
- Sync I/O performed by third-party SDKs is executed off the event loop via `asyncio.get_running_loop().run_in_executor(None, partial(connector._method_sync, ...))`, keeping tool `execute` methods fully async.
- Parameter validation uses dedicated `_coerce_*` helper functions that clamp values into bounded ranges and return `(value, error_message | None)` tuples, letting callers produce structured `INVALID_PARAMETERS` results instead of raising exceptions.
- Successful executions wrap data in `ToolResult(status='success', ..., evidence=build_evidence(risk_level, SOURCE_SYSTEM, duration_ms))`, while failures use `make_error_result` with a stable `code` string and the connector's `SOURCE_SYSTEM` as `source_system`.
- Connectors register their tools declaratively in a single `register_tools(registry)` method that calls `registry.register(...)` for each tool class, keeping registration centralized and allowing the registry's risk-tier gate to filter mutating tools.

The service is a FastAPI application (`app.py`) with a single entry point in `main.py` that boots uvicorn using `ExecutionRunSettings.from_env()`. The app lifecycle (`lifespan`) initializes two process-scoped services — an `ExecutionRecordStore` (memory or postgres via `execution_records.py`) and a `SingleFlightRegistry` (in-process idempotency keyed by `execution_id`, pinned to single-replica deployments) — attached to `app.state`. HTTP routes live under `api/routes/` and are mounted through `api/router.py`; the only execution surface is `POST /api/v1/executions/handoff` in `handoff.py`, which performs fail-closed authentication (constant-time bearer token comparison), envelope shape validation, HMAC-SHA256 signature verification, argument-digest re-verification, then delegates to `services/executor.py` for the one-shot tool-gateway call. All other routes are health endpoints (`health.py`). Cross-cutting concerns are isolated in `core/`: `config.py` provides frozen `ExecutionSettings` loaded from `EXECUTION_*` env vars with `__post_init__` validation; `observability.py`, `metrics.py`, `telemetry.py`, and `request_context.py` provide structured logging, Prometheus metrics, OpenTelemetry setup, and request-id propagation. Dependencies flow strictly inward: routes → services → core; services never import routes.

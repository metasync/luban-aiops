Three independent SPECs grouped by shared concern — making tool execution observable and auditable across the runtime:
- SPEC-011 adds an Elastic connector to `products/tool-gateway` (parallel to the existing K8s connector), extends `shared/shared-contracts/schemas/agent-stream-event.schema.json` with `tool_call`/`tool_result` stream frames, and renders them in a new Evidence panel in `products/operator-portal`. The trace queue is per-request (`asyncio.Queue`) scoped to `AgentKernel.stream_events`, and tool results are truncated via `AGENT_TOOL_DATA_SUMMARY_MAX_CHARS`.
- SPEC-025 persists those `tool_call`/`tool_result` frames alongside session transcripts in a dedicated `session_evidence` table (dual backend per SPEC-017), exposing them additively on `GET /api/v2/sessions/{session_id}` so reopened sessions render the same evidence card as live streams. Size caps are per-entry (131,072 chars) and per-session (4,194,304 bytes), tunable via `AGENT_EVIDENCE_*` env vars.
- SPEC-029 extends the closed audit vocabulary (`audit-event.schema.json`) with `skill_searched`, `skill_retrieved`, `skills_synced` and implements a fourth member of the canonical fire-and-forget audit-emitter parity family inside `products/skills-hub`, correlating via `x-request-id` forwarded from tool-gateway rather than forwarding user identity.
Dependency direction is one-way: each spec references prior contracts (`SPEC-013` audit trail, `SPEC-017` state store, `SPEC-022` transcripts, `SPEC-011` evidence panels) but does not introduce cross-spec coupling; all three converge on the shared contract layer under `shared/shared-contracts`.

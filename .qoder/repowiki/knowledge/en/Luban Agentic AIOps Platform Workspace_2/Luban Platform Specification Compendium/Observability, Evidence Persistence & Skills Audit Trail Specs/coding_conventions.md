- Each SPEC follows a fixed document shape: Status header (status/owner/created/release slice/related ADRs), Summary, Motivation, Requirements with numbered R-N blocks and acceptance criteria, Non-Goals, Impact listing products and contracts touched, Open Questions with proposed resolutions, and a Changelog.
- New event types extend closed JSON Schema enums in `shared/shared-contracts/schemas/` (e.g., `agent-stream-event.schema.json`, `audit-event.schema.json`) and are mirrored as Literal/enum values in the consuming service's Python schemas, validated by parity tests.
- Audit emission uses a canonical fire-and-forget emitter module replicated byte-for-byte across services (tool-gateway, platform-gateway, identity-broker, incident-service, skills-hub) with identical settings (`*_AUDIT_SERVICE_URL`, `*_AUDIT_CLIENT_ID`, `*_AUDIT_CLIENT_SECRET`) and a shared `AuditEmitterParityTest`.
- Connector implementations follow the established toolkit pattern: lazy client initialization on first invocation, environment-variable gating (`GATEWAY_ELASTIC_ENABLED`, `SKILLS_AUDIT_*`), structured error codes (`ELASTIC_NOT_CONFIGURED`, `ELASTIC_CONNECTION_ERROR`), and read-only semantics enforced at the connector boundary.
- Evidence payloads are bounded before storage or transmission — `data_summary` truncated to `AGENT_TOOL_DATA_SUMMARY_MAX_CHARS` (default 2000) for live streams, and per-entry/per-session caps (131,072 chars / 4,194,304 bytes) for persisted evidence, both tunable via env vars.

Three sibling spec directories under `docs/specs/`, each following the project's `spec.md` + `plan.md` + `tasks.md` triad and tracking status through draft → approved → delivered stages:
- SPEC-024 (`runtime-llm-model-switching`) defines the credential-gated `MODEL_CATALOG`, a read-only `/api/v2/models` discovery endpoint, per-session pinned model with explicit mid-session switch (agent rebuild + state restore), and enriched `chat_started`/`chat_completed` audit payloads — spanning agent-platform settings/catalog/kernel, platform-gateway pass-through, operator-portal selector, and shared-contracts schemas.
- SPEC-028 (`luban-llm-provider`) extends that catalog with a fourth `luban` provider adapter built on OpenAI-compatible AgentScope models, adding `LUBAN_*` env knobs, an operator hosting guide, and reference Kubernetes manifests under `shared/platform-ops/gitops/llm-hosting/`; it deliberately reuses all existing selection/pinning/discovery/audit code paths rather than introducing new ones.
- SPEC-071 (`agentscope-model-router`) adopts AgentScope 2.0.x's `ModelRouterMiddleware` behind a default-off `AGENTSCOPE_MODEL_ROUTER_ENABLED` knob, inserting a `routed` tier into the precedence chain `request > pinned > routed > default`, preserving fail-soft behavior, resume-safety via `middle_context`, and contract stability (`agent-stream-event.schema.json` byte-unchanged); it also mandates a measurement gate (R-3) before any move to default-on.
The specs form a layered dependency: 028 extends 024's catalog mechanics, and 071 composes on top of both by plugging into `_resolve_model` and `_build_middlewares()` without changing the v2 API surface.

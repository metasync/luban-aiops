- Each SPEC follows a fixed document triad: `spec.md` (status/motivation/requirements/non-goals/impact/changelog), `plan.md`, and `tasks.md`, with status progressing through draft → approved → delivered and a changelog section recording decisions and delivery signals.
- Requirements are numbered R-N and each carries testable acceptance criteria rather than prose-only goals, anchoring implementation to verifiable signals (test counts, overlay renders, `make verify` green).
- Cross-cutting security invariants (deny-by-default policy, delegated-token identity, audit emission, v2 contract byte-compatibility) are stated once as non-goals or adoption gates and repeated as acceptance criteria so behavior is preserved rather than redesigned.
- New configuration knobs are introduced as environment variables with explicit defaults (e.g. `AGENTSCOPE_KERNEL_TRACING=false`, `AGENTSCOPE_REPLY_TOKEN_BUDGET` unset = off, `AGENT_EXECUTION_WORKER_TIMEOUT_SECONDS=60`) and validated at startup, keeping unknown settings safe by default.
- Infrastructure isolation is enforced at the deployment layer (ClusterIP-only Service, no HTTPRoute, no portal route) combined with an authenticated handoff credential rather than relying on network policies.

Three independent SPEC documents (SPEC-010, SPEC-018, SPEC-038), each in its own directory with a `plan.md`/`spec.md`/`tasks.md` triad, describing sequential architectural changes across the platform:

- SPEC-010 splits the monolithic `tool-gateway` product: the portal-facing edge (token verification/JWKS, policy enforcement, chat/session proxying, delegation client, portal routes) moves into a new `products/platform-gateway` FastAPI service, while `tool-gateway` is reduced to the tool/connector home (`ToolRegistry`, connectors, `tools:list`/`tools:invoke`, redaction, audit). External HTTP contracts and the deny-by-default trust model are preserved; identity plumbing adds a new broker client for `platform-gateway` and renames portal JWT audience from `tool-gateway` to `platform-gateway`.
- SPEC-018 replaces hand-rolled `FunctionTool` subclassing and per-request toolkit rebuilds in `agent-platform` with AgentScope 2.0.6's `MiddlewareBase` hooks (`on_check_permission`, `on_acting`), adopting out-of-box `TracingMiddleware` (OpenTelemetry spans) and `ReplyBudgetControlMiddleware` (per-reply token budget) behind feature flags, plus opt-in built-in task tools — all gated by a four-point adoption gate preserving deny-by-default policy, delegated-token identity, read-only posture, and the v2 contract boundary.
- SPEC-038 promotes Phase 2 of the approval-gated execution path: a new `products/execution-runtime` worker receives the SPEC-037 signed envelope over an authenticated internal handoff, re-verifies signature + args digest via `execution_signing.verify_envelope` (its first production call site), calls tool-gateway with the forwarded delegated bearer token, signs and writes the receipt into shared Postgres, and provides single-flight idempotency keyed by `execution_id`. The worker is deployed as a ClusterIP-only pod with no portal exposure; agent-service resumes the stream by blocking on the handoff with a bounded timeout.

Dependency direction is one-way: these specs describe changes to existing products (`tool-gateway`, `agent-platform`, `identity-broker`, `operator-portal`) and introduce two new ones (`platform-gateway`, `execution-runtime`); they do not depend on each other except that SPEC-038 consumes the envelope contract defined by SPEC-037.

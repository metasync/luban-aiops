These are documentation-only spec artifacts (each directory contains plan.md, spec.md, tasks.md) describing a three-phase arc across the agent-platform / tool-gateway / operator-portal boundary:
- SPEC-051 implements ADR-0007: the kernel gains a session-scoped `FlowContext`/`FlowApproval` store so the first write-tier browser interaction parks exactly one confirmation card whose headline is assembled from the bound skill's metadata (`title`, `description`, `origin`, `risk_class`); subsequent writes in the same flow execute without further cards, bounded by a configurable TTL (`AGENT_BROWSER_FLOW_APPROVAL_TTL`). The password-reset sample is reconciled so its single gate lands on "Confirm reset" rather than authentication.
- SPEC-060 rebases the two surviving `samples/web-checks/` tutorials (`adhoc-password-reset`, `skill-graduation`) onto `acme-admin`, retiring `samples/web-checks/password-reset` (superseded by `acme-admin/password-reset`) and collapsing the catalog under `samples/acme-admin/`; `browser-check-target` is deliberately kept for platform consumers.
- SPEC-061 reverses SPEC-060's keep decision: it retires `browser-check-target`, `InventoryHealth`, `browser-check-demo.sh`, and the orphaned `browser-check-target` / `admin-portal` credential sets, leaving only `http://acme-admin:8080` in the `browser-dev` profile's allowlist. It also repoints product test fixtures that referenced the retired origin string.
Dependency direction is strictly forward: SPEC-051 establishes the gate semantics, SPEC-060 depends on SPEC-059's `acme-admin` target to rebase against, and SPEC-061 depends on SPEC-060's consolidation before removing the static mock. All three ride release slices within R5 — v0.33.0 (SPEC-051), v0.39.0 (SPEC-060 + SPEC-061 together).

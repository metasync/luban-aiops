Each child directory is a self-contained SPEC (SPEC-NNN-*) following the shared template under `templates/` — `plan.md`, `spec.md`, and `tasks.md` — so every feature ships with an authoring plan, formal specification, and implementation task list. Cross-child relationships are expressed through explicit cross-references between SPECs rather than code: security hardening (SPEC-001/003/009) gates identity trust (SPEC-008/068/070), which in turn feeds policy enforcement (SPEC-004/030/048) that drives HITL approval flows (SPEC-020/031/054) executed by the tool execution framework (SPEC-007/038/063). The numbering order encodes release cadence (R1–R5) and dependency direction, while the `templates/` directory enforces a uniform document shape across all 73+ specs.

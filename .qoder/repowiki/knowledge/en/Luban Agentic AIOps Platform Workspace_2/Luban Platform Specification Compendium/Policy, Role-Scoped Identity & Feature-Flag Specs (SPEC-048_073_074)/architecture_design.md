Three sibling SPEC directories under `docs/specs/`, each following the project's spec template (`spec.md` + `plan.md` + `tasks.md`) and forming a single phased program rooted in ADR-0017:
- SPEC-048 (policy-testing-rollout-controls) is the foundation: it adds bundle provenance (SHA-256 content hash on `bundle_metadata()`), a scenario-expectation harness (`policy-scenarios.yaml` evaluated by `validate_policy_scenarios.py` via `make verify`), a review-time `make policy-diff` impact report, and overlay copy-parity — all without changing evaluation semantics or the bundle schema.
- SPEC-073 (role-scoped-agent-identity) builds phase 2 of the multi-agent series: a closed `AgentRole` enum (`diagnostician`, `orchestrator`, `executor`) bound to a process-local `AGENT_ROLE` contextvar beside `DELEGATED_TOKEN`, per-role toolkit narrowing at `_ensure_toolkit` with a `(token, role)` cache key, and kernel-internal `staged_by_role` provenance on parked confirmations. Delivered inert (no caller wired).
- SPEC-074 (policy-role-axis) realizes the policy half of ADR-0017 Decision 4: an additive v3 `agent_roles_any` field in `policy-rule.schema.json` and an optional `agent_role` input on both gateway `evaluate()` engines, composing conjunctively with the human `roles_any` axis; the `executor`→human-approver disjointness invariant is encoded as policy rather than prose.
Dependency direction is strictly forward: SPEC-074 extends SPEC-048's scenario harness and SPEC-073's closed vocabulary; SPEC-048 has no dependency on the later phases. Each spec explicitly carves out Non-Goals (audit attribution, bounded diagnosis, v2 contract, tool-name allowlist, hot reload) so the three files remain stable architectural boundaries even though they describe code that lives across `products/agent-platform`, `products/platform-gateway`, `products/tool-gateway`, and `shared/shared-contracts`.

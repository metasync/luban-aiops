Three sibling spec directories under `docs/specs/`, each following the project's standard triad of `plan.md` + `spec.md` + `tasks.md`:
- SPEC-022 defines the session lifecycle API (`GET/DELETE /api/v2/sessions`, transcript enrichment), a voice-readiness contract via optional `input_modality` on `ChatRequest`, and a kustomize `runtime-profiles/mutating-dev` profile that opt-in enables mutating tools in dev-k8s while keeping all other environments deny-by-default. The portal UI is explicitly deferred to a future rebuild spec (Appendix A handoff).
- SPEC-026 extends SPEC-024 by moving catalog entry identity from provider name to model name, introducing `<PROVIDER>_MODELS` override, consolidating gitops overlays into a single generic `default` profile, and aliasing legacy provider-name ids.
- SPEC-027 extends SPEC-026 by adding an OpenAI-compatible `/models` live fetch per configured provider with a fail-soft ladder (live → in-memory last-good → Postgres-persisted last-good → curated series), periodic refresh via FastAPI lifespan background task, and per-adapter discovery filters; it deliberately keeps Redis exclusive to the AgentScope kernel message bus and persists cache in the sessions DB.
Dependency direction is strictly forward: 027 extends 026, which extends 024; 022 is orthogonal and builds on SPEC-016/017/020/021. All three specs are authored as requirements with acceptance criteria rather than code.

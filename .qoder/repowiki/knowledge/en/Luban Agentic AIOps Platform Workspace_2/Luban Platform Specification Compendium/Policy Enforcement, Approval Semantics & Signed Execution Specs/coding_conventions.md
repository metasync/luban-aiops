- Each spec follows a fixed triad of `plan.md` / `spec.md` / `tasks.md`, with `spec.md` carrying status, owner, release slice, related risks/ADRs, numbered Requirements with acceptance criteria, Non-Goals, Impact, Open Questions, and a dated Changelog.
- New cross-product contracts land as additive JSON Schema revisions under `shared/shared-contracts/schemas/` (e.g. v1 → v2 for policy schemas, new execution-request/receipt schemas) rather than ad-hoc types, keeping both gateway engines and the portal bound to a single source of truth.
- Security-sensitive defaults are fail-closed: missing policy bundles fail startup readiness, missing signing keys reject mutating resumes with an `execution_rejected` audit event, and unknown actions/roles return structured 403 bodies instead of silent denials.
- Audit trails are append-only and correlation-friendly: every decision, approval, and execution step emits structured log/audit events carrying `x-request-id`, `confirm_id`, and matched rule IDs so the chain `confirmation_decided → execution_requested → tool_invoked → execution_completed` is reconstructible.

Three sibling spec directories form a trust-model progression inside `docs/specs/`:

- `SPEC-008-service-to-service-identity` defines broker-mediated token delegation: `identity-broker` gains an `/api/v1/auth/exchange` endpoint that mints short-lived, audience-bound delegated tokens (`aud`, `act` claims) from verified user JWTs; the gateway caches them per-user and forwards them as `Authorization: Bearer` to `agent-platform`, replacing the previous `X-User-ID` body identity. The spec is marked `delivered` and references ADR-0004.
- `SPEC-068-outbound-execution-credential-schemes` extends the tool-gateway's `credential_sets.py` beyond HTTP Basic with a target-agnostic `scheme` vocabulary (`basic` | `bearer` | `oauth2_client_credentials`) and a connector-local OAuth2 `client_credentials` token client in `tools/oauth_client.py`. It generalizes `http_connector._resolve_auth` into a reusable async auth-resolution seam and is explicitly additive — existing sets are byte-for-byte unchanged. Also delivered.
- `SPEC-070-outbound-user-delegated-identity` builds on SPEC-068 by adding `oauth2_authorization_code` as a fourth scheme, carrying the requesting user's subject to external targets via per-user OAuth 2.x authorization-code redirects. It introduces a new durable credential store (gateway-owned Postgres tables with application-level encryption), cross-product first-use handoff contracts (`oq7-first-use-handoff-contract.md`), and a compatibility report against Red Hat AAP. Status is `delivered` at v0.51.0 with OQ-3 (live AAP integration) deferred to DI-070.

Dependency direction is strictly forward: SPEC-070 extends SPEC-068 additively; both extend the `credential_set` mechanism introduced in SPEC-049 and the identity model in `agentic-aiops-platform/identity-and-authorization-design.md`. Each spec directory follows the same scaffold (`spec.md` + `plan.md` + `tasks.md`; SPEC-070 additionally carries `compatibility-report.md` and `oq7-first-use-handoff-contract.md`).

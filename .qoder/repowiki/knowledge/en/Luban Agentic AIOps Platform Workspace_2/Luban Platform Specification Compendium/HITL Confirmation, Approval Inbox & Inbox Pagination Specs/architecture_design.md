Three sequential spec artifacts forming one feature arc across the same three product boundaries (agent-platform, platform-gateway, operator-portal/web-ui):
- SPEC-020 introduces the read-to-write bridge: kernel `RequireUserConfirmEvent` is translated into new v4/v5 SSE frames (`confirmation_request`, `confirmation_result`) and a `POST /api/v2/chat/confirm` endpoint that resumes parked replies under the confirmer's delegated token, gated by a new deny-by-default `chat:confirm` policy action.
- SPEC-031 persists the in-memory confirmation registry to Postgres (session-scoped, bounded to 50 per session), adds an `approvals:list` gateway endpoint (`GET /api/v1/approvals/inbox`) for designated approvers, and renders owner-side persistent cards plus an Approvals nav view in the portal.
- SPEC-036 refines the inbox API to `GET /api/v2/confirmations` with server-side offset pagination (`history_limit`/`history_offset`) separating pending from resolved history, and records the reverted cold-seeded transcript typewriter as delivered-then-reverted behavior.
Dependency direction is strictly forward: each spec references prior ones (SPEC-020 → SPEC-018/SPEC-019; SPEC-031 builds on SPEC-020's bridge; SPEC-036 extends SPEC-031's inbox) and all three converge on shared contracts under `shared/shared-contracts/schemas` (stream event schema, audit event schema, chat-confirm request schema, policy-default.yaml).

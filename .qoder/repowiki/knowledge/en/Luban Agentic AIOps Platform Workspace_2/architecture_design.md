The repository is a product-oriented monorepo: each capability lives in `products/<name>/` as an independent Python (uv) service or Node web UI with its own `pyproject.toml`, `Dockerfile`, `Makefile`, and `tests/`. Cross-cutting concerns are centralized at the root: `mk/*.mk` provides shared Make fragments; `shared/shared-contracts/` holds API/event/policy schemas consumed by all products; `shared/platform-ops/gitops/` contains Kustomize overlays (dev-k8s, runtime profiles); `docs/specs/` drives spec-led development with plan/spec/tasks per feature; `docs/adr/` records architectural decisions. The root `Makefile` orchestrates coordinated builds (`make build` tags every image with a single `IMAGE_TAG` derived from `VERSION` plus git sha), policy sync (`sync-policy` copies canonical policies into tool-gateway, platform-gateway, and dev overlay), scenario validation, version lockstep checks, and deployment via `shared/platform-ops/gitops/dev-k8s/deploy.sh`. Product boundaries are enforced by explicit contracts rather than shared code — e.g., `platform-gateway` proxies portal-facing chat/session/auth while `tool-gateway` handles tool execution, and both publish audit events to `audit-service`. Samples under `samples/acme-admin/` demonstrate skill authoring and composition but are deployed out-of-band so they never enter the base overlay.

The repository is organized as a multi-product monorepo with three top-level concerns:
- `products/` — independent service projects (agent-platform, audit-service, execution-runtime, identity-broker, incident-service, operator-portal, platform-gateway, skills-hub, tool-gateway; policy-center is design-stage). Each product ships its own `pyproject.toml`, `.python-version`, Dockerfile, `Makefile`, `src/<package>/`, and `tests/`, and is built/tested via `make -C products/<name>`.
- `shared/` — cross-cutting assets: `shared-contracts` (JSON schemas, SQL migrations, policy bundles, validation scripts), `platform-ops` (Kustomize GitOps overlays under `gitops/dev-k8s`, OpenObserve dashboards, e2e demo scripts), and `base-images/base-uv` (Amazon Linux 2023 + uv base image).
- `docs/` — ADRs (`adr/`), per-feature specs with plan/spec/tasks triads (`specs/SPEC-NNN-*`), release notes, guides, and workspace study documents.

The root `Makefile` is the orchestration layer: it enumerates `PYTHON_PRODUCTS` and `IMAGE_PRODUCTS`, delegates sync/test/lint/build/push to each product's Makefile, renders Kustomize overlays, validates policies/dashboards/version lockstep, runs live-checks and e2e demos, and writes a coordinated `.images.env` state file consumed by `deploy`. Dependency direction is inward from products to `shared/shared-contracts`; there is no direct Python import dependency between products — they communicate over HTTP/MCP/Postgres/Redis boundaries defined in the contracts. The `policy-center` product remains a stub; authorization is currently enforced inside `tool-gateway` and `platform-gateway` against the canonical policy bundle in `shared/shared-contracts/policies/`.

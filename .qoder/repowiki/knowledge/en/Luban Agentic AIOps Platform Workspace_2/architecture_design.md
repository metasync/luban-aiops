The workspace is organized as a product-oriented monorepo under `products/`, where each directory is an independently buildable, Dockerized Python service following the same internal layout (`src/<service>/api`, `core`, `schemas`, `services`, plus per-product `tests/`). Cross-cutting contracts live in `shared/shared-contracts` (JSON schemas for chat/session/stream events, tool invocation envelopes, policy models, and the canonical `policy-default.yaml` bundle) and are consumed by all products to avoid tight coupling. The runtime boundary is enforced by two gateways: `platform-gateway` (portal-facing edge handling token verification, policy enforcement, chat/session proxying, and token delegation) and `tool-gateway` (normalized tool/connector access including Playwright-based browser tools). The `agent-platform` hosts the AgentScope 2.0 kernel, session stores (Redis/Postgres), model providers (OpenAI, DashScope, DeepSeek, Luban via a registry), and middleware; `execution-runtime` isolates bounded mutating actions behind HMAC-signed execution envelopes from SPEC-037; `identity-broker` issues RSA-256 JWTs verified via JWKS; `audit-service` persists durable audit events; `incident-service` ingests Alertmanager webhooks and runs triage; `skills-hub` ingests Git/Markdown skills; `operator-portal` serves the Ant Design X UI. Deployment uses Kustomize overlays under `shared/platform-ops/gitops` driven by the root Makefile, which orchestrates coordinated image builds, policy sync (`make sync-policy`), overlay rendering, and the `verify` pre-commit gate that runs every product's tests plus kustomize checks. Spec-driven development is formalized in `docs/specs/` (SPEC-001..SPEC-053, each with spec.md/plan.md/tasks.md) and architecture decisions in `docs/adr/` (ADR-0001..ADR-0008), with living state docs in Tier 3 kept in lockstep with delivered specs.

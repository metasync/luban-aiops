The service is organized as a layered FastAPI application with clear dependency direction: `api/` routes depend on `services/`, which depend on `schemas/` and `core/`; nothing in `core/` imports upward.

- Entry point: `app.create_app()` builds a FastAPI app with an async lifespan that constructs a `SkillStore` (in-memory or Postgres via `build_skill_store`), initializes it, prunes stale source rows, starts a `SyncManager` background task, and wires HTTP request logging, Prometheus metrics, and OpenTelemetry.
- API layer (`api/routes/health.py`, `skills.py`, `status.py`) exposes read-only endpoints; route ordering in `router.py` deliberately registers `/status` before the `{skill_id}` catch-all so path matching is unambiguous.
- Storage abstraction: `services/skill_store.py` defines a `SkillStore` Protocol implemented by `InMemorySkillStore` (tests/dev) and `PostgresSkillStore` (production). Both delegate ranking to a shared `scoring.rank` so search results are byte-identical across backends. The Postgres backend uses raw psycopg connections per operation, idempotent DDL/ALTERs for schema evolution, and a GIN tsvector index combined with tag pre-filtering for full-text search.
- Ingestion pipeline (`services/ingestion.py`) walks a checked-out source directory, parses YAML frontmatter + Markdown body, enforces size/type constraints and the Skill v2 executable-flow shape (`kind` + `steps`), and returns validated `Skill` records plus per-document rejections.
- Sync orchestration (`services/sync.py`) runs periodically, cloning or watching sources, invoking ingestion, and atomically swapping snapshots into the store via `replace_source`; startup pruning removes skills from removed federation entries.
- Configuration (`core/config.py`) reads all settings from `SKILLS_*` environment variables into frozen dataclasses (`SkillsSettings`, `SourceSpec`, `QueryClient`, `WorkloadClient`) with strict parsing that fails fast on malformed federation entries.
- Cross-cutting concerns live in `core/`: `observability.py` (structured logging), `metrics.py` (Prometheus counters/histograms), `telemetry.py` (OTLP exporter), `request_context.py` (request-id propagation), `runtime.py`, and `validate.py` (CLI validation helper).
- Schemas (`schemas/skill.py`) define Pydantic models used by both ingestion and persistence layers.

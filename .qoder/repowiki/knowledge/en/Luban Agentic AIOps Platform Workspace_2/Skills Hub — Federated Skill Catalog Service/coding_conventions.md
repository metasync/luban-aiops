- Configuration is loaded exclusively from `SKILLS_*` environment variables into frozen dataclasses via `from_env()` and cached with `@lru_cache(maxsize=1)` through `get_settings()`, so the rest of the codebase never reads `os.environ` directly.
- Pluggable backends are expressed as a `Protocol` (`SkillStore`) with multiple implementations (`InMemorySkillStore`, `PostgresSkillStore`) selected by a factory (`build_skill_store`) based on a string setting, keeping runtime behavior decoupled from configuration.
- Validation functions return either a success value or a typed rejection object (`Rejection`) carrying `source_id`, `path`, and a human-readable `reason`, so ingestion can collect many errors without short-circuiting.
- Database access uses raw SQL strings with named `%(...)s` parameters and per-operation async connection context managers rather than an ORM, with idempotent `CREATE TABLE IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS` DDL for schema evolution.
- Search queries pre-filter candidates using PostgreSQL full-text operators and then re-rank in-process via the shared `scoring.rank` function so both backends produce identical result orderings.
- Service lifecycle is managed through FastAPI's `asynccontextmanager` lifespan, where resources (store, sync manager) are initialized before `yield` and torn down in `finally`, ensuring deterministic start/stop ordering.

The module is a flat index of one directory per spec (`docs/specs/SPEC-NNN-<slug>/`), each following the three-file template defined in `templates/`: `spec.md` (requirements with acceptance criteria and status header), `plan.md` (technical approach and sequencing), and `tasks.md` (execution checklist). A top-level `README.md` defines the three-tier documentation model (Architecture Record / Feature Specs / Living State Docs), the spec lifecycle statuses (`draft`, `approved`, `in-progress`, `delivered`, `superseded`), numbering/naming conventions, and the relationship to branch naming, PR review, release slices, and the root `make verify` gate. Specs are purely documentary artifacts — they do not contain code or build manifests — and serve as the authoritative contract between product decisions and implementation pull requests, which must link the spec ID they implement.

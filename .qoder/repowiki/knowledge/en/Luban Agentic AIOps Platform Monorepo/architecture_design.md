The workspace is organized as a product-per-service monorepo under `products/`, where each service (agent-platform, audit-service, execution-runtime, identity-broker, incident-service, platform-gateway, skills-hub, tool-gateway, operator-portal) ships its own Dockerfile, Makefile, and test suite. Cross-cutting wiring is centralized in three places: (1) the root `Makefile` aggregates per-product `sync/test/lint/build/push` targets, computes a coordinated `IMAGE_TAG` from the root `VERSION` file, writes `.images.env`, and drives `kustomize` overlay rendering plus policy and version validation; (2) `shared/shared-contracts/` holds JSON schemas, policy bundles, and observability conventions that every Python service consumes to keep inter-service boundaries stable without tight coupling; (3) `shared/platform-ops/gitops/` provides Kustomize overlays and sync scripts that deploy the built images into a dev cluster. The `platform-gateway` acts as the external entry point, delegating to `identity-broker` for tokens, `tool-gateway` for tool execution, and `agent-platform` for chat sessions, while `audit-service`, `incident-service`, and `skills-hub` are called out via HTTP and emit audit events through the shared contract. Spec-driven development is enforced by `docs/specs/SPEC-NNN-*` directories that define plan/spec/tasks driving changes across these products.

The repository is organized as a product-oriented monorepo under `products/`, where each directory is an independently buildable, containerized service (agent-platform, identity-broker, platform-gateway, tool-gateway, audit-service, incident-service, skills-hub, operator-portal). Cross-cutting concerns live in `shared/`: `shared-contracts` defines JSON schemas and policy YAMLs consumed by all services; `platform-ops` holds Kustomize overlays (`dev-k8s`, runtime profiles) and helper scripts for secret sync and deployment; `base-images/base-uv` provides the shared uv-based Python image. The root `Makefile` orchestrates cross-product routines: it enumerates `PYTHON_PRODUCTS` and `IMAGE_PRODUCTS`, delegates per-product `sync/test/lint/build/push` via `make -C products/<name>`, renders all Kustomize overlays, validates the canonical policy bundle against its schema, enforces version lockstep between `VERSION` and every product, and drives coordinated `build`/`deploy`/`e2e` flows that write/read `.images.env`. Each product follows a uniform internal layout (`src/<pkg>/api/routes`, `services`, `schemas`, `core/config+telemetry+metrics`, `tests/`) so the workspace can treat them uniformly at the top level while keeping inter-service coupling strictly through the shared contracts and HTTP APIs exposed by the gateway layer.

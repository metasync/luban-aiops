Each specification lives in its own directory under `docs/specs/` named `SPEC-NNN-<kebab-slug>/`, containing three files: `spec.md` (requirements with acceptance criteria), `plan.md` (technical approach and sequencing), and `tasks.md` (execution checklist). A shared template set in `templates/` standardizes spec structure, status headers (`draft` → `approved` → `in-progress` → `delivered` → `superseded`), requirement numbering (`R-1`, `R-2`, ...), and impact tracking. The root `README.md` defines the three-tier documentation model (Architecture Record, Feature Specs, Living State Docs), the lifecycle rules, and an index mapping every spec ID to its title and current status. Cross-spec dependencies are expressed via explicit extension notes (e.g., later specs state they extend earlier ones like SPEC-026/027/028), and delivery is tied to implementation pull requests that link their spec ID.

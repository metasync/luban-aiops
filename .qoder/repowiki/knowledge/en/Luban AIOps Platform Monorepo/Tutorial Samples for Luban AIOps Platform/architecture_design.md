Each sample lives under `samples/<category>/<name>/` with a fixed layout: `skill/*.md` files are the runnable skill definitions, `demo/` holds standalone shell scripts exercising the flow, and an optional `target/` directory can hold sample-specific infrastructure. The root `deploy-samples.sh` is the only coupling point to a live cluster — it discovers all `skill/` directories, packs their `.md` files into a single `skills-samples` ConfigMap (keys derived from `<sample-leaf>-<relpath>`), applies it to the `dev-luban-aiops` namespace, and restarts the `skills-hub` deployment so the generic `samples` source re-ingests them. This keeps the dependency direction strictly tutorial → platform: the base overlay declares only a generic `samples` skill source and never names a concrete sample. The `web-checks/password-reset` sample demonstrates a write-class browser web-check skill (`ResetUserPassword.md`) that enforces a one-HITL-gate-per-flow invariant by placing the sole `web.click` on admin sign-in and using read-tier `web.fill_credential` plus URL-parameter password delivery for the reset. Its `demo/demo.sh` validates prerequisites (browser connector, HITL bridging, admin portal pages, credential set, skill ingestion, tool discovery) and optionally runs a full operator-chat → agent-automation → HITL-approval → password-reset flow against the platform gateway.

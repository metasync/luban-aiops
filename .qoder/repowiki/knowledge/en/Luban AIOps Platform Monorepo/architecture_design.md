The repository is organized as a product-per-service monorepo under `products/`, where each service (agent-platform, audit-service, execution-runtime, identity-broker, incident-service, platform-gateway, skills-hub, tool-gateway) plus the operator-portal exposes its own Dockerfile, Makefile, and `src/<service>/` layout. Cross-cutting wiring happens at the root: the top-level `Makefile` orchestrates per-product `sync/test/lint/build/push` via loops over `PYTHON_PRODUCTS` and `IMAGE_PRODUCTS`, writes a coordinated `.images.env` state file consumed by the dev-k8s GitOps overlay in `shared/platform-ops/gitops/dev-k8s/`, and enforces version lockstep against the root `VERSION` file. Services communicate through JSON schemas published in `shared/shared-contracts/schemas/` (validated by scripts under `shared/shared-contracts/scripts/`) and share policy bundles copied from `shared/shared-contracts/policies/policy-default.yaml` to both gateway consumers via `make sync-policy`. The `platform-gateway` acts as the authenticated entry point that proxies to downstream services (tool-gateway, agent-platform, identity-broker, etc.), while `samples/` provides self-contained tutorial deployments installed out-of-band via `make deploy-samples` so base overlays never depend on them. Feature evolution is driven by the numbered specs in `docs/specs/SPEC-NNN-*`, each a plan/spec/tasks triad that gates implementation across these products.

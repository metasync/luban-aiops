The repository is organized as a product-per-directory monorepo under `products/`, where each service (agent-platform, audit-service, identity-broker, incident-service, platform-gateway, skills-hub, tool-gateway) plus the operator-portal exposes an HTTP API with a uniform layout (`src/<service>/api|core|schemas|services`). Cross-cutting concerns are centralized in `shared/`: JSON schemas and policy bundles in `shared/shared-contracts/` define inter-service contracts; `shared/platform-ops/gitops/` holds Kustomize overlays that render the full cluster manifest; `mk/*.mk` provides shared Makefile fragments for Docker image builds. The root `Makefile` is the orchestrator: it enumerates `PYTHON_PRODUCTS` and `IMAGE_PRODUCTS`, runs per-product `sync/test/lint/build/push` targets, renders all overlays via `kustomize build`, validates the canonical policy bundle against its schema, enforces version lockstep between `VERSION` and every product, and writes a coordinated `.images.env` used by `deploy.sh` to push images into the dev-k8s overlay. End-to-end validation is performed by `make e2e`, which drives demo scripts against a deployed cluster.

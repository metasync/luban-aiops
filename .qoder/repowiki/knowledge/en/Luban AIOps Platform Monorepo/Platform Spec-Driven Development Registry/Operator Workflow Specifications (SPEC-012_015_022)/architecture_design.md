Three sibling spec directories under `docs/specs/`, each following the project's standard plan/spec/tasks triple: SPEC-012 defines operator documentation deliverables (getting-started, configuration reference, troubleshooting, tool/connector guide, architecture overview) as Tier 3 living-state docs in `docs/guides/`; SPEC-015 specifies a new `products/incident-service` FastAPI product with dual intake (Alertmanager webhook + manual report), normalized incident model, agent-driven triage producing schema-validated reports via a pluggable `Connector` protocol (built-in audit sink), read-only tool-gateway connectors, and an Incidents portal view; SPEC-022 defines session lifecycle APIs (`GET/DELETE /api/v2/sessions`, transcript retrieval) exposed through agent-platform and proxied by platform-gateway under new deny-by-default policy actions, a voice-readiness contract (`input_modality` with two recorded invariants), and an environment-scoped kustomize profile (`runtime-profiles/mutating-dev`) that opt-in enables mutating tools only in dev. All three specs cross-reference shared contracts in `shared/shared-contracts/schemas/` and `policies/policy-default.yaml`, and tie delivery to existing service boundaries (platform-gateway, tool-gateway, agent-platform, operator-portal) rather than introducing new runtime surfaces beyond incident-service.

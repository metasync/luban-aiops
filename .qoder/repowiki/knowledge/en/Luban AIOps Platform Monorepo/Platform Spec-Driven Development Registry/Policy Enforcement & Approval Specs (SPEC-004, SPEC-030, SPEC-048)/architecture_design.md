Three sibling spec directories each document one delivered slice of the policy subsystem, all extending the shared-contracts policy model introduced in SPEC-004. SPEC-004 establishes deny-by-default evaluation in a small gateway-side module with a versioned YAML bundle loaded from `GATEWAY_POLICY_PATH`, route→action mapping (`chat`, `session:create`, `session:read`), structured 403 denials, and audit logging — keeping the decision logic dependency-free while the contract lives in `shared/shared-contracts`. SPEC-030 extends that model by activating the reserved `require_approval` outcome with explicit `tier_1` (self-approval) and `tier_2` (designated approver distinct from requester) levels, bridging the existing HITL confirmation path so the confirm route enforces decider roles and self-approval rules; it also revises both `policy-rule.schema.json` and `policy-decision.schema.json` to v2 additively. SPEC-048 adds operational controls around the already-delivered engine: content-hash provenance on matrix/readiness surfaces, a scenario-expectation harness (`policy-scenarios.yaml` evaluated via the real engine modules), a `make policy-diff` impact report, and a rollout runbook — explicitly preserving all prior evaluation semantics and schema shapes. Each spec follows a uniform structure (status/metadata, summary, requirements with acceptance criteria, non-goals, impact, open questions, changelog) and references the same shared contracts and gateway products as the implementation boundary.

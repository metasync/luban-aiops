Three independent spec directories under `docs/specs/`, each following the same plan/spec/tasks triad that drives implementation in code. SPEC-001 (Release 1 Platform Hardening) defines six requirements covering gateway authentication enforcement (`GATEWAY_REQUIRE_AUTH`), role propagation baseline, transitional runtime session integrity (TTL, max entries, per-session isolation), contract validation via pydantic against `shared/shared-contracts` schemas, backend resolution caching with bounded timeouts, and a CI baseline using GitHub Actions for pytest and kustomize overlay rendering. SPEC-010 (Platform Gateway Extraction) specifies splitting `products/tool-gateway` into a new `products/platform-gateway` product that owns the portal-facing edge (token verification, policy enforcement, chat/session proxying, delegation client, portal routes) while `tool-gateway` is reduced to the tool/connector home; it preserves external HTTP contracts, updates identity audiences (`platform-gateway` vs `tool-gateway`), and requires dev-k8s overlay changes plus Makefile integration. SPEC-016 (Session Store Postgres Separation) specifies adding a `PostgresSessionStore` implementing the existing `SessionStore` protocol behind the current memory/redis backends, with idle-TTL semantics mirroring Redis `EXPIRE`, environment-driven selection via `SESSION_STORE_BACKEND`, fail-open fallback to in-memory on connection failure, idempotent DDL bootstrap, and observability hooks — explicitly keeping kernel Redis (`RedisStorage` / `RedisMessageBus`) untouched since AgentScope provides no Postgres alternative.

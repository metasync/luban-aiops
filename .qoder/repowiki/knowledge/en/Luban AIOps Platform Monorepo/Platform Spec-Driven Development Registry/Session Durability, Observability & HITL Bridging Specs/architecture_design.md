Three independent spec directories under `docs/specs/`, each following the same tri-file layout (`spec.md` + `plan.md` + `tasks.md`) that defines requirements, acceptance criteria, non-goals, impact, and changelog. SPEC-006 specifies a strategy-pattern session store (`InMemorySessionStore` vs `RedisSessionStore`) selected via `SESSION_STORE_BACKEND` with graceful fallback to memory when Redis is unreachable, exposing a `build_session_store()` factory and Prometheus metrics. SPEC-011 extends the agent-stream contract (`agent-stream-event.schema.json`) with `tool_call`/`tool_result` frames, adds an Elastic connector behind `GATEWAY_ELASTIC_ENABLED`, and renders tool traces as an evidence panel in the operator portal. SPEC-020 bridges the AgentScope kernel's `RequireUserConfirmEvent` into two new v4/v5 SSE frames (`confirmation_request`/`confirmation_result`) plus a `POST /api/v2/chat/confirm` endpoint, a gateway proxy guarded by a new `chat:confirm` policy action, and an inline approval card in the portal; it also introduces a per-session in-memory confirmation registry keyed by `confirm_id` with configurable TTL expiry. All three specs are marked `delivered` and reference shared contracts under `shared/shared-contracts/schemas/` (stream event schema, audit event schema, chat confirm schema) and policy bundles under `shared/shared-contracts/policies/`.

Three sibling spec directories each define a vertical slice of the agent execution stack with plan/spec/tasks triads:
- SPEC-002 (`agent-service-contract`) establishes the single platform-owned HTTP+SSE boundary under `/api/v2/` in `shared/shared-contracts/schemas/` (agent-chat-request/response, stream-event, session, runtime-metadata, health), replacing the dual FastAPI/native surface so `tool-gateway` consumes one stable contract behind an adapter over the AgentScope kernel.
- SPEC-007 (`tool-execution-framework`) defines the read-only tool layer: shared `tool-invocation.schema.json` / `tool-result.schema.json`, a `ToolRegistry` + `BaseTool` abstraction in `tool-gateway`, a first `k8s.*` connector using `kubernetes-client/python`, policy-enforced `tools:invoke`/`tools:list` actions, and AgentScope Toolkit registration from gateway-discovered tools.
- SPEC-017 (`agent-kernel-utilization-and-durability`) extends `RuntimeSettings` with kernel knobs (ReAct budget, context compression, time injection, model retries), adds optional `response_schema` structured output for triage reports, and introduces an `AgentStateStore` protocol with `InMemoryAgentStateStore` and `PostgresAgentStateStore` that snapshots `AgentState` JSONB keyed by session id after every turn.
Dependency direction is strictly downward: specs reference ADR-0002 (kernel) and ADR-0003 (contract ownership); cross-spec dependencies flow SPEC-007 → SPEC-008 (token delegation) and SPEC-017 → SPEC-016 (sessions DB), keeping each spec self-contained while forming a layered R1-R3 delivery path.

Two independent spec artifacts under `docs/specs/`, each following the project's plan/spec/tasks triad: SPEC-005 (`observability-baseline`) defines a dual-surface design — an always-on Prometheus `/metrics` endpoint per service (tool-gateway, identity-broker, agent-platform) using `prometheus_client` RED metrics plus security-arc domain counters, and an opt-in OTel push pipeline gated by `OTEL_ENABLED` that bridges `x-request-id` to W3C `trace_id` via auto-propagated `traceparent`. SPEC-046 (`audit-reporting-and-export`) extends the existing durable audit trail (SPEC-013/029/037) with two read-only surfaces on audit-service — `GET /api/v1/audit/summary` (envelope-column aggregates over event_type/outcome/service/username/top_actors/decision_chain) and `GET /api/v1/audit/export` (bounded CSV streaming with `AUDIT_EXPORT_MAX_ROWS` truncation headers) — proxied through platform-gateway under the existing `audit:read` action, with a portal Audit view upgraded to two tabs (Events + Summary), a shared filter toolbar pinned against `audit-event.schema.json` via a vitest drift guard, and no new policy actions or event types. Both specs are delivered, versioned into release slices, and reference shared contracts in `shared/shared-contracts`.

Three independent spec directories under `docs/specs/`, each following a uniform three-file layout (`plan.md`, `spec.md`, `tasks.md`) that drives implementation across multiple products. SPEC-003 establishes RSA-signed JWT issuance via `identity-broker` with JWKS-based local verification in `tool-gateway`, replacing caller-asserted identities and removing the per-request introspection call. SPEC-008 extends that model by adding an audience (`aud`) claim to platform tokens and introducing a broker-mediated `POST /api/v1/auth/exchange` endpoint through which `agent-platform` obtains short-lived delegated tokens bound to `tool-gateway`, enabling authenticated tool invocation without passing user credentials into the least-trustworthy process. SPEC-037 adds a separate security layer on top of approval: HMAC-SHA256 signed execution requests created at resume time, argument-digest verification at invocation, durable request/receipt records keyed by `confirm_id`+`call_id`, and new audit event types (`execution_requested`, `execution_completed`, `execution_rejected`). Each spec explicitly enumerates requirements as R-1..R-N with acceptance criteria, lists impacted products (`identity-broker`, `tool-gateway`, `agent-platform`, `operator-portal`, `shared/platform-ops/gitops`), and tracks status through draft → approved → delivered in the changelog.

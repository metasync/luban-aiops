Each SPEC-N directory is an independent feature contract containing plan.md (rationale/scope), spec.md (requirements/contracts), and tasks.md (implementation checklist), all derived from the templates in docs/specs/templates/. Cross-cutting concerns are coordinated by grouping related specs into child modules (platform runtime, agent execution, identity/security, policy/approval, observability/audit, portal UI, operator workflow, content/knowledge, runtime providers, browser tools, session/observability/HITL bridging) so that implementation teams can track dependencies across domains. The README.md at the root documents the spec-driven development workflow that ties authoring, review, and delivery together, while the coding intent entries capture the current period's cross-spec integration goals such as the password-reset browser demo that exercises the full operator-chat → agent-automation → HITL-approval flow across browser-tools, skills, and approval subsystems.

## Stage 1: Contracts — the additive `session_type` discriminator (R-1)

> **Lockstep (found at plan time, mirrors the SPEC-055 stage-1 rule):** a shared
> schema is never edited alone. The gateway's `test_model_properties_match_contract
> _properties` binds `SessionRecord` to `agent-session.schema.json` by **property-set
> equality**, and the agent-platform validates real responses with
> `jsonschema.validate(...)` against both schemas' `additionalProperties:false` — so
> the moment `session_type` is on a schema, every bound Pydantic declaration must
> carry it too or `make verify` fails. The **bare field declarations** are therefore
> pulled forward into this stage (the store/handler/route *wiring* stays in stages
> 2–4), and the new enum-parity assertion lands here with the schemas so the
> vocabulary gap the property-name guard cannot see is closed atomically.

- [x] `shared/shared-contracts/schemas/agent-session.schema.json`: add an **additive** `session_type` property — `enum: ["operation", "development"]`, `default: "operation"`, a description naming it a birth property fixed once at creation and immutable (no promotion / demotion / conversion); **not** added to `required` (backward-compatible), `additionalProperties:false` unchanged (R-1)
- [x] `shared/shared-contracts/schemas/agent-session-list.schema.json`: add the same `session_type` property to the list `items` (the `SessionSummary` row carries it), same enum + default, **not** added to the items' `required` (R-1)
- [x] confirm the legacy `shared/shared-contracts/schemas/session.schema.json` is **not** touched (unbound — no loader, no parity test, `status` enum already diverged) and that **no** `agent-stream-event.schema.json` bump is needed (`session_type` rides the session record, never a stream frame) (R-1 / plan §1)
